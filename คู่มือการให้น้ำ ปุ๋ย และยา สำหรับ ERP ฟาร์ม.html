Crop Module 3/6 · Irrigation, Fertilizer & Pesticide — Dev-Ready Spec

โมดูลการให้น้ำ ปุ๋ย และยา (Irrigation, Fertilizer & Pesticide)

สเปกสำหรับเริ่มพัฒนาได้ทันที ครอบคลุมขอบเขตและจุดเชื่อมต่อกับโมดูลอื่น ฟังก์ชันหลักแยก MVP กับที่เพิ่มทีหลังได้ โครงสร้างฐานข้อมูล API หลักที่ต้องมี สิทธิ์การเข้าถึงตามบทบาท และสูตรคำนวณ/กฎทางธุรกิจ

ส่วนหนึ่งของ คู่มือ ERP สำหรับธุรกิจฟาร์ม อัปเดต 18 ก.ค. 2569
1. ขอบเขตและจุดเชื่อมต่อ (Scope & Integration) 2. ฟังก์ชันหลัก (Core Functions) 3. ฐานข้อมูล (Database) 4. API 5. สิทธิ์การเข้าถึง (Roles) 6. สูตรคำนวณ (Formulas) 7. หน้าจอที่ต้องมี (Screens)
Scope & Integration

1. ขอบเขตและจุดเชื่อมต่อ (Scope & Integration Points)

โมดูลนี้บันทึกการปฏิบัติงานจริงตามกำหนดการจากแผนการเพาะปลูก และเป็นจุดสำคัญด้านความปลอดภัยอาหาร — ต้องคุมระยะเวลาห้ามเก็บเกี่ยวหลังฉีดพ่นสารเคมี (PHI) ไม่ให้พลาด

อยู่ในขอบเขต

  • บันทึกการให้น้ำ (Irrigation Log)
  • บันทึกการให้ปุ๋ย (Fertilizer Application)
  • บันทึกการฉีดพ่นสารเคมี/ยาปราบศัตรูพืช (Pesticide Application)
  • คำนวณปริมาณที่ต้องใช้ตามพื้นที่
  • ตรวจสอบระยะเวลาห้ามเก็บเกี่ยวหลังฉีดพ่น (Pre-Harvest Interval, PHI)

อยู่นอกขอบเขต (รับ/ส่งข้อมูลกับโมดูลอื่น)

  • กำหนดการดูแลพืชตามแผน — รับจาก แผนการเพาะปลูก
  • การตัดสต็อกปุ๋ย/สารเคมีที่ใช้จริง — ส่งต่อให้ คลังสินค้า/สต็อก
  • ต้นทุนปุ๋ย/สารเคมีเข้ารอบผลิต — สะท้อนผ่าน COGS ที่คลังตัดแล้ว ไม่คำนวณเอง
  • พยากรณ์ฝนตก/แล้ง — รับจาก สภาพอากาศ ช่วยตัดสินใจวันให้น้ำ
โมดูลที่เกี่ยวข้องเหตุการณ์สิ่งที่โมดูลนี้ต้องทำPhase
แผนการเพาะปลูกแผนได้รับอนุมัติ มีกำหนดการดูแลพืชดึงกำหนดการมาสร้างรายการงานที่ต้องทำPhase 1
การให้น้ำฯ (ตัวเอง) → คลังสินค้า/สต็อกบันทึกให้ปุ๋ย/ฉีดพ่นสารเคมีจริงแจ้งตัดสต็อกปุ๋ย/สารเคมีที่ใช้Phase 1
การเก็บเกี่ยวจะเริ่มเก็บเกี่ยวจริงตรวจสอบว่าเลยระยะ PHI ปลอดภัยแล้วหรือยังPhase 1
สภาพอากาศพยากรณ์ฝนตก/แล้งช่วงที่จะให้น้ำช่วยแนะนำวันที่ควรให้น้ำ/เลื่อนการฉีดพ่นPhase 2
Core Functions

2. ฟังก์ชันหลัก (Core Functions)

แยกชัดว่าอะไรต้องใช้งานได้ตั้งแต่วันแรก (MVP) และอะไรเพิ่มทีหลังได้โดยไม่กระทบการบันทึกงานพื้นฐาน

MVP — ต้องมีวันแรก Phase 1

  • รับกำหนดการจากแผนการเพาะปลูกมาสร้างรายการงานที่ต้องทำ
  • บันทึกการให้น้ำจริง (วันที่ ปริมาณน้ำ)
  • บันทึกการให้ปุ๋ยจริง พร้อมแจ้งตัดสต็อก
  • บันทึกการฉีดพ่นสารเคมีจริง พร้อมแจ้งตัดสต็อก
  • คำนวณปริมาณปุ๋ย/สารเคมีที่ต้องใช้ตามพื้นที่ก่อนบันทึกจริง
  • ตรวจสอบและแจ้งเตือนระยะเวลาห้ามเก็บเกี่ยว (PHI) ต่อแปลง
  • ดูประวัติการดูแลพืชทั้งหมดต่อแปลง/รอบผลิต

เพิ่มทีหลังได้

  • แจ้งเตือนอัตโนมัติเมื่อถึงกำหนดต้องให้น้ำ/ปุ๋ย/ฉีดพ่นPhase 2
  • ปรับกำหนดการให้น้ำอัตโนมัติตามพยากรณ์ฝนPhase 2
  • บันทึกผ่านแอปมือถือหน้างานพร้อมพิกัด GPS ยืนยันตำแหน่งPhase 2
  • เชื่อมเซนเซอร์ความชื้นดิน/ระบบให้น้ำอัตโนมัติ (IoT)Phase 3
  • วิเคราะห์ประสิทธิภาพการใช้ปุ๋ย/สารเคมีต่อผลผลิตที่ได้Phase 3
Database

3. ฐานข้อมูล (Database)

แต่ละเอนทิตีคือ 1 ตารางในฐานข้อมูล พร้อมคำอธิบายว่าแทนอะไรในโลกจริง และแต่ละฟิลด์เก็บอะไร ชนิดข้อมูลแบบไหน

care_task Phase 1

งานดูแลพืชตามแผน — รายการงานที่ต้องทำตามกำหนดการจากแผนการเพาะปลูก เช่น "ให้ปุ๋ยครั้งที่ 2 วันที่ x" ก่อนจะมีการบันทึกว่าทำจริงหรือยัง

ความสัมพันธ์: ผูกกับ planting_plan จากโมดูลแผนการเพาะปลูก และเมื่อทำจริงจะเชื่อมกับ irrigation_log/fertilizer_application/pesticide_application ตามประเภทงาน

ฟิลด์ชนิดข้อมูลเก็บอะไร
idเลขอ้างอิง/UUID (PK)รหัสประจำแถวนี้ ไม่ซ้ำกัน สร้างอัตโนมัติ
planting_plan_idเลขอ้างอิง (FK → planting_plan)งานนี้เป็นของแผนปลูกรอบไหน
task_typeตัวเลือกคงที่ (enum)ประเภทงาน เลือกได้เฉพาะ: irrigation, fertilizer, pesticide
scheduled_dateวันที่ (date)วันที่ควรทำงานนี้ตามแผน
statusตัวเลือกคงที่ (enum)สถานะ เลือกได้เฉพาะ: pending, done, skipped, overdue

irrigation_log Phase 1

บันทึกการให้น้ำ — บันทึกทุกครั้งที่ให้น้ำจริงในแปลง/โซนหนึ่ง

ความสัมพันธ์: ผูกกับ field/field_zone (จากโมดูลผังแปลง) และ care_task ถ้าเป็นไปตามแผน

ฟิลด์ชนิดข้อมูลเก็บอะไร
idเลขอ้างอิง/UUID (PK)รหัสประจำแถวนี้ ไม่ซ้ำกัน สร้างอัตโนมัติ
field_id / field_zone_idเลขอ้างอิง (FK)ให้น้ำแปลงหรือโซนไหน
care_task_idเลขอ้างอิง (FK → care_task, ว่างได้)เป็นไปตามงานที่วางแผนไว้ไหม ถ้าให้น้ำนอกแผนปล่อยว่าง
irrigation_dateวันที่ (date)วันที่ให้น้ำจริง
water_volume_litersตัวเลข (decimal)ปริมาณน้ำที่ใช้จริง หน่วยลิตร
methodตัวเลือกคงที่ (enum)วิธีให้น้ำ เลือกได้เฉพาะ: sprinkler, drip, flood, manual

fertilizer_application Phase 1

บันทึกการให้ปุ๋ย — บันทึกทุกครั้งที่ใส่ปุ๋ยจริงในแปลง/โซนหนึ่ง พร้อมชนิดและปริมาณ

ความสัมพันธ์: ผูกกับ field/field_zone, care_task และ item (ชนิดปุ๋ยจากโมดูลคลังสินค้า) ที่ถูกตัดสต็อก

ฟิลด์ชนิดข้อมูลเก็บอะไร
idเลขอ้างอิง/UUID (PK)รหัสประจำแถวนี้ ไม่ซ้ำกัน สร้างอัตโนมัติ
field_id / field_zone_idเลขอ้างอิง (FK)ให้ปุ๋ยแปลงหรือโซนไหน
care_task_idเลขอ้างอิง (FK → care_task, ว่างได้)เป็นไปตามงานที่วางแผนไว้ไหม
item_idเลขอ้างอิง (FK → item)ใช้ปุ๋ยชนิดไหนจากคลังสินค้า
application_dateวันที่ (date)วันที่ใส่ปุ๋ยจริง
quantity_usedตัวเลข (decimal)ปริมาณปุ๋ยที่ใช้จริง
application_methodข้อความ/ตัวเลือกคงที่วิธีการใส่ปุ๋ย เช่น หว่าน โรยโคน ผสมน้ำราด

pesticide_application Phase 1

บันทึกการฉีดพ่นสารเคมี — บันทึกทุกครั้งที่ฉีดพ่นยาปราบศัตรูพืช/สารเคมีในแปลง/โซนหนึ่ง เป็นจุดสำคัญที่สุดสำหรับตรวจสอบความปลอดภัยอาหารก่อนเก็บเกี่ยว

ความสัมพันธ์: ผูกกับ field/field_zone, care_task และ item (ชนิดสารเคมีจากโมดูลคลังสินค้าที่มีค่า phi_days กำกับ)

ฟิลด์ชนิดข้อมูลเก็บอะไร
idเลขอ้างอิง/UUID (PK)รหัสประจำแถวนี้ ไม่ซ้ำกัน สร้างอัตโนมัติ
field_id / field_zone_idเลขอ้างอิง (FK)ฉีดพ่นแปลงหรือโซนไหน
care_task_idเลขอ้างอิง (FK → care_task, ว่างได้)เป็นไปตามงานที่วางแผนไว้ไหม
item_idเลขอ้างอิง (FK → item)ใช้สารเคมีชนิดไหนจากคลังสินค้า
application_dateวันที่ (date)วันที่ฉีดพ่นจริง
quantity_usedตัวเลข (decimal)ปริมาณสารเคมีที่ใช้จริง
target_pestข้อความ (text)ศัตรูพืชหรือโรคที่มุ่งกำจัด
phi_daysตัวเลข (integer)จำนวนวันที่ต้องเว้นก่อนเก็บเกี่ยวได้ ดึงจากมาตรฐานของสารเคมีนั้น
safe_harvest_dateวันที่ (date)วันที่เก็บเกี่ยวได้อย่างปลอดภัย คำนวณจาก application_date + phi_days

Business Rules & Formulas

6. สูตรคำนวณและกฎทางธุรกิจ (Business Rules & Formulas)

ตรรกะที่ dev ต้อง implement จริงเบื้องหลัง entity/endpoint ด้านบน — ข้อ 2-3 เป็นกฎความปลอดภัยอาหารที่สำคัญที่สุดของโมดูลนี้

คำนวณปริมาณตามพื้นที่ (Dosage Calculation)

Phase 1

ใช้ก่อนบันทึกจริงทุกครั้ง เพื่อไม่ให้ใส่ปุ๋ย/ฉีดพ่นเกินหรือขาดจากที่ควร

quantity_needed =
  dosage_rate_per_rai (จากฉลากผลิตภัณฑ์/มาตรฐาน)
  × field_or_zone.area_rai

คำนวณวันที่ปลอดภัยเก็บเกี่ยว (Safe Harvest Date)

Phase 1

คำนวณทันทีที่บันทึก pesticide_application ทุกครั้ง

safe_harvest_date = application_date + phi_days

ถ้า planting_plan.expected_harvest_date < safe_harvest_date
  -> flag เตือนว่าต้องเลื่อนเก็บเกี่ยว
     หรือเลือกสารที่มี phi_days สั้นกว่าในรอบถัดไป

ตรวจสอบก่อนอนุมัติเก็บเกี่ยวจริง (Pre-Harvest Safety Check)

Phase 1

กฎบังคับที่ต้อง enforce ที่ระดับ API ไม่ใช่แค่เตือนใน UI

is_safe_to_harvest(field, harvest_date) =
  ไม่มี pesticide_application ใดของ field นี้
  ที่ safe_harvest_date > harvest_date ที่ต้องการเก็บจริง

ถ้าไม่ผ่าน -> ห้ามโมดูลเก็บเกี่ยว
  บันทึกการเก็บเกี่ยวจนกว่าจะถึง safe_harvest_date

หมายเหตุ: นี่คือกฎความปลอดภัยอาหารหลักที่ทำให้ผ่านมาตรฐาน GAP — ควรปรึกษาเจ้าหน้าที่เกษตร/มาตรฐานสารเคมีจริงก่อนกำหนดค่า phi_days ในระบบ

ตรวจจับงานที่ล่าช้า (Task Overdue Detection)

Phase 1

ใช้ไล่ดูว่างานตามแผนไหนยังไม่ได้ทำทั้งที่ถึงกำหนดแล้ว

status = overdue
  ถ้า today > scheduled_date AND status = pending

ปริมาณน้ำสะสมต่อรอบผลิต (Cumulative Water Usage)

Phase 2

ใช้วิเคราะห์ประสิทธิภาพการใช้น้ำเทียบผลผลิตที่ได้ในภายหลัง

total_water_used(planting_plan) =
  SUM(irrigation_log.water_volume_liters)
  ของ field เดียวกัน
  ในช่วง planting_start_date ถึง harvest_end_date

7. หน้าจอที่ต้องมี (Screens/Pages)

รายชื่อหน้าจอที่ต้องมีจริงในโมดูลนี้ พร้อมส่วนประกอบหลักของแต่ละหน้า — ใช้เป็น checklist ออกแบบ UI ต่อได้ตรง ๆ ไม่ต้องนั่งไล่จากฟังก์ชัน/entity เอง

แดชบอร์ดงานดูแลพืชประจำวัน (Care Task Dashboard) Phase 1

หน้าแรกที่เจ้าหน้าที่เกษตร/ผู้จัดการแปลงเปิดดูว่าวันนี้ต้องทำอะไร ที่ไหนเลยกำหนดแล้วบ้าง

  • การ์ดสรุปจำนวนงานแยกตาม task_type (irrigation/fertilizer/pesticide) และสถานะ pending/overdue/done ของวันนี้
  • ตารางงานที่ status = overdue พร้อมลิงก์ตรงไปหน้าบันทึกจริงตามประเภทงาน
  • ตัวกรอง: planting_plan_id, แปลง/โซน, ช่วง scheduled_date

รายการงานดูแลพืชตามแผน (Care Task List) Phase 1

ดูและจัดการงาน care_task ทั้งหมดที่ดึงมาจากกำหนดการของแผนการเพาะปลูก

  • ตารางรายการ: task_type, scheduled_date, planting_plan_id, status พร้อม badge สีตามสถานะ
  • ตัวกรอง: status (pending/done/skipped/overdue), task_type, planting_plan_id
  • ปุ่ม "บันทึกว่าทำแล้ว/ข้ามงาน" อัปเดตสถานะผ่าน PATCH /crop/care-tasks/{id}

บันทึกการให้น้ำ (Irrigation Log) Phase 1

ดูประวัติและบันทึกการให้น้ำจริงของแต่ละแปลง/โซน

  • ตารางประวัติ: field_id/field_zone_id, irrigation_date, water_volume_liters, method
  • ตัวกรอง: แปลง/โซน, ช่วง irrigation_date, method (sprinkler/drip/flood/manual)
  • ปุ่ม "บันทึกการให้น้ำใหม่" ผูกกับ care_task_id ถ้ามาจากแผน แล้ว POST /crop/irrigation-logs

บันทึกการให้ปุ๋ย (Fertilizer Application) Phase 1

ดูประวัติและบันทึกการใส่ปุ๋ยจริง พร้อมตัดสต็อกอัตโนมัติ

  • ตารางประวัติ: item_id (ชนิดปุ๋ย), application_date, quantity_used, application_method
  • ตัวกรอง: แปลง/โซน, item_id, ช่วง application_date
  • ปุ่ม "บันทึกการให้ปุ๋ยใหม่" เลือก item_id จากคลังสินค้า กรอก quantity_used → POST /crop/fertilizer-applications (ตัดสต็อกอัตโนมัติ)
  • ลิงก์ไปหน้าเครื่องคำนวณปริมาณก่อนกรอกจริง

บันทึกการฉีดพ่นสารเคมี (Pesticide Application) Phase 1

ดูประวัติและบันทึกการฉีดพ่นสารเคมีจริง จุดสำคัญที่สุดด้านความปลอดภัยอาหาร

  • ตารางประวัติ: item_id, target_pest, application_date, quantity_used, safe_harvest_date พร้อมไฮไลต์แถวที่ยังไม่ปลอดภัยเก็บเกี่ยว
  • ตัวกรอง: แปลง/โซน, item_id, ช่วง application_date
  • ปุ่ม "บันทึกการฉีดพ่นใหม่" เลือก item_id (ดึง phi_days อัตโนมัติ) กรอก target_pest, quantity_used → POST /crop/pesticide-applications คำนวณ safe_harvest_date ให้ทันที

เครื่องคำนวณปริมาณตามพื้นที่ (Dosage Calculator) Phase 1

คำนวณปริมาณปุ๋ย/สารเคมีที่ต้องใช้ก่อนบันทึกจริงทุกครั้ง

  • ฟอร์มเลือกแปลง/โซน (ดึง area_rai อัตโนมัติ) และกรอก dosage_rate_per_rai จากฉลากผลิตภัณฑ์
  • แสดงผล quantity_needed ที่คำนวณได้ พร้อมปุ่ม "ใช้ค่านี้บันทึก" ส่งต่อไปหน้าบันทึกการให้ปุ๋ย/ฉีดพ่น
  • เรียกข้อมูลผ่าน GET /crop/reports/dosage-calculator

สถานะ PHI และวันที่ปลอดภัยเก็บเกี่ยว (PHI Status) Phase 1

ตรวจสอบก่อนอนุมัติเก็บเกี่ยวว่าเลยระยะห้ามเก็บเกี่ยวหลังฉีดพ่นแล้วหรือยัง

  • ตารางรายแปลง: safe_harvest_date ล่าสุดจาก pesticide_application, จำนวนวันที่เหลือ, badge เตือนถ้า planting_plan.expected_harvest_date เร็วกว่า safe_harvest_date
  • ตัวกรอง: แปลง/โซน, planting_plan_id
  • ปุ่ม "ตรวจสอบก่อนเก็บเกี่ยว" เรียก is_safe_to_harvest ผ่าน GET /crop/fields/{id}/phi-status

ประวัติการดูแลพืชต่อแปลง (Care History) Phase 1

ดูภาพรวมทุกกิจกรรมดูแลพืชของแปลง/รอบผลิตหนึ่งในหน้าเดียว

  • Timeline รวม care_task, irrigation_log, fertilizer_application, pesticide_application เรียงตามวันที่
  • ตัวกรอง: planting_plan_id, แปลง/โซน, ช่วงวันที่, task_type
  • ปุ่ม export ประวัติเป็น PDF สำหรับตรวจสอบมาตรฐาน GAP เรียกผ่าน GET /crop/reports/care-history

แจ้งเตือนกำหนดการดูแลพืช (Care Reminders) Phase 2

แจ้งเตือนอัตโนมัติเมื่อใกล้ถึงหรือเลยกำหนดงานดูแลพืช

  • รายการแจ้งเตือนที่สร้างจาก care_task ที่ scheduled_date ใกล้ถึงหรือกลายเป็น status = overdue
  • ตั้งค่าช่องทางแจ้งเตือน (แอป/SMS) ต่อผู้ใช้/บทบาท

ปรับกำหนดการให้น้ำตามพยากรณ์ฝน (Weather-adjusted Schedule) Phase 2

เลื่อนกำหนดการให้น้ำอัตโนมัติเมื่อมีพยากรณ์ฝนตกจากโมดูลสภาพอากาศ

  • ตารางเปรียบเทียบ scheduled_date เดิมของ care_task (task_type = irrigation) กับวันที่แนะนำใหม่ตามพยากรณ์ฝน
  • ปุ่ม "เลื่อนกำหนดการ" อัปเดต care_task.scheduled_date อัตโนมัติ

บันทึกหน้างานผ่านมือถือ + GPS (Mobile Field Entry) Phase 2

ให้พนักงานภาคสนามบันทึกการให้น้ำ/ปุ๋ย/ฉีดพ่นจากหน้างานจริงพร้อมยืนยันตำแหน่ง

  • ฟอร์มย่อบันทึก irrigation_log/fertilizer_application/pesticide_application พร้อมพิกัด GPS ยืนยันว่าอยู่ในแปลงจริง
  • ปุ่มถ่ายรูปหน้างานแนบกับบันทึกที่ POST ไป

รายงานปริมาณน้ำสะสมต่อรอบผลิต (Cumulative Water Usage Report) Phase 2

ดูปริมาณน้ำรวมที่ใช้ไปของแต่ละรอบผลิต เทียบผลผลิตที่ได้ในภายหลัง

  • กราฟ/ตาราง total_water_used = SUM(irrigation_log.water_volume_liters) ต่อ planting_plan ในช่วง planting_start_date ถึง harvest_end_date
  • ตัวกรอง: planting_plan_id, ช่วงวันที่

แดชบอร์ดเซนเซอร์ความชื้นดินและให้น้ำอัตโนมัติ (Soil Sensor & Auto-Irrigation Dashboard) Phase 3

เชื่อมเซนเซอร์ IoT ในแปลงเข้ากับระบบให้น้ำอัตโนมัติ

  • กราฟค่าความชื้นดินตามเวลาต่อแปลง/โซนจากเซนเซอร์ IoT
  • สวิตช์เปิด/ปิดระบบให้น้ำอัตโนมัติ พร้อม log ที่ระบบสร้าง irrigation_log อัตโนมัติเมื่อความชื้นต่ำกว่าเกณฑ์

วิเคราะห์ประสิทธิภาพการใช้ปุ๋ย/สารเคมีต่อผลผลิต (Input Efficiency Analysis) Phase 3

เทียบปริมาณปุ๋ย/สารเคมีที่ใช้กับผลผลิตที่ได้จริง เพื่อช่วยตัดสินใจปรับสูตรรอบถัดไป

  • กราฟเปรียบเทียบ quantity_used ของ fertilizer_application/pesticide_application ต่อรอบผลิต กับผลผลิตจากโมดูลเก็บเกี่ยว
  • ตัวกรอง: item_id, planting_plan_id, ช่วงเวลา
