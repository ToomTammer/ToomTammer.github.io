Crop Module 1/6 · Field & Land Mapping — Dev-Ready Spec

โมดูลผังแปลงและที่ดิน (Field & Land Mapping)

สเปกสำหรับเริ่มพัฒนาได้ทันที ครอบคลุมขอบเขตและจุดเชื่อมต่อกับโมดูลอื่น ฟังก์ชันหลักแยก MVP กับที่เพิ่มทีหลังได้ โครงสร้างฐานข้อมูล API หลักที่ต้องมี สิทธิ์การเข้าถึงตามบทบาท และสูตรคำนวณ/กฎทางธุรกิจ

ส่วนหนึ่งของ คู่มือ ERP สำหรับธุรกิจฟาร์ม อัปเดต 18 ก.ค. 2569
1. ขอบเขตและจุดเชื่อมต่อ (Scope & Integration) 2. ฟังก์ชันหลัก (Core Functions) 3. ฐานข้อมูล (Database) 4. API 5. สิทธิ์การเข้าถึง (Roles) 6. สูตรคำนวณ (Formulas)
Scope & Integration

1. ขอบเขตและจุดเชื่อมต่อ (Scope & Integration Points)

โมดูลนี้เป็นรากฐานของโมดูลพืชไร่/พืชสวนทั้งหมด — กำหนด "แปลง" และ "โซน" ที่ทุกโมดูลปลูกพืชอื่นต้องอ้างอิงตาม field_id/zone_id เดียวกัน

อยู่ในขอบเขต

  • ทะเบียนแปลง/ที่ดิน (Field Registry) พร้อมขนาดพื้นที่และขอบเขต GPS/GIS
  • การแบ่งโซน/แปลงย่อยภายในแปลงใหญ่
  • ประวัติการใช้ที่ดินย้อนหลัง
  • ข้อมูลดิน (ประเภทดิน, pH, ความอุดมสมบูรณ์)
  • เอกสารสิทธิ์ที่ดินอ้างอิง

อยู่นอกขอบเขต (รับ/ส่งข้อมูลกับโมดูลอื่น)

  • แผนการเพาะปลูกจริงต่อรอบ — ส่งต่อให้ แผนการเพาะปลูก ใช้ field_id/zone_id อ้างอิง
  • การสร้างศูนย์ต้นทุนต่อแปลง — ส่งต่อให้ บัญชีและการเงิน สร้าง cost_center
  • การให้น้ำ/ปุ๋ย/สารเคมีต่อแปลง — โมดูล การให้น้ำ ปุ๋ย และยา อ้างอิง field_id นี้
  • พยากรณ์อากาศเฉพาะจุด — รับจาก สภาพอากาศ โดยใช้พิกัด GPS ของแปลง
โมดูลที่เกี่ยวข้องเหตุการณ์สิ่งที่ผังแปลงต้องทำPhase
ผังแปลง (ตัวเอง) → บัญชีและการเงินสร้างแปลง/โซนใหม่เสนอให้สร้าง cost_center ผูกกับแปลงนั้นPhase 1
แผนการเพาะปลูกวางแผนปลูกพืชในแปลง/โซนหนึ่งให้ field_id/zone_id อ้างอิงสำหรับผูกแผนปลูกPhase 1
การให้น้ำ ปุ๋ย และยาบันทึกการให้น้ำ/ปุ๋ย/สารเคมีต่อแปลงให้พื้นที่ (ไร่) ของแปลงไว้คำนวณปริมาณที่ต้องใช้Phase 1
การเก็บเกี่ยวบันทึกผลผลิตต่อแปลงเมื่อจบรอบอัปเดตประวัติการใช้ที่ดินหลังเก็บเกี่ยวPhase 1
สภาพอากาศต้องการพิกัด GPS ของแปลงเพื่อสอบถามพยากรณ์เฉพาะจุดให้พิกัดขอบเขตแปลงPhase 2
Core Functions

2. ฟังก์ชันหลัก (Core Functions)

แยกชัดว่าอะไรต้องใช้งานได้ตั้งแต่วันแรก (MVP) และอะไรเพิ่มทีหลังได้โดยไม่กระทบการอ้างอิงแปลงพื้นฐาน

MVP — ต้องมีวันแรก Phase 1

  • จัดการทะเบียนแปลง/ที่ดิน พร้อมขนาดพื้นที่และพิกัด GPS
  • วาดขอบเขตแปลงบนแผนที่ (GIS polygon) อย่างง่าย
  • แบ่งย่อยแปลงเป็นโซน/แปลงย่อย
  • บันทึกประวัติการใช้ที่ดินย้อนหลัง
  • เชื่อมกับบัญชีเพื่อสร้างศูนย์ต้นทุนต่อแปลง/โซน
  • ดูสรุปพื้นที่ทั้งหมดแยกตามสถานะการใช้งาน (ว่าง/กำลังปลูก/พักดิน)

เพิ่มทีหลังได้

  • บันทึกข้อมูลดิน (ประเภทดิน, pH, ความอุดมสมบูรณ์)Phase 2
  • เชื่อมพิกัด GPS ไปสอบถามพยากรณ์อากาศเฉพาะจุดPhase 2
  • แนบเอกสารสิทธิ์ที่ดิน (เลขโฉนด, ไฟล์สแกน)Phase 2
  • แผนที่ภาพรวมฟาร์มแบบ interactive (ซูม/คลิกดูรายละเอียดแปลง)Phase 2
  • วิเคราะห์ประวัติการปลูกเพื่อแนะนำการหมุนเวียนพืชPhase 3
  • เชื่อมภาพถ่ายดาวเทียม/โดรนติดตามสภาพแปลง (NDVI)Phase 3
Database

3. ฐานข้อมูล (Database)

แต่ละเอนทิตีคือ 1 ตารางในฐานข้อมูล พร้อมคำอธิบายว่าแทนอะไรในโลกจริง และแต่ละฟิลด์เก็บอะไร ชนิดข้อมูลแบบไหน

field Phase 1

แปลง/ที่ดิน — ทะเบียนแปลงที่ดินหลักของฟาร์ม แต่ละแปลงคือพื้นที่ทางกายภาพต่อเนื่องหนึ่งผืน

ความสัมพันธ์: ผูกกับ field_zone (แปลงย่อย), land_use_history และเชื่อมกับ cost_center ในโมดูลบัญชี

ฟิลด์ชนิดข้อมูลเก็บอะไร
idเลขอ้างอิง/UUID (PK)รหัสประจำแถวนี้ ไม่ซ้ำกัน สร้างอัตโนมัติ
field_codeข้อความ (text)รหัสแปลงที่ใช้อ้างอิงภายในระบบ
nameข้อความ (text)ชื่อแปลง เช่น "แปลงหลังบ้านริมคลอง"
area_raiตัวเลข (decimal)ขนาดพื้นที่เป็นไร่
gps_boundaryข้อความ (GeoJSON/polygon)พิกัดขอบเขตแปลงบนแผนที่ สำหรับวาด/คำนวณพื้นที่
land_title_refข้อความ (text, ว่างได้)เลขที่เอกสารสิทธิ์ที่ดินอ้างอิง เช่น เลขโฉนด
default_cost_center_idเลขอ้างอิง (FK → cost_center)ศูนย์ต้นทุนหลักที่ผูกกับแปลงนี้
statusตัวเลือกคงที่ (enum)สถานะ เลือกได้เฉพาะ: active, fallow (พักดิน), inactive

field_zone Phase 1

โซน/แปลงย่อย — การแบ่งพื้นที่ย่อยภายในแปลงใหญ่ ใช้เมื่อปลูกพืชต่างชนิดหรือต่างรอบในแปลงเดียวกัน

ความสัมพันธ์: ผูกกับ field (แปลงแม่) และอาจมี cost_center ของตัวเองถ้าต้องแยกต้นทุนละเอียดกว่าระดับแปลง

ฟิลด์ชนิดข้อมูลเก็บอะไร
idเลขอ้างอิง/UUID (PK)รหัสประจำแถวนี้ ไม่ซ้ำกัน สร้างอัตโนมัติ
field_idเลขอ้างอิง (FK → field)โซนนี้อยู่ในแปลงไหน
zone_codeข้อความ (text)รหัสโซนภายในแปลง เช่น "A1", "A2"
area_raiตัวเลข (decimal)ขนาดพื้นที่ของโซนนี้เป็นไร่
gps_boundaryข้อความ (GeoJSON, ว่างได้)พิกัดขอบเขตโซนย่อย ถ้าต้องการแยกจากแปลงแม่
cost_center_idเลขอ้างอิง (FK → cost_center, ว่างได้)ศูนย์ต้นทุนของโซนนี้โดยเฉพาะ ถ้าไม่ระบุใช้ของแปลงแม่ร่วมกัน

soil_data Phase 2

ข้อมูลดิน — คุณสมบัติดินของแปลง/โซน ใช้ประกอบการวางแผนปลูกและใส่ปุ๋ยให้เหมาะสม

ความสัมพันธ์: ผูกกับ field หรือ field_zone

ฟิลด์ชนิดข้อมูลเก็บอะไร
idเลขอ้างอิง/UUID (PK)รหัสประจำแถวนี้ ไม่ซ้ำกัน สร้างอัตโนมัติ
field_id / field_zone_idเลขอ้างอิง (FK)ข้อมูลดินนี้เป็นของแปลงหรือโซนไหน
soil_typeข้อความ/ตัวเลือกคงที่ (enum)ประเภทดิน เช่น ดินร่วน ดินเหนียว ดินทราย
ph_levelตัวเลข (decimal)ค่าความเป็นกรด-ด่างของดิน
organic_matter_pctตัวเลข (decimal, ว่างได้)ร้อยละอินทรียวัตถุในดิน
test_dateวันที่ (date)วันที่ตรวจวัดค่าดินนี้

land_use_history Phase 1

ประวัติการใช้ที่ดิน — บันทึกว่าที่ผ่านมาแปลง/โซนนี้ปลูกพืชอะไรในช่วงไหนบ้าง ใช้วางแผนหมุนเวียนพืชและวิเคราะห์ผลผลิตย้อนหลัง

ความสัมพันธ์: ผูกกับ field/field_zone และอ้างอิง cost_center (batch) ของรอบปลูกจริงจากโมดูลแผนการเพาะปลูก

ฟิลด์ชนิดข้อมูลเก็บอะไร
idเลขอ้างอิง/UUID (PK)รหัสประจำแถวนี้ ไม่ซ้ำกัน สร้างอัตโนมัติ
field_id / field_zone_idเลขอ้างอิง (FK)ประวัตินี้เป็นของแปลงหรือโซนไหน
crop_typeข้อความ (text)ชนิดพืชที่ปลูกในรอบนั้น
planting_start_date / harvest_end_dateวันที่ (date, ว่างได้)ช่วงเวลาปลูกจนถึงเก็บเกี่ยวเสร็จ (ว่างถ้ายังไม่จบรอบ)
ref_cost_center_idเลขอ้างอิง (FK → cost_center)ศูนย์ต้นทุน (batch) ของรอบปลูกนี้ในโมดูลบัญชี
yield_resultตัวเลข (decimal, ว่างได้)ผลผลิตที่ได้จริง ถ้ามีบันทึกไว้จากโมดูลเก็บเกี่ยว

Business Rules & Formulas

6. สูตรคำนวณและกฎทางธุรกิจ (Business Rules & Formulas)

ตรรกะที่ dev ต้อง implement จริงเบื้องหลัง entity/endpoint ด้านบน

คำนวณพื้นที่จากขอบเขต GPS

Phase 1

ใช้ตรวจสอบว่าพื้นที่ที่วาดบนแผนที่ตรงกับที่กรอกไว้หรือไม่

area_sq_meters =
  geodesic_area(gps_boundary polygon)
  (คำนวณจากพิกัดขอบเขตด้วยสูตรพื้นที่ทรงกลม/shoelace)

area_rai = area_sq_meters / 1600
  (1 ไร่ = 1,600 ตารางเมตร)

ตรวจสอบพื้นที่โซนย่อยไม่เกินแปลงแม่

Phase 1

ป้องกันข้อมูลผิดพลาดตอนแบ่งโซนย่อยเกินพื้นที่จริง

SUM(field_zone.area_rai WHERE field_id = X)
  <= field.area_rai (ของแปลง X)

ถ้าเกิน -> reject การบันทึกโซนใหม่/แก้ไข

สถานะการใช้ที่ดิน ณ ปัจจุบัน (Current Land Utilization)

Phase 1

ใช้สรุปว่าฟาร์มมีพื้นที่ว่างเหลือเท่าไหร่ ณ ตอนนี้

is_in_use(field/zone) =
  มี land_use_history ที่
  planting_start_date <= today
  AND (harvest_end_date >= today OR harvest_end_date ว่าง)

utilization_rate =
  SUM(area_rai ที่ is_in_use = true)
  / SUM(area_rai ทั้งหมด)

เตือนแปลงที่พักดินนานเกินกำหนด (Fallow Period Alert)

Phase 1

พักดินนานเกินไปอาจเสียโอกาสในการผลิตโดยไม่จำเป็น

fallow_days = today - last_harvest_end_date
  (ของ land_use_history ล่าสุดที่จบรอบแล้ว)

fallow_days > max_fallow_days
  -> flag เตือนให้พิจารณาวางแผนปลูกรอบใหม่

เตือนความเสี่ยงปลูกพืชตระกูลเดียวกันซ้ำ

Phase 2

ปลูกพืชตระกูลเดียวกันซ้ำในแปลงเดิมต่อเนื่องเพิ่มความเสี่ยงโรค/ศัตรูพืชสะสมในดิน

last_crop_family(field) =
  crop_family ของ land_use_history ล่าสุดของแปลงนั้น

new_crop_family == last_crop_family
