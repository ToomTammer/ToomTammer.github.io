โมดูลคลังสินค้า/สต็อก (Inventory & Warehouse)

สเปกสำหรับเริ่มพัฒนาได้ทันที ครอบคลุมขอบเขตและจุดเชื่อมต่อกับโมดูลอื่น ฟังก์ชันหลักแยก MVP กับที่เพิ่มทีหลังได้ โครงสร้างฐานข้อมูล API หลักที่ต้องมี สิทธิ์การเข้าถึงตามบทบาท และสูตรคำนวณ/กฎทางธุรกิจ

ส่วนหนึ่งของ คู่มือ ERP สำหรับธุรกิจฟาร์ม อัปเดต 18 ก.ค. 2569
1. ขอบเขตและจุดเชื่อมต่อ (Scope & Integration) 2. ฟังก์ชันหลัก (Core Functions) 3. ฐานข้อมูล (Database) 4. API 5. สิทธิ์การเข้าถึง (Roles) 6. สูตรคำนวณ (Formulas)
Scope & Integration

1. ขอบเขตและจุดเชื่อมต่อ (Scope & Integration Points)

โมดูลนี้เป็นศูนย์กลางของทุกการเข้า-ออกของสินค้าในฟาร์ม รับข้อมูลเข้าจากจัดซื้อ ส่งข้อมูลออกให้ขายและบัญชี ไม่ควรมีใครแก้ตัวเลขสต็อกตรง ๆ นอกจากผ่านการเคลื่อนไหวที่บันทึกไว้

อยู่ในขอบเขต

  • ทะเบียนสินค้า/วัตถุดิบ (Item Master)
  • รับเข้า-เบิกจ่ายสินค้า และ lot/batch tracking
  • ยอดคงเหลือสต็อกแบบเรียลไทม์ และมูลค่าสต็อก
  • แจ้งเตือนวันหมดอายุและจุดสั่งซื้อซ้ำ
  • ตรวจนับสต็อกจริงและโอนย้ายระหว่างคลัง

อยู่นอกขอบเขต (รับ/ส่งข้อมูลกับโมดูลอื่น)

  • การสั่งซื้อสินค้าเข้าคลัง — มาจาก จัดซื้อ ผ่านใบรับสินค้า
  • การตัดสต็อกตอนขาย — มาจาก ขายและลูกค้า
  • การบันทึกต้นทุนขาย (COGS) เข้าบัญชี — ส่งให้ บัญชีและการเงิน
  • ปริมาณอาหารสัตว์ที่ใช้ตามสูตรอาหาร — มาจาก ปศุสัตว์
  • ปริมาณปุ๋ย/สารเคมีที่ใช้ตามแผนปลูก — มาจาก พืชไร่/พืชสวน
โมดูลที่เกี่ยวข้องเหตุการณ์สิ่งที่คลังต้องทำPhase
จัดซื้อบันทึกรับสินค้า (goods receipt) ผ่านการตรวจสอบเพิ่ม stock เข้าคลังเป็น lot ใหม่Phase 1
ขายและลูกค้าปิดคำสั่งขาย/ออกใบส่งของตัดสต็อกตาม FIFO และส่งต้นทุนขายให้บัญชีPhase 1
ปศุสัตว์บันทึกการให้อาหารประจำวันตัดสต็อกอาหารสัตว์ตามสูตรที่ใช้จริงPhase 1
พืชไร่/พืชสวนบันทึกการให้ปุ๋ย/ฉีดพ่นสารเคมีตัดสต็อกปุ๋ย/สารเคมีตามพื้นที่ที่ใช้จริงPhase 1
บัญชีและการเงินต้องการมูลค่าต้นทุนขายรายวันส่งมูลค่าสต็อกที่ตัดออกให้ลงบัญชีอัตโนมัติPhase 1
จัดซื้อต้องการทราบว่าสินค้าไหนใกล้หมดแจ้งเตือนสต็อกถึงจุดสั่งซื้อซ้ำPhase 2
Core Functions

2. ฟังก์ชันหลัก (Core Functions)

แยกชัดว่าอะไรต้องใช้งานได้ตั้งแต่วันแรก (MVP) และอะไรเพิ่มทีหลังได้โดยไม่กระทบการควบคุมสต็อกพื้นฐาน

MVP — ต้องมีวันแรก Phase 1

  • จัดการทะเบียนสินค้า/วัตถุดิบ (สร้าง/แก้ไข/ปิดใช้งาน)
  • รับสินค้าเข้าคลังพร้อมระบุ lot/batch และวันหมดอายุ
  • เบิกจ่าย/ตัดสต็อกออกจากคลังตามลำดับ FIFO
  • ดูยอดคงเหลือสต็อกแบบเรียลไทม์ต่อสินค้า/คลัง/lot
  • แจ้งเตือนสินค้าใกล้หมดอายุ
  • แจ้งเตือนสต็อกต่ำกว่าระดับขั้นต่ำ (reorder point)
  • รายงานมูลค่าสต็อกคงเหลือสำหรับส่งบัญชี

เพิ่มทีหลังได้

  • ตรวจนับสต็อกจริง (physical count) พร้อมปรับยอดPhase 2
  • คลังหลายแห่ง/หลายจุดเก็บ พร้อมโอนย้ายสินค้าระหว่างคลังPhase 2
  • เสนอสร้างใบขอซื้ออัตโนมัติเมื่อถึงจุดสั่งซื้อซ้ำPhase 2
  • ตั้งค่าวิธีคิดต้นทุนแบบถัวเฉลี่ยถ่วงน้ำหนัก (นอกจาก FIFO)Phase 2
  • พยากรณ์ความต้องการสต็อกล่วงหน้าจากแผนการผลิตPhase 3
  • ตรวจสอบย้อนกลับถึง lot ต้นทางเมื่อสินค้ามีปัญหา (recall)Phase 3
  • วิเคราะห์อัตราหมุนเวียนสต็อก (inventory turnover)Phase 3
Database

3. ฐานข้อมูล (Database)

แต่ละเอนทิตีคือ 1 ตารางในฐานข้อมูล พร้อมคำอธิบายว่าแทนอะไรในโลกจริง และแต่ละฟิลด์เก็บอะไร ชนิดข้อมูลแบบไหน

item Phase 1

รายการสินค้า/วัตถุดิบ — ทะเบียนสินค้าทุกชนิดที่เก็บในคลัง เช่น อาหารสัตว์ เมล็ดพันธุ์ ปุ๋ย ยา อุปกรณ์

ความสัมพันธ์: ผูกกับ stock_lot และ stock_movement ถูกอ้างอิงจาก purchase_order_line (จัดซื้อ) และคำสั่งขาย

ฟิลด์ชนิดข้อมูลเก็บอะไร
idเลขอ้างอิง/UUID (PK)รหัสประจำแถวนี้ ไม่ซ้ำกัน สร้างอัตโนมัติ
item_codeข้อความ (text)รหัสสินค้าที่ใช้อ้างอิงภายในระบบ
nameข้อความ (text)ชื่อสินค้า เช่น "อาหารไก่ไข่สูตรเข้มข้น"
categoryตัวเลือกคงที่ (enum)ประเภทสินค้า เลือกได้เฉพาะ: feed, seed, fertilizer, medicine, equipment, other
unitข้อความ (text)หน่วยนับ เช่น กก., ลิตร, ถุง, ชิ้น
reorder_pointตัวเลข (decimal)ระดับสต็อกขั้นต่ำ ถ้าต่ำกว่านี้ต้องสั่งซื้อเพิ่ม
max_stock_levelตัวเลข (decimal)ระดับสต็อกสูงสุดที่ต้องการสำรองไว้
shelf_life_daysตัวเลข (integer, ว่างได้)อายุการเก็บรักษาเป็นวัน ใช้คำนวณวันหมดอายุอัตโนมัติตอนรับเข้า

warehouse Phase 1

คลัง/จุดเก็บ — สถานที่จัดเก็บสินค้าจริง เช่น โกดังกลาง โรงเก็บอาหารสัตว์ประจำโรงเรือน โรงเก็บปุ๋ย

ความสัมพันธ์: ผูกกับ stock_lot ว่าล็อตไหนอยู่คลังไหน และอาจผูกกับ cost_center (โมดูลบัญชี) ถ้าเป็นคลังประจำพื้นที่เฉพาะ

ฟิลด์ชนิดข้อมูลเก็บอะไร
idเลขอ้างอิง/UUID (PK)รหัสประจำแถวนี้ ไม่ซ้ำกัน สร้างอัตโนมัติ
warehouse_codeข้อความ (text)รหัสคลัง
nameข้อความ (text)ชื่อคลัง เช่น "โกดังกลาง" หรือ "โรงเก็บอาหาร โรงเรือน 2"
cost_center_idเลขอ้างอิง (FK → cost_center, ว่างได้)ถ้าคลังนี้ผูกกับพื้นที่เฉพาะ ให้ชี้ไปยังศูนย์ต้นทุนนั้น

stock_lot Phase 1

ล็อต/รุ่นสินค้าคงคลัง — สินค้าล็อตหนึ่งที่รับเข้ามาพร้อมกัน มีวันหมดอายุและต้นทุนของตัวเอง ใช้ทำ FIFO และตรวจสอบย้อนกลับ

ความสัมพันธ์: ผูกกับ item, warehouse และอ้างอิง goods_receipt จากโมดูลจัดซื้อที่ทำให้เกิดล็อตนี้

ฟิลด์ชนิดข้อมูลเก็บอะไร
idเลขอ้างอิง/UUID (PK)รหัสประจำแถวนี้ ไม่ซ้ำกัน สร้างอัตโนมัติ
lot_noข้อความ (text)เลขที่ล็อต สร้างอัตโนมัติตอนรับเข้า
item_id / warehouse_idเลขอ้างอิง (FK)ล็อตนี้เป็นสินค้าอะไร เก็บอยู่คลังไหน
goods_receipt_refข้อความ (text, ว่างได้)เลขที่ใบรับสินค้าต้นทางจากโมดูลจัดซื้อ
received_dateวันที่ (date)วันที่รับล็อตนี้เข้าคลัง
expiry_dateวันที่ (date, ว่างได้)วันหมดอายุของล็อตนี้ (คำนวณจาก received_date + shelf_life_days หรือระบุเอง)
unit_costตัวเลข (decimal)ต้นทุนต่อหน่วยของล็อตนี้ ณ วันที่รับเข้า
quantity_remainingตัวเลข (decimal)ปริมาณคงเหลือในล็อตนี้ ณ ตอนนี้

stock_movement Phase 1

การเคลื่อนไหวสต็อก — บันทึกทุกครั้งที่มีสินค้าเข้า-ออกคลัง ไม่ว่าจะรับเข้า เบิกใช้ ขาย โอนย้าย หรือปรับยอด เป็นประวัติที่แก้ไขย้อนหลังไม่ได้

ความสัมพันธ์: ผูกกับ stock_lot และอ้างอิงเอกสารต้นทางจากโมดูลอื่น เช่น คำสั่งขาย บันทึกการให้อาหาร

ฟิลด์ชนิดข้อมูลเก็บอะไร
idเลขอ้างอิง/UUID (PK)รหัสประจำแถวนี้ ไม่ซ้ำกัน สร้างอัตโนมัติ
movement_typeตัวเลือกคงที่ (enum)ประเภทการเคลื่อนไหว เลือกได้เฉพาะ: receipt, issue, sale, transfer, adjustment
stock_lot_idเลขอ้างอิง (FK → stock_lot)เคลื่อนไหวกับล็อตไหน
quantityตัวเลข (decimal)จำนวนที่เคลื่อนไหว ค่าบวก=เข้าคลัง ค่าลบ=ออกจากคลัง
movement_dateวันที่ (date)วันที่เกิดการเคลื่อนไหวจริง
source_moduleตัวเลือกคงที่ (enum)ใครสั่งให้เกิดรายการนี้ เลือกได้เฉพาะ: procurement, sales, livestock, crop, manual
source_ref_idข้อความ (text)เลขอ้างอิงเอกสารต้นทาง เช่น เลขที่ใบส่งของที่ทำให้ตัดสต็อก
cost_center_idเลขอ้างอิง (FK → cost_center, ว่างได้)ศูนย์ต้นทุนที่รับ/เสียของนี้ไป ค่าเริ่มต้น default มาจาก stock_lot.warehouse_id → warehouse.cost_center_id แต่ override ได้ตอนเบิกใช้จริง เช่น เบิกอาหารสัตว์ให้ batch ที่ไม่ตรงกับคลังตั้งต้น — ต้องมีค่านี้ก่อนโพสต์ COGS เข้าบัญชี ถ้า resolve ไม่ได้ทั้งสองทางให้ reject การตัดสต็อก

stock_count + stock_count_line Phase 2

การตรวจนับสต็อก — บันทึกผลตรวจนับจริงเทียบกับยอดในระบบ เพื่อปรับยอดให้ตรงกับความเป็นจริง

ความสัมพันธ์: ผูกกับ warehouse และสร้าง stock_movement ประเภท adjustment เมื่อพบส่วนต่าง

ฟิลด์ชนิดข้อมูลเก็บอะไร
idเลขอ้างอิง/UUID (PK)รหัสประจำแถวนี้ ไม่ซ้ำกัน สร้างอัตโนมัติ
count_dateวันที่ (date)วันที่ตรวจนับ
warehouse_idเลขอ้างอิง (FK → warehouse)ตรวจนับคลังไหน
counted_byเลขอ้างอิง (FK → user)ใครเป็นคนตรวจนับ
statusตัวเลือกคงที่ (enum)สถานะ เลือกได้เฉพาะ: draft, completed, adjusted
(line) idเลขอ้างอิง/UUID (PK)รหัสประจำบรรทัดนี้ ไม่ซ้ำกัน สร้างอัตโนมัติ
(line) stock_count_idเลขอ้างอิง (FK → stock_count)บรรทัดนี้เป็นของรอบตรวจนับไหน
(line) stock_lot_idเลขอ้างอิง (FK → stock_lot)นับล็อตไหน
(line) system_quantity / counted_quantityตัวเลข (decimal)ยอดในระบบตอนเริ่มนับ เทียบกับยอดที่นับได้จริง

stock_transfer Phase 2

การโอนย้ายสินค้าระหว่างคลัง — เช่น ย้ายอาหารสัตว์จากโกดังกลางไปโรงเก็บประจำโรงเรือน

ความสัมพันธ์: ผูกกับ warehouse ต้นทาง-ปลายทาง และสร้าง stock_movement ประเภท transfer สองรายการ (ออกจากต้นทาง เข้าปลายทาง)

ฟิลด์ชนิดข้อมูลเก็บอะไร
idเลขอ้างอิง/UUID (PK)รหัสประจำแถวนี้ ไม่ซ้ำกัน สร้างอัตโนมัติ
from_warehouse_id / to_warehouse_idเลขอ้างอิง (FK → warehouse)โอนจากคลังไหนไปคลังไหน
transfer_dateวันที่ (date)วันที่โอนย้าย
statusตัวเลือกคงที่ (enum)สถานะ เลือกได้เฉพาะ: draft, in_transit, completed

Business Rules & Formulas

6. สูตรคำนวณและกฎทางธุรกิจ (Business Rules & Formulas)

ตรรกะที่ dev ต้อง implement จริงเบื้องหลัง entity/endpoint ด้านบน

การตัดสต็อกแบบ FIFO

Phase 1

เข้าก่อนออกก่อน — ใช้ทุกครั้งที่มีการเบิกจ่ายหรือขายสินค้าออกจากคลัง

ORDER BY stock_lot.received_date ASC
  (lot ที่รับเข้าเก่าสุดถูกตัดออกก่อน)

ตัดจาก lot ที่ quantity_remaining > 0 ไปเรื่อย ๆ
  จนครบ quantity_needed

cost_of_issue = SUM( qty_ตัดจากแต่ละ_lot × lot.unit_cost )

มูลค่าสต็อกคงเหลือ (Stock Valuation)

Phase 1

ใช้สรุปส่งให้โมดูลบัญชีบันทึกมูลค่าสินทรัพย์คงเหลือ

stock_value(item, warehouse) =
  SUM( stock_lot.quantity_remaining × stock_lot.unit_cost )
  ต่อทุก lot ของ item/warehouse นั้น

แจ้งเตือนวันหมดอายุ (Expiry Alert)

Phase 1

ตั้ง threshold ล่วงหน้าได้ต่อ item หรือทั้งหมวดหมู่สินค้า

days_to_expiry = stock_lot.expiry_date - today

flag เตือนถ้า days_to_expiry <= alert_threshold_days
  (ค่าเริ่มต้นแนะนำ: 7-14 วัน แล้วแต่ประเภทสินค้า)

จุดสั่งซื้อซ้ำ (Reorder Point Trigger)

Phase 1

รวมยอดคงเหลือทุกล็อตทุกคลังของสินค้าเดียวกัน แล้วเทียบกับระดับขั้นต่ำ

current_stock(item) = SUM(quantity_remaining)
  ต่อทุก lot ทุกคลังของ item นั้น

trigger: current_stock <= item.reorder_point

suggested_order_qty = item.max_stock_level - current_stock

ส่วนต่างจากการตรวจนับ (Stock Count Variance)

Phase 2

ใช้สร้างรายการปรับยอดหลังตรวจนับสต็อกจริง

variance = counted_quantity - system_quantity

variance != 0
  -> สร้าง stock_movement (movement_type = adjustment)

|variance| > threshold_pct × system_quantity
  -> ต้องมีผู้อนุมัติก่อนปรับยอดจริง
     (threshold_pct แนะนำเริ่มที่ 5%)

ต้นทุนถัวเฉลี่ยถ่วงน้ำหนัก (Weighted Average Cost)

Phase 2

ทางเลือกแทน FIFO สำหรับฟาร์มที่ต้องการต้นทุนคงที่ต่อรอบมากกว่าติดตามราคาต่อล็อต

weighted_avg_cost(item, warehouse) =
  SUM( quantity_remaining × unit_cost )
  / SUM( quantity_remaining )
  ต่อทุก lot ของ item/warehouse นั้น

หมายเหตุ: เลือกวิธีคิดต้นทุนได้ต่อสินค้าหรือทั้งระบบ แต่ควรคงที่ตลอดรอบบัญชี ไม่สลับไปมา เพื่อไม่ให้ต้นทุนขายเพี้ยน

เอกสารนี้เป็นสเปกเริ่มพัฒนาโมดูล "คลังสินค้า/สต็อก" ควรรีวิวโครงสร้างฐานข้อมูลกับทีม dev จริงก่อนเริ่ม implement ← กลับไปภาพรวม ERP ฟาร์ม
