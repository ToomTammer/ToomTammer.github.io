Scope & Integration

1. ขอบเขตและจุดเชื่อมต่อ (Scope & Integration Points)

โมดูลนี้เป็นจุดปิดวงจรของสัตว์แต่ละตัว/ฝูง — ต้องผ่านการตรวจสอบระยะหยุดยาจากโมดูลสุขภาพก่อนอนุญาตส่งออก แล้วอัปเดตสถานะกลับไปที่ทะเบียนสัตว์ ไม่ได้เป็นเจ้าของข้อมูลการตายเอง (อยู่ที่ทะเบียนสัตว์แล้ว) แค่ดึงมาสรุปรายงานปิดรอบ

อยู่ในขอบเขต

  • มาตรฐานเกรดตามน้ำหนัก/ขนาด (Grading Standard)
  • คัดเกรดสัตว์ก่อนส่งขาย/ชำแหละ (Pre-Sale Grading)
  • บันทึกการส่งสัตว์ออกขาย/ชำแหละ (Dispatch Record)
  • เปรียบเทียบราคาผู้รับซื้อหลายราย
  • รายงานสรุปผลผลิตปิดรอบ (ขาย+ตาย+คัดออก เทียบจำนวนเริ่มต้น)

อยู่นอกขอบเขต (รับ/ส่งข้อมูลกับโมดูลอื่น)

  • น้ำหนัก/ความพร้อมขาย — รับจาก การเจริญเติบโตและผลผลิต
  • ตรวจสอบระยะหยุดยา — รับผลจาก สุขภาพและวัคซีน
  • การบันทึกว่าสัตว์ตัวไหนตายจริงและจำนวนคงเหลือ — เป็นของ ทะเบียนสัตว์ อยู่แล้ว โมดูลนี้แค่ดึงมาสรุปรายงาน
  • การอัปเดตสถานะสัตว์เป็น sold/culled — ส่งต่อให้ ทะเบียนสัตว์
  • การตัดสต็อกสัตว์มีชีวิต/สร้างสต็อกซาก — ส่งต่อให้ คลังสินค้า/สต็อก
  • ราคาขายจริง/ใบสั่งขาย — ส่งต่อให้ ขายและลูกค้า
โมดูลที่เกี่ยวข้องเหตุการณ์สิ่งที่คัดแยกฯ ต้องทำPhase
การเจริญเติบโตและผลผลิตสัตว์/ฝูงถึงเกณฑ์น้ำหนักพร้อมขายรับแจ้งเตือนมาวางแผนคัดแยกPhase 1
สุขภาพและวัคซีนต้องการส่งสัตว์ออกขาย/ชำแหละตรวจสอบระยะหยุดยาก่อนอนุมัติPhase 1
คัดแยกฯ (ตัวเอง) → ทะเบียนสัตว์คัดสัตว์ออกขาย/ชำแหละสำเร็จอัปเดตสถานะสัตว์เป็น sold/culledPhase 1
คัดแยกฯ (ตัวเอง) → คลังสินค้า/สต็อกคัดเกรดเสร็จแจ้งตัดสต็อกสัตว์มีชีวิต/สร้างสต็อกซากPhase 1
คัดแยกฯ (ตัวเอง) → ขายและลูกค้ามีสัตว์พร้อมขายแยกตามเกรดให้ข้อมูลเกรด+ราคาแนะนำไปตั้งราคาขายPhase 1
Core Functions

2. ฟังก์ชันหลัก (Core Functions)

แยกชัดว่าอะไรต้องใช้งานได้ตั้งแต่วันแรก (MVP) และอะไรเพิ่มทีหลังได้โดยไม่กระทบการปิดรอบพื้นฐาน

MVP — ต้องมีวันแรก Phase 1

  • ตั้งมาตรฐานเกรดตามน้ำหนัก/ขนาดต่อชนิดสัตว์
  • ตรวจสอบระยะหยุดยาก่อนอนุมัติคัดแยกส่งขาย
  • บันทึกการคัดเกรดจริง (น้ำหนัก เกรด) ต่อตัว/ฝูง
  • บันทึกการส่งสัตว์ออกขาย/ชำแหละ พร้อมอัปเดตสถานะสัตว์
  • ดูรายงานสรุปผลผลิตปิดรอบเทียบจำนวนเริ่มต้น
  • เชื่อมราคารับซื้อกับเกรด/น้ำหนัก

เพิ่มทีหลังได้

  • เปรียบเทียบราคาผู้รับซื้อหลายราย (โรงชำแหละ/ตลาด)Phase 2
  • วิเคราะห์สาเหตุการสูญเสียแยกตามช่วงอายุ/สาเหตุPhase 2
  • พยากรณ์ปริมาณที่จะพร้อมขายล่วงหน้าจากแนวโน้มการเติบโตPhase 3
  • วิเคราะห์ความสัมพันธ์ระหว่างการดูแลกับคุณภาพ/เกรดที่ได้Phase 3
Database

3. ฐานข้อมูล (Database)

แต่ละเอนทิตีคือ 1 ตารางในฐานข้อมูล พร้อมคำอธิบายว่าแทนอะไรในโลกจริง และแต่ละฟิลด์เก็บอะไร ชนิดข้อมูลแบบไหน

grading_standard_livestock Phase 1

มาตรฐานเกรดปศุสัตว์ — เกณฑ์ที่ใช้ตัดสินว่าสัตว์เป็นเกรดอะไรตามน้ำหนัก/ขนาด ต่อชนิดสัตว์

ความสัมพันธ์: ผูกกับ species จากโมดูลทะเบียนสัตว์ ถูกอ้างอิงจาก sorting_record ตอนตัดสินเกรด

ฟิลด์ชนิดข้อมูลเก็บอะไร
speciesข้อความ/ตัวเลือกคงที่ (enum)มาตรฐานนี้ใช้กับสัตว์ชนิดไหน
gradeข้อความ/ตัวเลือกคงที่ (enum)ชื่อเกรด เช่น A, B, C, reject
min_weight / max_weightตัวเลข (decimal)ช่วงน้ำหนักที่ยอมรับสำหรับเกรดนี้

sorting_record Phase 1

บันทึกการคัดเกรด — บันทึกผลคัดเกรดจริงของสัตว์/ฝูงก่อนส่งขาย

ความสัมพันธ์: ผูกกับ animal/animal_group และ grading_standard_livestock ที่ใช้ตัดสิน เป็นต้นทางให้ dispatch_record

ฟิลด์ชนิดข้อมูลเก็บอะไร
animal_id / animal_group_idเลขอ้างอิง (FK)คัดเกรดสัตว์ตัวไหนหรือฝูงไหน
sorting_dateวันที่ (date)วันที่คัดเกรดจริง
weight_at_sortingตัวเลข (decimal)น้ำหนักที่ชั่งได้ตอนคัดเกรด
assigned_gradeข้อความ/ตัวเลือกคงที่ (enum)เกรดที่ตัดสินได้จากน้ำหนักเทียบมาตรฐาน
sorted_byเลขอ้างอิง (FK → user)ใครเป็นคนคัดเกรด

dispatch_record Phase 1

บันทึกการส่งขาย/ชำแหละ — บันทึกการส่งสัตว์ออกจากฟาร์มจริง ไม่ว่าจะขายเป็นตัวมีชีวิตหรือส่งชำแหละ เป็นจุดที่ต้องตรวจสอบระยะหยุดยาและอัปเดตสถานะสัตว์

ความสัมพันธ์: ผูกกับ sorting_record และ animal/animal_group เชื่อมต่อไปยังโมดูลขายและลูกค้า/คลังสินค้า

ฟิลด์ชนิดข้อมูลเก็บอะไร
sorting_record_idเลขอ้างอิง (FK → sorting_record)ส่งออกตามผลคัดเกรดครั้งไหน
dispatch_dateวันที่ (date)วันที่ส่งออกจริง
destination_typeตัวเลือกคงที่ (enum)ปลายทาง เลือกได้เฉพาะ: slaughterhouse, live_market, direct_customer
buyer_refข้อความ (text, ว่างได้)ผู้ซื้อ/โรงชำแหละที่รับซื้อ
quantityตัวเลข (integer)จำนวนตัวที่ส่งออกครั้งนี้
total_weightตัวเลข (decimal)น้ำหนักรวมที่ส่งออกครั้งนี้

buyer_price_quote Phase 2

ใบเสนอราคาผู้รับซื้อ — ราคาที่ผู้รับซื้อแต่ละราย (โรงชำแหละ/ตลาด) เสนอสำหรับสัตว์เกรดหนึ่ง ใช้เปรียบเทียบก่อนตัดสินใจส่งขาย

ความสัมพันธ์: ผูกกับ species/grade เป็นข้อมูลอ้างอิงก่อนสร้าง dispatch_record

ฟิลด์ชนิดข้อมูลเก็บอะไร
buyer_refข้อความ (text)ผู้รับซื้อรายไหน
species / gradeข้อความ/ตัวเลือกคงที่เสนอราคาสำหรับสัตว์ชนิด/เกรดไหน
price_per_kgตัวเลข (decimal)ราคาต่อกิโลกรัมที่เสนอ
quote_date / valid_untilวันที่ (date)วันที่เสนอราคาและวันหมดอายุของราคานี้

Business Rules & Formulas

6. สูตรคำนวณและกฎทางธุรกิจ (Business Rules & Formulas)

ตรรกะที่ dev ต้อง implement จริงเบื้องหลัง entity/endpoint ด้านบน — ข้อ 2 เรียกใช้กฎจากโมดูลสุขภาพและวัคซีน ไม่ implement ซ้ำ

ตัดสินเกรดจากน้ำหนัก (Auto Grade Assignment)

Phase 1

ตรวจไล่จากเกรดสูงสุดลงมา ตัวแรกที่ผ่านคือเกรดที่กำหนดให้

assigned_grade =
  grading_standard_livestock ตัวแรก (เรียงจากเกรดสูงสุด)
  ที่ min_weight <= weight_at_sorting <= max_weight

ถ้าไม่เข้าเกณฑ์เกรดใดเลย -> assigned_grade = reject

ตรวจสอบก่อนอนุมัติส่งขาย/ชำแหละ (Pre-Dispatch Safety Check)

Phase 1

เรียกใช้กฎจากโมดูลสุขภาพและวัคซีนโดยตรง ไม่ทำซ้ำเอง

before insert dispatch_record:
  call is_safe_to_sell(animal/animal_group, dispatch_date)
  (จากโมดูลสุขภาพและวัคซีน)

ถ้า false -> reject การบันทึก
  พร้อมแจ้งวันที่ขายได้ปลอดภัยจริง (safe_sale_date)

รายงานปิดรอบผลิต (Production Closeout Reconciliation)

Phase 1

ตรวจสอบว่าจำนวนสัตว์ครบถ้วน ไม่มีตัวที่หายไปโดยไม่มีที่มาที่ไป

SUM(dispatch_record.quantity)
+ SUM(สัตว์ที่ตาย/คัดออก จากโมดูลทะเบียนสัตว์)
+ current_quantity คงเหลือ (ถ้ายังไม่จบรอบ)
= animal_group.initial_quantity

ถ้าผลรวมไม่เท่ากัน -> flag ให้ตรวจสอบข้อมูลย้อนหลัง

เลือกผู้รับซื้อราคาดีที่สุด (Best Buyer Price Selection)

Phase 2

ใช้ตอนมีใบเสนอราคาหลายรายสำหรับเกรดเดียวกัน

best_buyer(species, grade) = buyer_price_quote
  WHERE price_per_kg = MAX(price_per_kg)
    AND valid_until >= today

มูลค่ารวมตามเกรดที่ส่งออก (Total Dispatch Value by Grade)

Phase 1

ใช้เปรียบเทียบว่าการคัดเกรดทำให้มูลค่ารวมดีขึ้นจริงเทียบกับขายรวมราคาเดียว

total_value(animal_group) =
  SUM( dispatch_record.total_weight × price_per_kg
       ของเกรดนั้น )
  ต่อทุกเกรดของฝูงนี้
เอกสารนี้เป็นสเปกเริ่มพัฒนาโมดูล "คัดแยกและส่งขาย" ควรรีวิวโครงสร้างฐานข้อมูลกับทีม dev จริงก่อนเริ่ม implement ← กลับไปภาพรวม ERP ฟาร์ม
