โมดูลสุขภาพและวัคซีน (Health & Vaccination)

สเปกสำหรับเริ่มพัฒนาได้ทันที ครอบคลุมขอบเขตและจุดเชื่อมต่อกับโมดูลอื่น ฟังก์ชันหลักแยก MVP กับที่เพิ่มทีหลังได้ โครงสร้างฐานข้อมูล API หลักที่ต้องมี สิทธิ์การเข้าถึงตามบทบาท และสูตรคำนวณ/กฎทางธุรกิจ

ส่วนหนึ่งของ คู่มือ ERP สำหรับธุรกิจฟาร์ม อัปเดต 18 ก.ค. 2569

Scope & Integration

1. ขอบเขตและจุดเชื่อมต่อ (Scope & Integration Points)

โมดูลนี้เป็นจุดสำคัญด้านความปลอดภัยอาหาร — ต้องคุมระยะหยุดยา (withdrawal period) ก่อนอนุญาตขาย/ชำแหละ เทียบเท่ากับ PHI ของโมดูลพืช "การให้น้ำ ปุ๋ย และยา"

อยู่ในขอบเขต

  • ตารางวัคซีนมาตรฐานต่อชนิดสัตว์ (Vaccination Schedule)
  • บันทึกการฉีดวัคซีนจริง (Vaccination Record)
  • บันทึกการรักษา/ใช้ยา (Treatment Record) พร้อมระยะหยุดยา
  • ตรวจสอบระยะหยุดยาก่อนส่งขาย/ชำแหละ (Withdrawal Period)
  • ประวัติสุขภาพรวมต่อตัว/ฝูง

อยู่นอกขอบเขต (รับ/ส่งข้อมูลกับโมดูลอื่น)

  • ทะเบียนสัตว์/ฝูง — รับจาก ทะเบียนสัตว์
  • การตัดสต็อกยา/วัคซีนที่ใช้จริง — ส่งต่อให้ คลังสินค้า/สต็อก
  • ตรวจสอบว่าปลอดภัยขาย/ชำแหละหรือยัง — ส่งต่อให้ คัดแยกและส่งขาย ใช้ตรวจก่อนอนุมัติ
  • ต้นทุนค่ายา/วัคซีนเข้ารอบผลิต — สะท้อนผ่าน COGS ที่คลังตัดแล้ว ไม่คำนวณเอง
โมดูลที่เกี่ยวข้องเหตุการณ์สิ่งที่สุขภาพฯ ต้องทำPhase
ทะเบียนสัตว์มีสัตว์/ฝูงพร้อมดูแลอ้างอิง animal_id/animal_group_idPhase 1
สุขภาพฯ (ตัวเอง) → คลังสินค้า/สต็อกบันทึกฉีดวัคซีน/ใช้ยาจริงแจ้งตัดสต็อกวัคซีน/ยาที่ใช้Phase 1
คัดแยกและส่งขายต้องการคัดสัตว์ออกขาย/ชำแหละตรวจสอบสถานะระยะหยุดยาก่อนอนุญาตPhase 1
ผสมพันธุ์และตั้งท้องต้องการประวัติสุขภาพช่วงตั้งท้องให้ health record อ้างอิงPhase 2
Core Functions

2. ฟังก์ชันหลัก (Core Functions)

แยกชัดว่าอะไรต้องใช้งานได้ตั้งแต่วันแรก (MVP) และอะไรเพิ่มทีหลังได้โดยไม่กระทบการดูแลสุขภาพพื้นฐาน

MVP — ต้องมีวันแรก Phase 1

  • ตั้งตารางวัคซีนมาตรฐานต่อชนิดสัตว์
  • บันทึกการฉีดวัคซีนจริง พร้อมแจ้งตัดสต็อก
  • บันทึกการรักษา/ใช้ยา พร้อมระบุระยะหยุดยา
  • ตรวจสอบสถานะระยะหยุดยาก่อนอนุญาตขาย/ชำแหละ
  • ดูประวัติสุขภาพรวมต่อตัว/ฝูง
  • แจ้งเตือนวัคซีนที่ถึงกำหนดตามตารางมาตรฐาน

เพิ่มทีหลังได้

  • บันทึกอาการป่วย/การวินิจฉัยเบื้องต้นก่อนตัดสินใจรักษาPhase 2
  • คำนวณอัตราการเจ็บป่วยต่อฝูงPhase 2
  • เชื่อมกับสัตวแพทย์ภายนอกสำหรับกรณีซับซ้อนPhase 2
  • วิเคราะห์แนวโน้มโรคระบาดเทียบสภาพแวดล้อมโรงเรือนPhase 3
  • พยากรณ์ความเสี่ยงโรคล่วงหน้าจากข้อมูลย้อนหลังPhase 3
Database

3. ฐานข้อมูล (Database)

แต่ละเอนทิตีคือ 1 ตารางในฐานข้อมูล พร้อมคำอธิบายว่าแทนอะไรในโลกจริง และแต่ละฟิลด์เก็บอะไร ชนิดข้อมูลแบบไหน

vaccination_schedule_standard Phase 1

ตารางวัคซีนมาตรฐาน — กำหนดว่าสัตว์ชนิดหนึ่งต้องฉีดวัคซีนอะไรตอนอายุเท่าไหร่ ใช้เป็นแผนอ้างอิงเทียบกับสัตว์จริง

ความสัมพันธ์: ผูกกับ species (ชนิดสัตว์จากโมดูลทะเบียนสัตว์) ถูกใช้เทียบกับอายุจริงของสัตว์เพื่อหาวัคซีนที่ถึงกำหนด

ฟิลด์ชนิดข้อมูลเก็บอะไร
idเลขอ้างอิง/UUID (PK)รหัสประจำแถวนี้ ไม่ซ้ำกัน สร้างอัตโนมัติ
speciesข้อความ/ตัวเลือกคงที่ (enum)ชนิดสัตว์ที่ตารางนี้ใช้กับ
vaccine_nameข้อความ (text)ชื่อวัคซีน
age_days_dueตัวเลข (integer)อายุเป็นวันที่ควรฉีดวัคซีนนี้
is_boosterจริง/เท็จ (boolean)เป็นวัคซีนกระตุ้นซ้ำหรือไม่

vaccination_record Phase 1

บันทึกการฉีดวัคซีน — บันทึกทุกครั้งที่ฉีดวัคซีนจริงให้สัตว์หรือฝูง

ความสัมพันธ์: ผูกกับ animal/animal_group และ item (วัคซีนจากโมดูลคลังสินค้า) ที่ถูกตัดสต็อก

ฟิลด์ชนิดข้อมูลเก็บอะไร
idเลขอ้างอิง/UUID (PK)รหัสประจำแถวนี้ ไม่ซ้ำกัน สร้างอัตโนมัติ
animal_id / animal_group_idเลขอ้างอิง (FK)ฉีดให้สัตว์ตัวไหนหรือฝูงไหน
vaccine_item_idเลขอ้างอิง (FK → item)ใช้วัคซีนชนิดไหนจากคลังสินค้า
vaccination_dateวันที่ (date)วันที่ฉีดจริง
administered_byเลขอ้างอิง (FK → user)ใครเป็นคนฉีด

treatment_record Phase 1

บันทึกการรักษา/ใช้ยา — บันทึกทุกครั้งที่รักษาโรคหรือใช้ยา พร้อมระยะหยุดยาที่ต้องเว้นก่อนขาย/ชำแหละ เป็นจุดสำคัญที่สุดด้านความปลอดภัยอาหาร

ความสัมพันธ์: ผูกกับ animal/animal_group และ item (ยาจากโมดูลคลังสินค้าที่มีค่า withdrawal_days กำกับ)

ฟิลด์ชนิดข้อมูลเก็บอะไร
idเลขอ้างอิง/UUID (PK)รหัสประจำแถวนี้ ไม่ซ้ำกัน สร้างอัตโนมัติ
animal_id / animal_group_idเลขอ้างอิง (FK)รักษาสัตว์ตัวไหนหรือฝูงไหน
medication_item_idเลขอ้างอิง (FK → item)ใช้ยาชนิดไหนจากคลังสินค้า
diagnosisข้อความ (text)อาการ/โรคที่วินิจฉัยได้
treatment_dateวันที่ (date)วันที่รักษาจริง
dosageตัวเลข (decimal)ปริมาณยาที่ใช้
withdrawal_daysตัวเลข (integer)จำนวนวันที่ต้องเว้นก่อนขาย/ชำแหละได้ ดึงจากมาตรฐานของยานั้น
safe_sale_dateวันที่ (date)วันที่ขายได้อย่างปลอดภัย คำนวณจาก treatment_date + withdrawal_days

health_symptom_log Phase 2

บันทึกอาการเบื้องต้น — บันทึกอาการผิดปกติที่สังเกตเห็นก่อนตัดสินใจรักษา ใช้ติดตามและวิเคราะห์แนวโน้มโรค

ความสัมพันธ์: ผูกกับ animal/animal_group อาจนำไปสู่ treatment_record ถ้าตัดสินใจรักษา

ฟิลด์ชนิดข้อมูลเก็บอะไร
idเลขอ้างอิง/UUID (PK)รหัสประจำแถวนี้ ไม่ซ้ำกัน สร้างอัตโนมัติ
animal_id / animal_group_idเลขอ้างอิง (FK)พบอาการที่สัตว์ตัวไหนหรือฝูงไหน
observed_dateวันที่ (date)วันที่สังเกตเห็นอาการ
symptom_descriptionข้อความ (text)รายละเอียดอาการที่พบ
severityตัวเลือกคงที่ (enum)ความรุนแรง เลือกได้เฉพาะ: mild, moderate, severe
treatment_record_idเลขอ้างอิง (FK → treatment_record, ว่างได้)ถ้านำไปสู่การรักษาแล้ว ชี้ไปยังรายการรักษานั้น

Business Rules & Formulas

6. สูตรคำนวณและกฎทางธุรกิจ (Business Rules & Formulas)

ตรรกะที่ dev ต้อง implement จริงเบื้องหลัง entity/endpoint ด้านบน — ข้อ 1-2 เป็นกฎความปลอดภัยอาหารที่สำคัญที่สุดของโมดูลนี้

คำนวณวันที่ปลอดภัยขาย/ชำแหละ (Safe Sale Date)

Phase 1

คำนวณทันทีที่บันทึก treatment_record ทุกครั้ง

safe_sale_date = treatment_date + withdrawal_days

ตรวจสอบก่อนอนุมัติขาย/ชำแหละจริง (Pre-Sale Safety Check)

Phase 1

กฎบังคับที่ต้อง enforce ที่ระดับ API ไม่ใช่แค่เตือนใน UI — เทียบเท่า pre-harvest safety gate ของโมดูลพืช

is_safe_to_sell(animal/animal_group, sale_date) =
  ไม่มี treatment_record ใดของสัตว์/ฝูงนี้
  ที่ safe_sale_date > sale_date ที่ต้องการขายจริง

ถ้าไม่ผ่าน -> ห้ามโมดูลคัดแยกและส่งขาย
  บันทึกการขาย/ชำแหละจนกว่าจะถึง safe_sale_date

คำนวณวัคซีนที่ถึงกำหนด (Vaccination Due Calculation)

Phase 1

เทียบอายุปัจจุบันของสัตว์กับตารางมาตรฐาน หาว่าวัคซีนตัวไหนยังไม่ได้ฉีด

current_age_days = today - birth_date (หรือ start_date)

due_vaccines =
  vaccination_schedule_standard
  ที่ age_days_due <= current_age_days
  AND ยังไม่มี vaccination_record ที่ตรงกับวัคซีนนั้น

อัตราการเจ็บป่วย (Morbidity Rate)

Phase 2

ใช้ติดตามสุขภาพรวมของฝูงเทียบเป็น KPI มาตรฐาน

morbidity_rate_pct(animal_group, period) =
  COUNT(สัตว์ที่มี treatment_record ในช่วงเวลานี้)
  / current_quantity ของฝูง × 100

เตือนวัคซีนล่าช้า (Overdue Vaccination Alert)

Phase 1

แยกจาก "ถึงกำหนด" ธรรมดา — เตือนเฉพาะที่เลยกรอบเวลาผ่อนผันแล้ว

overdue_vaccines =
  due_vaccines ที่
  (current_age_days - age_days_due) > grace_period_days
  (ค่าเริ่มต้นแนะนำ: 7 วัน)

-> flag เตือนผู้จัดการฟาร์ม/สัตวแพทย์

7. หน้าจอที่ต้องมี (Screens/Pages)

รายชื่อหน้าจอที่ต้องมีจริงในโมดูลนี้ พร้อมส่วนประกอบหลักของแต่ละหน้า — ใช้เป็น checklist ออกแบบ UI ต่อได้ตรง ๆ ไม่ต้องนั่งไล่จากฟังก์ชัน/entity เอง

แดชบอร์ดสุขภาพและวัคซีน (Health & Vaccination Dashboard) Phase 1

หน้าแรกที่สัตวแพทย์/ผู้จัดการฟาร์มเปิดดูภาพรวมสุขภาพประจำวัน

  • การ์ดสรุป: จำนวนวัคซีนที่ถึงกำหนดวันนี้ (due_vaccines), จำนวนวัคซีนล่าช้า (overdue_vaccines), จำนวนสัตว์/ฝูงที่ยังอยู่ในระยะหยุดยา
  • รายการแจ้งเตือนวัคซีนล่าช้าที่ flag ถึงผู้จัดการฟาร์ม/สัตวแพทย์ (overdue > grace_period_days)
  • ปุ่มลัด "บันทึกฉีดวัคซีน" และ "บันทึกการรักษา" ไปยังฟอร์มโดยตรง

ตารางวัคซีนมาตรฐาน (Vaccination Schedule Standards) Phase 1

จัดการแผนวัคซีนมาตรฐานต่อชนิดสัตว์ที่ใช้เทียบกับอายุจริง

  • ตารางรายการ: species, vaccine_name, age_days_due, is_booster
  • ตัวกรองตาม species
  • ฟอร์มสร้าง/แก้ไขมาตรฐานวัคซีนใหม่ (POST /livestock/vaccination-schedule-standards)

รายการวัคซีนที่ถึงกำหนด (Vaccination Due List) Phase 1

ไล่ดูสัตว์/ฝูงที่ถึงกำหนดฉีดวัคซีนตามตารางมาตรฐาน แยกล่าช้าออกจากถึงกำหนดปกติ

  • ตารางรายการ: animal_id/animal_group_id, vaccine_name, age_days_due เทียบ current_age_days, badge "ล่าช้า" ถ้าเกิน grace_period_days
  • ตัวกรอง: species, animal_group, สวิตช์ "แสดงเฉพาะที่ล่าช้า"
  • ปุ่ม "บันทึกฉีดวัคซีนนี้" ต่อแถว เปิดฟอร์มบันทึกฉีดวัคซีนแบบ pre-fill animal และ vaccine

บันทึกการฉีดวัคซีน (Vaccination Records) Phase 1

ดูและบันทึกประวัติการฉีดวัคซีนจริง

  • ตารางรายการ: vaccination_date, animal_id/animal_group_id, vaccine_item_id (ชื่อวัคซีน), administered_by
  • ตัวกรอง: ช่วงวันที่, สัตว์/ฝูง, ชนิดวัคซีน
  • ปุ่ม "บันทึกฉีดวัคซีนใหม่" — ฟอร์มเลือกสัตว์/ฝูง, vaccine_item_id จากคลัง, administered_by, vaccination_date พร้อมแจ้งตัดสต็อกอัตโนมัติ

บันทึกการรักษา/ใช้ยา (Treatment Records) Phase 1

บันทึกการรักษาโรค/ใช้ยา จุดสำคัญที่สุดด้านความปลอดภัยอาหารเพราะกำหนดระยะหยุดยา

  • ตารางรายการ: treatment_date, animal_id/animal_group_id, medication_item_id, diagnosis, dosage, withdrawal_days, safe_sale_date พร้อม badge ถ้ายังอยู่ในระยะหยุดยา
  • ตัวกรอง: ช่วงวันที่, สัตว์/ฝูง, diagnosis
  • ปุ่ม "บันทึกการรักษาใหม่" — ฟอร์มเลือก medication_item_id, กรอก diagnosis/dosage/treatment_date แล้วระบบคำนวณ safe_sale_date = treatment_date + withdrawal_days ให้อัตโนมัติ

ตรวจสอบสถานะระยะหยุดยา (Withdrawal Status Check) Phase 1

จุดตรวจสอบก่อนอนุมัติขาย/ชำแหละ ใช้เป็น gate ให้โมดูลคัดแยกและส่งขายเรียกดู

  • ช่องค้นหาสัตว์/ฝูง แสดงผล is_safe_to_sell พร้อม safe_sale_date ล่าสุดที่ยังไม่ผ่าน
  • รายการ treatment_record ที่เป็นสาเหตุให้ยังห้ามขาย พร้อมวันที่จะปลอดภัย
  • แสดงสถานะแบบ badge เขียว/แดง เชื่อมกับ GET /livestock/animals/{id}/withdrawal-status

ประวัติสุขภาพรายตัว/ฝูง (Animal/Group Health History) Phase 1

ดูภาพรวมประวัติสุขภาพทั้งหมดของสัตว์หรือฝูงหนึ่งตัวในหน้าเดียว

  • Timeline รวมเหตุการณ์จาก vaccination_record, treatment_record และ health_symptom_log เรียงตามวันที่
  • ตัวกรอง: ช่วงวันที่, ประเภทเหตุการณ์ (วัคซีน/รักษา/อาการ)
  • คลิกแต่ละเหตุการณ์ลิงก์กลับไปหน้ารายละเอียดที่เกี่ยวข้อง

บันทึกอาการเบื้องต้น (Health Symptom Log) Phase 2

บันทึกอาการผิดปกติที่พบก่อนตัดสินใจรักษา ใช้ติดตามและวิเคราะห์แนวโน้มโรค

  • ตารางรายการ: observed_date, animal_id/animal_group_id, symptom_description, severity (badge mild/moderate/severe)
  • ตัวกรอง: severity, ช่วงวันที่, สัตว์/ฝูง
  • ปุ่ม "แปลงเป็นการรักษา" สร้าง treatment_record ใหม่แล้วผูก treatment_record_id กลับมาที่รายการอาการนี้

รายงานอัตราการเจ็บป่วย (Morbidity Rate Report) Phase 2

ติดตามอัตราการเจ็บป่วยของฝูงเทียบเป็น KPI มาตรฐาน

  • ตัวเลือก animal_group และช่วงเวลาที่ต้องการดู
  • การ์ดแสดงค่า morbidity_rate_pct พร้อมกราฟแนวโน้มย้อนหลัง
  • ตารางรายการ treatment_record ที่ถูกนับในช่วงเวลานั้น

ส่งต่อสัตวแพทย์ภายนอก (External Vet Referral) Phase 2

ติดตามเคสที่ซับซ้อนเกินกำลังทีมภายในและถูกส่งต่อให้สัตวแพทย์ภายนอก

  • ตารางรายการเคสที่ส่งต่อ: อ้างอิง treatment_record/health_symptom_log ต้นเรื่อง, ชื่อ/ช่องทางติดต่อสัตวแพทย์ภายนอก, สถานะ (รอนัด/กำลังรักษา/ปิดเคส)
  • ตัวกรองตามสถานะเคส
  • ปุ่ม "ส่งต่อเคสใหม่" เลือกจากรายการอาการ/การรักษาที่รุนแรง (severity = severe)

วิเคราะห์แนวโน้มโรคระบาด (Disease Trend Analysis) Phase 3

ดูความสัมพันธ์ระหว่างความถี่การเจ็บป่วยกับสภาพแวดล้อมโรงเรือน

  • กราฟความถี่ health_symptom_log/treatment_record เทียบช่วงเวลา แยกตามโรงเรือน/พื้นที่
  • ตัวกรอง: โรงเรือน/พื้นที่, ช่วงเวลา, ชนิดสัตว์

พยากรณ์ความเสี่ยงโรค (Disease Risk Forecast) Phase 3

ประเมินความเสี่ยงล่วงหน้าของแต่ละฝูงจากข้อมูลสุขภาพย้อนหลัง

  • รายการ animal_group พร้อมคะแนนความเสี่ยงและปัจจัยหลักที่ใช้คำนวณ
  • คลิกเข้าดูรายละเอียดย้อนไปหน้าประวัติสุขภาพของฝูงนั้น
