โมดูลรายงานและแดชบอร์ด (Reports & Dashboard)

สเปกสำหรับเริ่มพัฒนาได้ทันที ครอบคลุมขอบเขตและจุดเชื่อมต่อกับโมดูลอื่น ฟังก์ชันหลักแยก MVP กับที่เพิ่มทีหลังได้ โครงสร้างฐานข้อมูล API หลักที่ต้องมี สิทธิ์การเข้าถึงตามบทบาท และสูตรคำนวณ/กฎทางธุรกิจ

ส่วนหนึ่งของ คู่มือ ERP สำหรับธุรกิจฟาร์ม อัปเดต 18 ก.ค. 2569
1. ขอบเขตและจุดเชื่อมต่อ (Scope & Integration) 2. ฟังก์ชันหลัก (Core Functions) 3. ฐานข้อมูล (Database) 4. API 5. สิทธิ์การเข้าถึง (Roles) 6. สูตรคำนวณ (Formulas) 7. หน้าจอที่ต้องมี (Screens)
Scope & Integration

1. ขอบเขตและจุดเชื่อมต่อ (Scope & Integration Points)

โมดูลนี้ต่างจากโมดูลอื่นตรงที่ไม่ได้เป็นเจ้าของข้อมูลธุรกรรมใด ๆ เอง แต่เป็นชั้นอ่านและรวมข้อมูล (aggregation layer) จากทุกโมดูลมาแสดงในที่เดียว ห้ามคำนวณตัวเลขทางธุรกิจซ้ำเอง ต้องดึงค่าที่โมดูลต้นทางคำนวณเสร็จแล้วเท่านั้น

อยู่ในขอบเขต

  • แดชบอร์ดภาพรวมฟาร์ม (Overview Dashboard)
  • รายงานต้นทุน-กำไรต่อฟาร์ม/แปลง/โรงเรือน/รอบผลิต
  • เปรียบเทียบรอบผลิตปัจจุบันกับย้อนหลัง
  • KPI สำหรับผู้บริหาร และการจัดวางแดชบอร์ดต่อบทบาท
  • Export รายงานและตั้งเวลาส่งอัตโนมัติ

อยู่นอกขอบเขต (อ่านอย่างเดียว ไม่คำนวณเอง)

  • ไม่สร้าง/แก้ไขรายการธุรกรรมใด ๆ — เป็น read-only จากทุกโมดูล
  • ไม่คำนวณ COGS/ค่าเสื่อม/ค่าแรงเอง — ใช้ค่าที่ บัญชีและการเงิน / คลังสินค้า / บุคลากรและแรงงาน / สินทรัพย์และเครื่องจักร คำนวณเสร็จแล้วเท่านั้น
  • ไม่เป็นเจ้าของ logic การแจ้งเตือนเชิงปฏิบัติการ (สต็อกใกล้หมด, PM ใกล้ถึง) — แค่รวมมาแสดงในที่เดียว
โมดูลต้นทางข้อมูลที่ดึงมาใช้ทำอะไรใน ReportsPhase
บัญชีและการเงินงบกำไรขาดทุน, ต้นทุนต่อศูนย์ต้นทุน, กระแสเงินสดแดชบอร์ดการเงินภาพรวมPhase 1
คลังสินค้า/สต็อกมูลค่าสต็อกคงเหลือ, รายการใกล้หมดอายุการ์ดสรุปสต็อกในแดชบอร์ดPhase 1
ขายและลูกค้ายอดขายรายเดือน, ประวัติราคากราฟยอดขายและ KPI ลูกค้าPhase 1
จัดซื้อPO ที่รอรับสินค้า, ต้นทุนการซื้อรายงานสถานะจัดซื้อPhase 1
บุคลากรและแรงงานต้นทุนแรงงานต่อศูนย์ต้นทุนรวมเข้าต้นทุนรวมต่อรอบผลิตPhase 1
สินทรัพย์และเครื่องจักรค่าเสื่อมราคา, ต้นทุนซ่อมบำรุงรวมเข้าต้นทุนรวมต่อรอบผลิตPhase 1
ปศุสัตว์ / พืชไร่-พืชสวนผลผลิต, FCR, พื้นที่เก็บเกี่ยวKPI การผลิตเทียบรอบก่อนหน้าPhase 2
Core Functions

2. ฟังก์ชันหลัก (Core Functions)

แยกชัดว่าอะไรต้องใช้งานได้ตั้งแต่วันแรก (MVP) และอะไรเพิ่มทีหลังได้โดยไม่กระทบการดูภาพรวมพื้นฐาน

MVP — ต้องมีวันแรก Phase 1

  • แดชบอร์ดภาพรวมฟาร์ม (กำไร-ขาดทุน, กระแสเงินสด, มูลค่าสต็อก, ยอดขาย)
  • รายงานต้นทุน-กำไรแยกตามฟาร์ม/แปลง/โรงเรือน/รอบผลิต
  • รวมต้นทุนจากทุกโมดูลเป็นต้นทุนรวมต่อรอบผลิต
  • ตัวกรองช่วงเวลาและพื้นที่/ศูนย์ต้นทุน
  • Export รายงานเป็น PDF/Excel
  • จำกัดสิทธิ์การเห็นข้อมูลตามบทบาท/พื้นที่

เพิ่มทีหลังได้

  • เปรียบเทียบรอบผลิตปัจจุบันกับย้อนหลังPhase 2
  • KPI ผู้บริหาร (FCR เฉลี่ย, ต้นทุนต่อหน่วย, growth rate)Phase 2
  • Notification center รวมการแจ้งเตือนจากทุกโมดูลPhase 2
  • ตั้งเวลาส่งรายงานอัตโนมัติทางอีเมลPhase 2
  • แดชบอร์ดเปรียบเทียบหลายฟาร์ม/นิติบุคคลPhase 3
  • Custom report builder ให้ผู้ใช้สร้างรายงานเองPhase 3
  • พยากรณ์แนวโน้มจากข้อมูลย้อนหลังPhase 3
Database

3. ฐานข้อมูล (Database)

โมดูลนี้ไม่มีตารางข้อมูลธุรกรรมของตัวเอง (อ่านจากตารางของโมดูลอื่นผ่าน view/query) มีแค่เอนทิตีสนับสนุนไว้ควบคุมว่ารายงานไหนมี ใครเห็นอะไร และตั้งเวลาส่งอย่างไร

report_definition Phase 1

นิยามรายงาน — กำหนดว่าระบบมีรายงานอะไรบ้าง แต่ละอันดึงข้อมูลจากไหน และต้องมีสิทธิ์ระดับไหนถึงจะดูได้

ความสัมพันธ์: ถูกอ้างอิงจาก dashboard_widget และ scheduled_report

ฟิลด์ชนิดข้อมูลเก็บอะไร
idเลขอ้างอิง/UUID (PK)รหัสประจำแถวนี้ ไม่ซ้ำกัน สร้างอัตโนมัติ
report_codeข้อความ (text)รหัสรายงานที่ใช้อ้างอิงภายในระบบ
nameข้อความ (text)ชื่อรายงาน เช่น "งบกำไรขาดทุนรายเดือน"
categoryตัวเลือกคงที่ (enum)หมวดรายงาน เลือกได้เฉพาะ: financial, inventory, sales, hr, asset, production
data_source_queryข้อความ (text)อ้างอิง view/query ที่ไปดึงข้อมูลจากตารางต้นทางในโมดูลอื่น
required_roleข้อความ/ตัวเลือกคงที่สิทธิ์ขั้นต่ำที่ต้องมีถึงจะเห็นรายงานนี้ได้

dashboard_widget Phase 1

องค์ประกอบในแดชบอร์ด — การ์ด/กราฟย่อยแต่ละชิ้นที่ประกอบกันเป็นแดชบอร์ด เช่น การ์ด "กำไรเดือนนี้" หรือกราฟ "ยอดขาย 6 เดือนย้อนหลัง"

ความสัมพันธ์: ผูกกับ report_definition (ดึงข้อมูลจากไหน) และถูกจัดวางผ่าน dashboard_layout

ฟิลด์ชนิดข้อมูลเก็บอะไร
idเลขอ้างอิง/UUID (PK)รหัสประจำแถวนี้ ไม่ซ้ำกัน สร้างอัตโนมัติ
widget_typeตัวเลือกคงที่ (enum)รูปแบบการแสดงผล เลือกได้เฉพาะ: kpi_card, line_chart, bar_chart, table
report_definition_idเลขอ้างอิง (FK → report_definition)widget นี้ดึงข้อมูลจากรายงานนิยามไหน
titleข้อความ (text)หัวข้อที่แสดงบน widget
refresh_interval_minutesตัวเลข (integer)ความถี่ในการดึงข้อมูลใหม่มาแสดง

dashboard_layout Phase 1

การจัดวางแดชบอร์ด — กำหนดว่าผู้ใช้แต่ละคน/บทบาทเห็นแดชบอร์ดหน้าตาแบบไหน widget ไหนอยู่ตำแหน่งไหน

ความสัมพันธ์: ผูกกับ user หรือ role และ dashboard_widget หลายตัว

ฟิลด์ชนิดข้อมูลเก็บอะไร
idเลขอ้างอิง/UUID (PK)รหัสประจำแถวนี้ ไม่ซ้ำกัน สร้างอัตโนมัติ
user_id / roleเลขอ้างอิง (FK) / ตัวเลือกคงที่เลย์เอาต์นี้เป็นของผู้ใช้คนไหน หรือบทบาทไหน
widget_idเลขอ้างอิง (FK → dashboard_widget)แสดง widget ตัวไหน
position_orderตัวเลข (integer)ลำดับตำแหน่งที่แสดงบนหน้าแดชบอร์ด

scheduled_report Phase 2

การตั้งเวลาส่งรายงาน — ตั้งค่าส่งรายงานที่กำหนดไว้ทางอีเมลตามรอบเวลาอัตโนมัติ

ความสัมพันธ์: ผูกกับ report_definition ที่จะส่ง

ฟิลด์ชนิดข้อมูลเก็บอะไร
idเลขอ้างอิง/UUID (PK)รหัสประจำแถวนี้ ไม่ซ้ำกัน สร้างอัตโนมัติ
report_definition_idเลขอ้างอิง (FK → report_definition)ส่งรายงานตัวไหน
recipient_emailsข้อความ (list)รายชื่ออีเมลผู้รับ
schedule_cronข้อความ (text)รูปแบบเวลาที่ส่ง เช่น ทุกวันจันทร์ 8:00 น.
formatตัวเลือกคงที่ (enum)รูปแบบไฟล์ เลือกได้เฉพาะ: pdf, excel
last_sent_atวันที่/เวลา (ว่างได้)ครั้งล่าสุดที่ส่งสำเร็จ

notification Phase 2

การแจ้งเตือนรวม — ศูนย์รวมการแจ้งเตือนจากทุกโมดูล เช่น สต็อกใกล้หมด PM ใกล้ถึงกำหนด ใบแจ้งหนี้เลยกำหนด มาแสดงในที่เดียวโดยไม่ต้องเข้าหลายโมดูล

ความสัมพันธ์: อ้างอิง source_module และรายการต้นทางที่ทำให้เกิดการแจ้งเตือนนั้น (ไม่ใช่เจ้าของ logic การเตือน แค่รวมมาแสดง)

ฟิลด์ชนิดข้อมูลเก็บอะไร
idเลขอ้างอิง/UUID (PK)รหัสประจำแถวนี้ ไม่ซ้ำกัน สร้างอัตโนมัติ
source_moduleตัวเลือกคงที่ (enum)มาจากโมดูลไหน เลือกได้เฉพาะ: inventory, asset, accounting, sales, procurement
source_ref_idข้อความ (text)เลขอ้างอิงรายการต้นทางที่ทำให้เกิดการแจ้งเตือนนี้
severityตัวเลือกคงที่ (enum)ระดับความสำคัญ เลือกได้เฉพาะ: info, warning, critical
messageข้อความ (text)ข้อความแจ้งเตือนที่แสดงให้ผู้ใช้เห็น
is_readจริง/เท็จ (boolean)ผู้ใช้เปิดอ่านแล้วหรือยัง
API

4. API

Endpoint หลักที่ต้องมีสำหรับ MVP (Phase 1) และที่ตามมาใน Phase 2

MethodEndpointคำอธิบายPhase
GET/reports/dashboard/overviewข้อมูลแดชบอร์ดภาพรวมฟาร์ม — รวมข้อมูลจาก dashboard_layout, dashboard_widget ของผู้ใช้/บทบาทปัจจุบันเพื่อรู้ว่าต้องแสดง widget ไหน แต่ละ widget ดึงตัวเลขจริงตาม report_definition ที่ผูกไว้ (เช่น กำไรขาดทุน/กระแสเงินสดจากบัญชีและการเงิน, มูลค่าสต็อกจากคลังสินค้า/สต็อก, ยอดขายจากขายและลูกค้า)1
GET/reports/profit-lossงบกำไรขาดทุน (filter: cost_center_id, period) — proxy เรียก GET /accounting/reports/profit-loss ตรงๆ ไม่คำนวณซ้ำเอง เพื่อไม่ให้ตัวเลขเพี้ยนจากบัญชี (single source of truth)1
GET/reports/cost-breakdownต้นทุนรวมแยกตามแหล่งที่มา (วัตถุดิบ/แรงงาน/ค่าเสื่อม) ต่อศูนย์ต้นทุน — รวมข้อมูลจาก accounting.cogs_from_journal_entry() กับ journal_entry_line อื่นๆ ของศูนย์ต้นทุนนั้น ไม่สร้างตัวเลขต้นทุนขึ้นใหม่เอง1
GET/reports/definitionsดึงรายชื่อรายงานที่ผู้ใช้ปัจจุบันมีสิทธิ์ดู — ดึงจาก report_definition (filter ตาม required_role เทียบกับสิทธิ์ผู้ใช้ปัจจุบัน)1
POST/reports/{report_code}/exportส่งออกรายงานเป็น PDF/Excel — ดึงจาก report_definition (data_source_query) เพื่อรู้ว่าต้อง query ข้อมูลจากตารางต้นทางใด แล้ว render เป็นไฟล์ (ยังไม่มี entity เก็บ log การ export ในสเปกนี้ ต้องเพิ่มถ้าต้องการ audit trail)1
GET/reports/dashboard-layoutsดึงการจัดวางแดชบอร์ดของผู้ใช้/บทบาทปัจจุบัน — ดึงจาก dashboard_layout, dashboard_widget1
POST/reports/dashboard-layoutsบันทึกการจัดวาง widget ใหม่ — บันทึกลง dashboard_layout (อ้างอิง widget_id จาก dashboard_widget)1
GET/reports/kpisดึงค่า KPI ตาม metric ที่ระบุ (filter: metric, period) — อ้างอิง report_definition ว่า metric นั้นดึงจากไหน ตัวเลขจริงมาจากโมดูลต้นทาง เช่น FCR จากโมดูลปศุสัตว์ / พืชไร่-พืชสวน และต้นทุนต่อหน่วยจากสูตร total_cost() ในหัวข้อ 6 (ยังไม่มี entity เก็บค่า KPI สำเร็จรูปในสเปกนี้ คำนวณสดทุกครั้งที่เรียก)2
GET/reports/comparison/period-over-periodเปรียบเทียบตัวเลขรอบปัจจุบันกับรอบก่อนหน้า — ดึงข้อมูลงวดปัจจุบันและงวดก่อนหน้าตาม report_definition ที่ระบุ แล้วคำนวณ variance ตามสูตรในหัวข้อ 6 (ไม่มี entity เก็บผลเปรียบเทียบไว้ล่วงหน้า คำนวณสดทุกครั้ง)2
GET/reports/notificationsดึงการแจ้งเตือนรวมจากทุกโมดูล — ดึงจาก notification2
POST/reports/notifications/{id}/mark-readทำเครื่องหมายว่าอ่านแล้ว — บันทึกลง notification (อัปเดต is_read)2
GET/reports/scheduled-reportsดึงรายการตั้งเวลาส่งรายงาน — ดึงจาก scheduled_report2
POST/reports/scheduled-reportsตั้งเวลาส่งรายงานใหม่ — บันทึกลง scheduled_report (อ้างอิง report_definition_id จาก report_definition)2
Roles & Permissions

5. สิทธิ์การเข้าถึง (Roles & Permissions)

ใครทำอะไรได้บ้างในโมดูลนี้ — ใช้ออกแบบ RBAC ได้ตรง ๆ

เจ้าของฟาร์ม / ผู้บริหาร
เห็นทุกรายงานทุกพื้นที่ ตั้งเวลาส่งรายงานอัตโนมัติ จัดการนิยามรายงาน/แดชบอร์ด
ผู้จัดการฟาร์ม/แปลง
เห็นเฉพาะรายงานของศูนย์ต้นทุนที่ตนดูแล
พนักงานบัญชี
เห็นรายงานการเงินทั้งหมด แต่ไม่เห็นรายงานเงินเดือนรายบุคคลที่เป็นข้อมูลอ่อนไหว
เจ้าหน้าที่ทั่วไป
เห็นเฉพาะแดชบอร์ดสรุปพื้นฐานที่ผู้บริหารแชร์ให้ ไม่เห็นรายละเอียดการเงินเชิงลึก

Business Rules & Formulas

6. สูตรคำนวณและกฎทางธุรกิจ (Business Rules & Formulas)

ตรรกะที่ dev ต้อง implement จริงเบื้องหลัง entity/endpoint ด้านบน — เน้นกฎการรวม/กรองข้อมูล ไม่ใช่การคำนวณตัวเลขทางธุรกิจใหม่

กฎการกรองข้อมูลตามสิทธิ์ (Data Scoping Rule)

Phase 1

ทุก query ของรายงานต้องผ่านกฎนี้ก่อนเสมอ ไม่ว่าจะเรียกจาก endpoint ไหน

effective_cost_centers(user) =
  role IN (owner, accountant)
    -> ALL cost_centers
  role = farm_manager
    -> cost_centers ที่เป็นลูกของ
       user.assigned_cost_center_id เท่านั้น

ทุก query ต้อง filter:
  WHERE cost_center_id IN effective_cost_centers(user)

การรวมต้นทุนข้ามโมดูล (Cross-Module Cost Rollup)

Phase 1

กฎสำคัญที่สุดของโมดูลนี้ — ห้ามคำนวณต้นทุนย่อยเอง ให้รวมค่าที่คำนวณเสร็จแล้วเท่านั้น

total_cost(cost_center, period) =
    accounting.cogs_from_journal_entry(cost_center, period)
  + hr.payroll_run_line.gross_pay(cost_center, period)
  + asset.depreciation_entry.depreciation_amount(cost_center, period)

ห้าม re-calculate COGS/ค่าเสื่อม/ค่าแรงเองในโมดูลนี้
ให้ query ค่าที่โมดูลต้นทางคำนวณ+โพสต์เสร็จแล้วเท่านั้น

เปรียบเทียบรอบต่อรอบ (Period-over-Period Comparison)

Phase 2

ใช้ period ก่อนหน้าแบบเดียวกันของ cost_center เดียวกันเสมอ

variance = current_period_value - previous_period_value
variance_pct = variance / previous_period_value × 100

previous_period = เดือนก่อนหน้า
  หรือรอบผลิตก่อนหน้าของ cost_center เดียวกัน
  (ไม่ใช่แค่ลบเดือนปฏิทิน ถ้า cost_center เป็นแบบ batch)

ความสดของข้อมูล (Data Freshness)

Phase 1

กำหนดว่าเมื่อไหร่ต้องดึงข้อมูลใหม่มาแสดงใน widget

widget cache invalidated เมื่อ:
  เวลาที่ผ่านไป >= refresh_interval_minutes
  หรือ
  มี event ใหม่จากโมดูลต้นทาง
  (เช่น journal_entry ใหม่ถูก post เข้าระบบ)

ระดับความสำคัญของการแจ้งเตือนรวม (Notification Severity)

Phase 2

ใช้จัดลำดับว่าอะไรควรเด่นสุดใน notification center

info     = แจ้งเตือนทั่วไป (เช่น รายงานพร้อมดูแล้ว)
warning  = ใกล้ถึง threshold
           (สต็อกใกล้หมด, PM ใกล้ถึงกำหนด)
critical = เลยกำหนดแล้วจริง
           (ใบแจ้งหนี้เกิน 90 วัน, สต็อกหมดจริง)

เรียงแสดงผล: critical ก่อน -> warning -> info
Screens

7. หน้าจอที่ต้องมี (Screens/Pages)

รายชื่อหน้าจอที่ต้องมีจริงในโมดูลนี้ พร้อมส่วนประกอบหลักของแต่ละหน้า — ใช้เป็น checklist ออกแบบ UI ต่อได้ตรง ๆ ไม่ต้องนั่งไล่จากฟังก์ชัน/entity เอง

แดชบอร์ดภาพรวมฟาร์ม (Overview Dashboard) Phase 1

หน้าแรกที่ทุกบทบาทเปิดดู ประกอบจาก dashboard_widget ที่จัดวางไว้ตาม dashboard_layout ของผู้ใช้/บทบาทนั้น

  • เรนเดอร์ widget ตามลำดับ position_order ของ dashboard_layout (ดึงจาก GET /reports/dashboard-layouts แล้ว fetch ข้อมูลตาม widget_type: kpi_card, line_chart, bar_chart, table)
  • การ์ดสรุป: กำไร-ขาดทุน, กระแสเงินสด, มูลค่าสต็อก, ยอดขาย — ข้อมูลมาจาก GET /reports/dashboard/overview
  • ตัวกรองช่วงวันที่/ศูนย์ต้นทุน ใช้ร่วมกับทุก widget บนหน้านี้
  • badge บอกความสดของข้อมูลต่อ widget ตาม refresh_interval_minutes (cache invalidate ตามกฎ Data Freshness)

งบกำไรขาดทุน (Profit & Loss Report) Phase 1

ดูงบกำไรขาดทุนตามศูนย์ต้นทุน/รอบเวลา — เป็นแค่หน้าแสดงผลที่ proxy เรียก accounting ตรง ๆ ไม่คำนวณเลขเอง

  • ตารางงบกำไรขาดทุนจาก GET /reports/profit-loss (filter: cost_center_id, period)
  • ป้าย "ข้อมูลจากบัญชีและการเงิน (single source of truth)" เตือนว่าหน้านี้เป็น proxy อย่างเดียว ไม่มีการคำนวณซ้ำ
  • ปุ่ม "ส่งออก" เรียก POST /reports/{report_code}/export เลือกรูปแบบ PDF/Excel

ต้นทุนแยกตามแหล่งที่มา (Cost Breakdown Report) Phase 1

ดูต้นทุนรวมต่อศูนย์ต้นทุนแยกตามวัตถุดิบ/แรงงาน/ค่าเสื่อม — รวมค่าที่โมดูลต้นทางคำนวณเสร็จแล้วเท่านั้น

  • ตารางต้นทุนจาก GET /reports/cost-breakdown แยก 3 แถว: accounting.cogs_from_journal_entry, hr.payroll_run_line.gross_pay, asset.depreciation_entry.depreciation_amount ตามสูตร total_cost(cost_center, period)
  • ตัวกรอง: cost_center_id, period (ใช้ effective_cost_centers(user) กรองสิทธิ์ก่อนเสมอ)
  • ปุ่ม "ส่งออก" (PDF/Excel) และปุ่ม "เทียบรอบก่อนหน้า" เชื่อมไปหน้าเปรียบเทียบรอบต่อรอบ

คลังรายงาน (Report Catalog) Phase 1

รายชื่อรายงานทั้งหมดที่ผู้ใช้ปัจจุบันมีสิทธิ์ดู พร้อมช่องทางเปิด/ส่งออก

  • ตารางรายการ report_definition: report_code, name, category (financial/inventory/sales/hr/asset/production) — ดึงจาก GET /reports/definitions ซึ่งกรอง required_role ให้แล้ว
  • ตัวกรองตาม category
  • ปุ่ม "เปิดดู" ไปหน้ารายงานนั้น และปุ่ม "ส่งออก" เรียก POST /reports/{report_code}/export

ห้องสมุด Widget (Widget Library) Phase 1

จัดการนิยาม widget ที่ใช้ประกอบแดชบอร์ด — เฉพาะเจ้าของ/ผู้บริหารที่จัดการนิยามรายงาน/แดชบอร์ดได้

  • ตารางรายการ dashboard_widget: widget_type, title, report_definition_id ที่ผูกอยู่, refresh_interval_minutes
  • ฟอร์มสร้าง/แก้ไข widget: เลือก widget_type (kpi_card/line_chart/bar_chart/table), เลือก report_definition ที่ดึงข้อมูล, ตั้ง title และ refresh_interval_minutes

จัดวางแดชบอร์ด (Dashboard Layout Editor) Phase 1

จัดตำแหน่ง widget บนแดชบอร์ดของตนเอง หรือของบทบาทที่ตนจัดการได้

  • พื้นที่ลาก-วาง widget ที่เลือกจากห้องสมุด Widget แล้วเรียงเป็น position_order
  • โหลดเลย์เอาต์เดิมจาก GET /reports/dashboard-layouts ตาม user_id/role และบันทึกใหม่ด้วย POST /reports/dashboard-layouts
  • ปุ่ม "เพิ่ม widget" / "ลบ widget" ออกจากเลย์เอาต์ปัจจุบัน

KPI ผู้บริหาร (Executive KPI Dashboard) Phase 2

ดูตัวชี้วัดสรุประดับผู้บริหาร เช่น FCR เฉลี่ย ต้นทุนต่อหน่วย growth rate

  • การ์ด KPI จาก GET /reports/kpis (filter: metric, period)
  • ตัวเลือก metric ให้สลับดูได้ทีละตัวหรือหลายตัวพร้อมกัน

เปรียบเทียบรอบต่อรอบ (Period-over-Period Comparison) Phase 2

เทียบตัวเลขรอบปัจจุบันกับรอบก่อนหน้าของศูนย์ต้นทุนเดียวกัน

  • ตารางเทียบ current_period_value vs previous_period_value พร้อม variance และ variance_pct จาก GET /reports/comparison/period-over-period
  • ตัวกรอง cost_center_id + period ปัจจุบัน (ระบบเลือก previous_period ให้ตามกฎ — เดือนก่อนหน้า หรือรอบผลิตก่อนหน้าถ้าเป็น cost_center แบบ batch)
  • ไฮไลต์แถวที่ variance_pct ผิดปกติ (บวก/ลบมาก) ด้วยสี

ศูนย์การแจ้งเตือน (Notification Center) Phase 2

รวมการแจ้งเตือนจากทุกโมดูลไว้ที่เดียว ไม่ใช่เจ้าของ logic การเตือน แค่รวมมาแสดง

  • รายการจาก GET /reports/notifications: source_module, message, severity, is_read เรียงลำดับ critical -> warning -> info
  • ตัวกรองตาม source_module (inventory/asset/accounting/sales/procurement) และ severity
  • ปุ่ม "ทำเครื่องหมายว่าอ่านแล้ว" เรียก POST /reports/notifications/{id}/mark-read และคลิกแถวลิงก์ไปยัง source_ref_id ในโมดูลต้นทาง

ตั้งเวลาส่งรายงาน (Scheduled Reports) Phase 2

ตั้งค่าส่งรายงานที่เลือกไว้ทางอีเมลตามรอบเวลาอัตโนมัติ — เฉพาะเจ้าของ/ผู้บริหาร

  • ตารางรายการ scheduled_report: report_definition ที่ส่ง, recipient_emails, schedule_cron, format (pdf/excel), last_sent_at — จาก GET /reports/scheduled-reports
  • ฟอร์มตั้งเวลาใหม่: เลือกรายงานจาก report_definition, กรอก recipient_emails, ตั้ง schedule_cron, เลือก format แล้วบันทึกด้วย POST /reports/scheduled-reports

เปรียบเทียบหลายฟาร์ม/นิติบุคคล (Multi-Farm Comparison) Phase 3

เทียบผลประกอบการข้ามฟาร์ม/นิติบุคคลในองค์กรเดียวกัน สำหรับเจ้าของ/ผู้บริหารที่ดูแลหลายฟาร์ม

  • ตารางเทียบ total_cost และงบกำไรขาดทุนรายฟาร์ม โดยรวม cost_center ระดับบนสุดของแต่ละฟาร์มเข้าด้วยกัน (ต่อยอดจาก /reports/profit-loss และ /reports/cost-breakdown เดิม)
  • ตัวกรองเลือกฟาร์ม/นิติบุคคลที่จะเทียบ + ช่วงเวลา

ตัวสร้างรายงานเอง (Custom Report Builder) Phase 3

ให้ผู้ใช้สร้างนิยามรายงานของตัวเองได้จาก data source ที่ระบบอนุญาต

  • ฟอร์มสร้าง report_definition ใหม่: report_code, name, category, เลือก data_source_query จาก view ที่อนุญาตตาม required_role ของผู้ใช้
  • พรีวิวผลลัพธ์ก่อนบันทึก แล้วเพิ่มเข้าคลังรายงานให้เลือกใช้เป็น widget หรือส่งออกได้เหมือนรายงานอื่น
เอกสารนี้เป็นสเปกเริ่มพัฒนาโมดูล "รายงานและแดชบอร์ด" ควรรีวิวโครงสร้างฐานข้อมูลกับทีม dev จริงก่อนเริ่ม implement ← กลับไปภาพรวม ERP ฟาร์ม
