โมดูลแผนการเพาะปลูก (Planting Plan)

สเปกสำหรับเริ่มพัฒนาได้ทันที ครอบคลุมขอบเขตและจุดเชื่อมต่อกับโมดูลอื่น ฟังก์ชันหลักแยก MVP กับที่เพิ่มทีหลังได้ โครงสร้างฐานข้อมูล API หลักที่ต้องมี สิทธิ์การเข้าถึงตามบทบาท และสูตรคำนวณ/กฎทางธุรกิจ

ส่วนหนึ่งของ คู่มือ ERP สำหรับธุรกิจฟาร์ม อัปเดต 18 ก.ค. 2569
1. ขอบเขตและจุดเชื่อมต่อ (Scope & Integration) 2. ฟังก์ชันหลัก (Core Functions) 3. ฐานข้อมูล (Database) 4. API 5. สิทธิ์การเข้าถึง (Roles) 6. สูตรคำนวณ (Formulas) 7. หน้าจอที่ต้องมี (Screens)
Scope & Integration

1. ขอบเขตและจุดเชื่อมต่อ (Scope & Integration Points)

โมดูลนี้ใช้ field_id/zone_id และประวัติการใช้ที่ดินจากโมดูล "ผังแปลงและที่ดิน" มาวางแผนปลูกแต่ละรอบ แล้วส่งต่อกำหนดการให้โมดูลปฏิบัติงานจริงทำตาม

อยู่ในขอบเขต

  • ปฏิทินฤดูกาลเพาะปลูก (Planting Calendar)
  • แผนพันธุ์พืชต่อแปลง/โซนต่อรอบ
  • ตรวจสอบและแนะนำการหมุนเวียนพืช (Crop Rotation)
  • ประมาณการผลผลิตและต้นทุนล่วงหน้า
  • การสร้างรอบผลิต/batch ต่อพืชแต่ละรอบ

อยู่นอกขอบเขต (รับ/ส่งข้อมูลกับโมดูลอื่น)

  • ขอบเขตแปลง/ประวัติการใช้ที่ดิน — รับจาก ผังแปลงและที่ดิน
  • การสร้างศูนย์ต้นทุนต่อรอบปลูก — ส่งต่อให้ บัญชีและการเงิน สร้าง cost_center ประเภท batch
  • การให้น้ำ/ปุ๋ย/สารเคมีจริงตามแผน — ส่งต่อให้ การให้น้ำ ปุ๋ย และยา ปฏิบัติงาน
  • การเก็บเกี่ยวจริง — รับผลจาก การเก็บเกี่ยว มาปิดรอบแผน
  • เมล็ดพันธุ์ที่ต้องใช้ — แจ้งไปที่ คลังสินค้า/สต็อก หรือ จัดซื้อ ถ้าต้องซื้อเพิ่ม
โมดูลที่เกี่ยวข้องเหตุการณ์สิ่งที่แผนการเพาะปลูกต้องทำPhase
ผังแปลงและที่ดินมีแปลง/โซนพร้อมปลูก พร้อมประวัติการใช้ที่ดินดึงมาใช้เลือกแปลงและตรวจสอบหมุนเวียนพืชPhase 1
แผนการเพาะปลูก (ตัวเอง) → บัญชีและการเงินอนุมัติแผนปลูกใหม่สร้าง cost_center ประเภท batch ผูกกับรอบนี้Phase 1
แผนการเพาะปลูก (ตัวเอง) → การให้น้ำ ปุ๋ย และยาแผนปลูกได้รับอนุมัติแล้วส่งกำหนดการให้ปฏิบัติงานจริงทำตามPhase 1
แผนการเพาะปลูก (ตัวเอง) → คลังสินค้า/สต็อกต้องใช้เมล็ดพันธุ์ตามแผนแจ้งจองสต็อกเมล็ดพันธุ์ที่ต้องใช้Phase 1
การเก็บเกี่ยวเก็บเกี่ยวจริงเสร็จสิ้นปิดรอบแผนและบันทึกผลจริงเทียบกับประมาณการPhase 1
สภาพอากาศพยากรณ์ฝน/แล้งช่วงที่วางแผนปลูกปรับคำแนะนำวันเริ่มปลูกให้เหมาะสมPhase 2
Core Functions

2. ฟังก์ชันหลัก (Core Functions)

แยกชัดว่าอะไรต้องใช้งานได้ตั้งแต่วันแรก (MVP) และอะไรเพิ่มทีหลังได้โดยไม่กระทบการวางแผนปลูกพื้นฐาน

MVP — ต้องมีวันแรก Phase 1

  • สร้างแผนการเพาะปลูกต่อแปลง/โซนต่อรอบ (เลือกพันธุ์ วันปลูก วันเก็บเกี่ยว)
  • ตรวจสอบคำเตือนหมุนเวียนพืชจากประวัติที่ดิน
  • ประมาณการผลผลิตและต้นทุนล่วงหน้าตามพันธุ์และพื้นที่
  • สร้างศูนย์ต้นทุน (batch) อัตโนมัติเมื่ออนุมัติแผน
  • ดูปฏิทินฤดูกาลเพาะปลูกรวมทุกแปลง
  • ปิดรอบแผนเมื่อเก็บเกี่ยวเสร็จ พร้อมเทียบผลจริงกับประมาณการ

เพิ่มทีหลังได้

  • แนะนำวันเริ่มปลูกที่เหมาะสมจากพยากรณ์อากาศPhase 2
  • แผนหมุนเวียนพืชระยะยาวหลายรอบล่วงหน้าPhase 2
  • จองสต็อกเมล็ดพันธุ์/แจ้งจัดซื้อล่วงหน้าอัตโนมัติตามแผนPhase 2
  • เปรียบเทียบพันธุ์พืชหลายตัวเลือกจากข้อมูลย้อนหลังPhase 3
  • พยากรณ์ผลตอบแทนสุทธิต่อพันธุ์พืชก่อนตัดสินใจปลูกจริงPhase 3
Database

3. ฐานข้อมูล (Database)

แต่ละเอนทิตีคือ 1 ตารางในฐานข้อมูล พร้อมคำอธิบายว่าแทนอะไรในโลกจริง และแต่ละฟิลด์เก็บอะไร ชนิดข้อมูลแบบไหน

crop_variety Phase 1

พันธุ์พืช — ทะเบียนพันธุ์พืชที่ฟาร์มปลูก พร้อมข้อมูลอ้างอิงมาตรฐาน เช่น ระยะเวลาปลูกถึงเก็บเกี่ยว และผลผลิตเฉลี่ยต่อไร่

ความสัมพันธ์: ถูกอ้างอิงจาก planting_plan ทุกแผนที่เลือกปลูกพันธุ์นี้

ฟิลด์ชนิดข้อมูลเก็บอะไร
idเลขอ้างอิง/UUID (PK)รหัสประจำแถวนี้ ไม่ซ้ำกัน สร้างอัตโนมัติ
variety_codeข้อความ (text)รหัสพันธุ์พืชที่ใช้อ้างอิงภายในระบบ
nameข้อความ (text)ชื่อพันธุ์ เช่น "ข้าวโพดเลี้ยงสัตว์ พันธุ์ 999"
crop_familyข้อความ/ตัวเลือกคงที่ (enum)ตระกูลพืช ใช้ตรวจสอบการหมุนเวียนพืช เช่น ตระกูลหญ้า/ธัญพืช, ตระกูลถั่ว
days_to_harvestตัวเลข (integer)จำนวนวันโดยประมาณจากวันปลูกถึงวันเก็บเกี่ยว
expected_yield_per_raiตัวเลข (decimal)ผลผลิตเฉลี่ยที่คาดหวังต่อไร่ ใช้ตั้งต้นประมาณการ

planting_plan Phase 1

แผนการเพาะปลูก — แผนปลูกพืชหนึ่งรอบในแปลง/โซนหนึ่ง ตั้งแต่วางแผนจนถึงปิดรอบเมื่อเก็บเกี่ยวเสร็จ

ความสัมพันธ์: ผูกกับ field/field_zone (จากโมดูลผังแปลง), crop_variety และสร้าง cost_center (batch) ในโมดูลบัญชีเมื่ออนุมัติ

ฟิลด์ชนิดข้อมูลเก็บอะไร
idเลขอ้างอิง/UUID (PK)รหัสประจำแถวนี้ ไม่ซ้ำกัน สร้างอัตโนมัติ
field_id / field_zone_idเลขอ้างอิง (FK)ปลูกในแปลงหรือโซนไหน
crop_variety_idเลขอ้างอิง (FK → crop_variety)ปลูกพันธุ์อะไร
planned_planting_dateวันที่ (date)วันที่วางแผนจะเริ่มปลูก
expected_harvest_dateวันที่ (date)วันที่คาดว่าจะเก็บเกี่ยว คำนวณจากวันปลูก + days_to_harvest
cost_center_idเลขอ้างอิง (FK → cost_center)ศูนย์ต้นทุน (batch) ที่สร้างขึ้นเมื่อแผนนี้ได้รับอนุมัติ
statusตัวเลือกคงที่ (enum)สถานะ เลือกได้เฉพาะ: draft, approved, in_progress, harvested, cancelled

yield_estimate Phase 1

การประมาณการผลผลิตและต้นทุน — ตัวเลขประมาณการที่คำนวณตอนวางแผน ใช้เทียบกับผลจริงหลังเก็บเกี่ยวเสร็จ

ความสัมพันธ์: ผูกกับ planting_plan หนึ่งแผนต่อหนึ่งชุดประมาณการ

ฟิลด์ชนิดข้อมูลเก็บอะไร
idเลขอ้างอิง/UUID (PK)รหัสประจำแถวนี้ ไม่ซ้ำกัน สร้างอัตโนมัติ
planting_plan_idเลขอ้างอิง (FK → planting_plan)ประมาณการนี้เป็นของแผนไหน
estimated_yieldตัวเลข (decimal)ผลผลิตที่คาดว่าจะได้ทั้งรอบ
estimated_costตัวเลข (decimal)ต้นทุนที่คาดว่าจะเกิดขึ้นทั้งรอบ
actual_yield / actual_costตัวเลข (decimal, ว่างได้)ผลผลิตและต้นทุนจริงที่เกิดขึ้น กรอกหลังปิดรอบ

crop_rotation_rule Phase 1

กฎการหมุนเวียนพืช — กำหนดว่าแปลง/โซนหนึ่งไม่ควรปลูกพืชตระกูลเดียวกันซ้ำกี่รอบติดต่อกัน เพื่อลดความเสี่ยงโรค/ศัตรูพืชสะสมในดิน

ความสัมพันธ์: ใช้ตรวจสอบร่วมกับ land_use_history จากโมดูลผังแปลงตอนสร้างแผนใหม่

ฟิลด์ชนิดข้อมูลเก็บอะไร
idเลขอ้างอิง/UUID (PK)รหัสประจำแถวนี้ ไม่ซ้ำกัน สร้างอัตโนมัติ
crop_familyข้อความ/ตัวเลือกคงที่ (enum)ตระกูลพืชที่กฎนี้ใช้ควบคุม
min_gap_cyclesตัวเลข (integer)ต้องเว้นกี่รอบก่อนปลูกพืชตระกูลเดิมซ้ำในแปลง/โซนเดียวกัน

Business Rules & Formulas

6. สูตรคำนวณและกฎทางธุรกิจ (Business Rules & Formulas)

ตรรกะที่ dev ต้อง implement จริงเบื้องหลัง entity/endpoint ด้านบน

คำนวณวันที่คาดว่าจะเก็บเกี่ยว

Phase 1

คำนวณอัตโนมัติทันทีที่เลือกพันธุ์พืชและวันปลูก

expected_harvest_date =
  planned_planting_date + crop_variety.days_to_harvest

ประมาณการผลผลิตและต้นทุน

Phase 1

ตั้งต้นจากพื้นที่จริงของแปลง/โซนคูณค่ามาตรฐานของพันธุ์นั้น

estimated_yield =
  field_or_zone.area_rai × crop_variety.expected_yield_per_rai

estimated_cost =
  standard_cost_per_rai(crop_variety) × field_or_zone.area_rai
  (standard_cost_per_rai อ้างอิงจากรอบก่อนหน้าของพันธุ์เดียวกัน
   หรือค่าเริ่มต้นที่ตั้งไว้ถ้ายังไม่มีประวัติ)

ตรวจสอบกฎการหมุนเวียนพืช

Phase 1

ตรวจก่อนอนุมัติแผนทุกครั้ง ไม่บล็อกอัตโนมัติ เว้นแต่ตั้ง policy ให้บล็อก

recent_cycles =
  land_use_history ของ field/zone เดียวกัน
  เรียงล่าสุด จำนวน min_gap_cycles รอบ (ตาม crop_rotation_rule)

ถ้ามี cycle ใดใน recent_cycles ที่ crop_family
  ตรงกับพันธุ์ที่จะปลูกใหม่
  -> flag เตือนความเสี่ยง

ส่วนต่างประมาณการกับผลจริง

Phase 1

คำนวณตอนปิดรอบแผน ใช้ปรับปรุง standard_cost_per_rai ของรอบถัดไป

yield_variance_pct =
  (actual_yield - estimated_yield) / estimated_yield × 100

cost_variance_pct =
  (actual_cost - estimated_cost) / estimated_cost × 100

การเปลี่ยนสถานะแผนตามวงจร

Phase 1

กำหนดลำดับสถานะที่ถูกต้องของแผน ป้องกันการข้ามขั้นตอนผิดลำดับ

draft -> approved
  (เมื่ออนุมัติ สร้าง cost_center อัตโนมัติ)

approved -> in_progress
  (เมื่อถึง planned_planting_date จริง)

in_progress -> harvested
  (เมื่อมีบันทึกเก็บเกี่ยวจริงจากโมดูลเก็บเกี่ยว)

ทุกสถานะ ยกเว้น harvested -> cancelled ได้
Screens

7. หน้าจอที่ต้องมี (Screens/Pages)

รายชื่อหน้าจอที่ต้องมีจริงในโมดูลนี้ พร้อมส่วนประกอบหลักของแต่ละหน้า — ใช้เป็น checklist ออกแบบ UI ต่อได้ตรง ๆ ไม่ต้องนั่งไล่จากฟังก์ชัน/entity เอง

ปฏิทินฤดูกาลเพาะปลูก (Planting Calendar) Phase 1

มุมมองรวมทุกแผนปลูกทุกแปลง ใช้เป็นหน้าแรกดูภาพรวมฤดูกาล

  • ปฏิทิน/ไทม์ไลน์แสดงช่วง planned_planting_date ถึง expected_harvest_date ของทุก planting_plan
  • ตัวกรอง: field_id, ช่วงวันที่, status
  • คลิกแถบแผนเพื่อเปิดหน้ารายละเอียดแผน (ดึงข้อมูลจาก GET /crop/reports/planting-calendar)

รายการแผนการเพาะปลูก (Planting Plans List) Phase 1

ค้นและดูแผนปลูกทั้งหมดแบบตาราง

  • ตารางรายการ: field_id/field_zone_id, ชื่อพันธุ์ (crop_variety), planned_planting_date, expected_harvest_date, status พร้อม badge สี
  • ตัวกรอง: field_id, status, date_from/date_to (ตรงกับพารามิเตอร์ของ GET /crop/planting-plans)
  • ปุ่ม "สร้างแผนใหม่" เปิดฟอร์มสร้างแผน คลิกแถวเข้าหน้ารายละเอียด

สร้าง/แก้ไขแผนการเพาะปลูก (Planting Plan Form) Phase 1

ฟอร์มวางแผนปลูกใหม่หนึ่งรอบในแปลง/โซนหนึ่ง

  • เลือก field_id/field_zone_id, crop_variety_id, planned_planting_date
  • expected_harvest_date คำนวณอัตโนมัติ (planned_planting_date + crop_variety.days_to_harvest) แสดงแบบ read-only
  • แสดงประมาณการตั้งต้น estimated_yield/estimated_cost ให้ตรวจสอบก่อนบันทึกเป็น draft (POST /crop/planting-plans)

รายละเอียดแผนการเพาะปลูก (Planting Plan Detail) Phase 1

ดูสถานะ ประวัติ และสั่งดำเนินการต่อแผนหนึ่งแผน

  • ข้อมูลแผน + cost_center_id ที่ผูกอยู่ พร้อม timeline สถานะ draft → approved → in_progress → harvested/cancelled
  • บล็อกเทียบประมาณการกับผลจริง: estimated_yield/cost, actual_yield/cost, yield_variance_pct, cost_variance_pct
  • ปุ่มตามสถานะ: "ตรวจสอบหมุนเวียนพืช", "อนุมัติ" (POST .../approve), "ปิดรอบ" (POST .../close), "ยกเลิก" (POST .../cancel)

ตรวจสอบหมุนเวียนพืชก่อนอนุมัติ (Rotation Check) Phase 1

แสดงผลตรวจคำเตือนหมุนเวียนพืชก่อนอนุมัติแผนจริง

  • รายการ recent_cycles ของ field/zone เดียวกัน เรียงล่าสุดตามจำนวน min_gap_cycles รอบ (GET .../rotation-check)
  • ไฮไลต์รอบที่ crop_family ตรงกับพันธุ์ใหม่ พร้อม flag เตือนความเสี่ยง
  • ปุ่ม "อนุมัติทั้งที่มีคำเตือน" พร้อมช่องกรอกเหตุผล — เฉพาะเจ้าของฟาร์ม/ผู้บริหาร

ทะเบียนพันธุ์พืช (Crop Varieties) Phase 1

จัดการข้อมูลอ้างอิงพันธุ์พืชที่ฟาร์มปลูก

  • ตารางรายการ: variety_code, name, crop_family, days_to_harvest, expected_yield_per_rai
  • ตัวกรองตาม crop_family
  • ฟอร์มเพิ่ม/แก้ไขพันธุ์ (POST/PATCH /crop/varieties)

กฎการหมุนเวียนพืช (Crop Rotation Rules) Phase 1

ตั้งกฎเว้นระยะปลูกพืชตระกูลเดียวกันซ้ำในแปลง/โซนเดียวกัน

  • ตารางรายการ: crop_family, min_gap_cycles
  • ปุ่ม "ตั้งกฎใหม่" (POST /crop/rotation-rules) — เฉพาะเจ้าของฟาร์ม/ผู้บริหาร

ปิดรอบแผน/บันทึกผลจริง (Close Cycle) Phase 1

กรอกผลจริงหลังเก็บเกี่ยวเสร็จเพื่อปิดรอบแผน

  • ฟอร์มกรอก actual_yield, actual_cost ของ yield_estimate ที่ผูกกับแผนนี้
  • คำนวณ yield_variance_pct และ cost_variance_pct แสดงสดทันทีที่กรอก
  • ปุ่ม "ยืนยันปิดรอบ" เปลี่ยนสถานะแผนเป็น harvested (POST .../close)

รายงานเทียบประมาณการกับผลจริง (Estimate vs Actual Report) Phase 1

ดูความแม่นยำของประมาณการผลผลิต/ต้นทุนสะสมทุกรอบ

  • ตาราง/กราฟเทียบ estimated_yield vs actual_yield และ estimated_cost vs actual_cost แยกตาม crop_variety
  • ตัวกรอง: ช่วงวันที่, field_id, crop_variety_id (GET /crop/reports/estimate-vs-actual)

คำแนะนำวันเริ่มปลูกจากพยากรณ์อากาศ (Planting Date Advisor) Phase 2

แนะนำวันเริ่มปลูกที่เหมาะสมจากพยากรณ์ฝน/แล้ง

  • เลือก field_id/field_zone_id + crop_variety_id แล้วแสดงช่วงวันแนะนำซ้อนกราฟพยากรณ์ฝน/แล้ง
  • ปุ่ม "ใช้วันนี้สร้างแผน" ส่งค่า planned_planting_date ต่อไปยังฟอร์มสร้างแผน

จองสต็อกเมล็ดพันธุ์ (Seed Stock Reservation) Phase 2

แจ้งจองสต็อกเมล็ดพันธุ์ล่วงหน้าตามแผนที่อนุมัติแล้ว

  • รายการแผน status = approved ที่ยังไม่จองเมล็ดพันธุ์ พร้อมพันธุ์ (crop_variety_id) และปริมาณประมาณจากพื้นที่
  • ปุ่ม "จองสต็อก" ส่งคำขอไปคลังสินค้า หรือ "แจ้งจัดซื้อ" ถ้าสต็อกไม่พอ พร้อมสถานะการจอง

แผนหมุนเวียนพืชระยะยาว (Long-term Rotation Planning) Phase 2

วางแผนปลูกหลายรอบล่วงหน้าต่อแปลง/โซน ป้องกันชนกฎหมุนเวียนพืชในอนาคต

  • มุมมองตารางเวลาหลายรอบต่อ field_id/field_zone_id แสดง crop_family ที่วางแผนไว้แต่ละรอบ
  • ไฮไลต์ช่วงที่จะชน min_gap_cycles ของ crop_rotation_rule ล่วงหน้า พร้อมปุ่มสร้างแผนร่างหลายรอบพร้อมกัน

เปรียบเทียบพันธุ์พืชและพยากรณ์ผลตอบแทน (Variety Comparison & Net Return Forecast) Phase 3

เทียบพันธุ์พืชหลายตัวเลือกจากข้อมูลย้อนหลังก่อนตัดสินใจปลูกจริง

  • ตารางเทียบพันธุ์ที่เลือก: expected_yield_per_rai, days_to_harvest, ต้นทุน/ผลผลิตเฉลี่ยจาก yield_estimate ย้อนหลัง
  • กราฟพยากรณ์ผลตอบแทนสุทธิต่อพันธุ์ พร้อมปุ่ม "เลือกพันธุ์นี้สร้างแผน" ส่งต่อไปฟอร์มสร้างแผน
