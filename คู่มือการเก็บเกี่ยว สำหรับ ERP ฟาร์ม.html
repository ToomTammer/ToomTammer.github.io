โมดูลการเก็บเกี่ยว (Harvest)

สเปกสำหรับเริ่มพัฒนาได้ทันที ครอบคลุมขอบเขตและจุดเชื่อมต่อกับโมดูลอื่น ฟังก์ชันหลักแยก MVP กับที่เพิ่มทีหลังได้ โครงสร้างฐานข้อมูล API หลักที่ต้องมี สิทธิ์การเข้าถึงตามบทบาท และสูตรคำนวณ/กฎทางธุรกิจ

ส่วนหนึ่งของ คู่มือ ERP สำหรับธุรกิจฟาร์ม อัปเดต 18 ก.ค. 2569

Scope & Integration

1. ขอบเขตและจุดเชื่อมต่อ (Scope & Integration Points)

โมดูลนี้เป็นจุดปิดวงจรของรอบผลิตพืช — ต้องผ่านการตรวจสอบ PHI ก่อนบันทึกได้ แล้วส่งผลลัพธ์ไปปิดแผน อัปเดตประวัติที่ดิน และสร้างสต็อกสินค้าสำเร็จรูป ไม่ทำหน้าที่คัดเกรดละเอียด (อยู่ในโมดูล "คุณภาพผลผลิต")

อยู่ในขอบเขต

  • บันทึกการเก็บเกี่ยวจริง (Harvest Record) — วันที่ ปริมาณ หน่วยนับ
  • บันทึกความสูญเสียหลังเก็บเกี่ยว (Post-Harvest Loss)
  • บันทึกแรงงานที่เก็บเกี่ยว (สำหรับค่าแรงตามผลงาน)
  • ปิดรอบแผนการเพาะปลูกพร้อมบันทึกผลจริง
  • คำนวณผลผลิตต่อไร่และเปรียบเทียบรอบย้อนหลัง

อยู่นอกขอบเขต (รับ/ส่งข้อมูลกับโมดูลอื่น)

  • ตรวจสอบว่าปลอดภัยเก็บเกี่ยวหรือยัง (PHI) — รับจาก การให้น้ำ ปุ๋ย และยา
  • การรับผลผลิตเข้าคลังเป็นสินค้าสำเร็จรูป — ส่งต่อให้ คลังสินค้า/สต็อก สร้าง stock_lot
  • การคัดเกรดละเอียด/ตรวจคุณภาพเพื่อขาย — ส่งต่อให้ คุณภาพผลผลิต
  • ค่าแรงเก็บเกี่ยวตามผลงาน — ส่งไปที่ บุคลากรและแรงงาน (piece rate)
  • อัปเดตประวัติการใช้ที่ดิน — ส่งกลับไปที่ ผังแปลงและที่ดิน
โมดูลที่เกี่ยวข้องเหตุการณ์สิ่งที่การเก็บเกี่ยวต้องทำPhase
การให้น้ำ ปุ๋ย และยาต้องการบันทึกเก็บเกี่ยวจริงตรวจสอบสถานะ PHI ก่อนอนุญาตให้บันทึกPhase 1
การเก็บเกี่ยว (ตัวเอง) → แผนการเพาะปลูกบันทึกเก็บเกี่ยวครั้งสุดท้ายของรอบปิดรอบแผนพร้อมบันทึกผลจริงเทียบประมาณการPhase 1
การเก็บเกี่ยว (ตัวเอง) → ผังแปลงและที่ดินปิดรอบแผนแล้วอัปเดตผลผลิตใน land_use_historyPhase 1
การเก็บเกี่ยว (ตัวเอง) → คลังสินค้า/สต็อกเก็บเกี่ยวเสร็จ ได้ผลผลิตจริงสร้าง stock_lot สินค้าสำเร็จรูปใหม่เข้าคลังPhase 1
คุณภาพผลผลิตต้องการคัดเกรดละเอียดก่อนขายส่งต่อผลผลิตที่เก็บเกี่ยวแล้วไปคัดเกรดPhase 1
การเก็บเกี่ยว (ตัวเอง) → บุคลากรและแรงงานมีแรงงานเก็บเกี่ยวแบบตามผลงานส่งปริมาณที่เก็บได้ต่อคนไปคำนวณค่าแรงPhase 2
Core Functions

2. ฟังก์ชันหลัก (Core Functions)

แยกชัดว่าอะไรต้องใช้งานได้ตั้งแต่วันแรก (MVP) และอะไรเพิ่มทีหลังได้โดยไม่กระทบการปิดรอบผลิตพื้นฐาน

MVP — ต้องมีวันแรก Phase 1

  • ตรวจสอบสถานะ PHI ก่อนอนุญาตให้บันทึกเก็บเกี่ยว
  • บันทึกการเก็บเกี่ยวจริง (วันที่ ปริมาณ หน่วยนับ)
  • บันทึกความสูญเสียหลังเก็บเกี่ยว/ระหว่างขนย้าย
  • ปิดรอบแผนการเพาะปลูกพร้อมบันทึกผลจริงเทียบประมาณการ
  • สร้างสต็อกสินค้าสำเร็จรูปเข้าคลังอัตโนมัติ
  • คำนวณผลผลิตต่อไร่และดูรายงานเทียบรอบย้อนหลัง

เพิ่มทีหลังได้

  • บันทึกแรงงาน/ทีมที่เก็บเกี่ยวและปริมาณที่แต่ละคนเก็บได้Phase 2
  • รองรับเก็บเกี่ยวหลายครั้งต่อรอบสำหรับพืชที่ทยอยเก็บPhase 2
  • แจ้งเตือนล่วงหน้าก่อนถึงวันเก็บเกี่ยวตามแผนPhase 2
  • วิเคราะห์ปัจจัยที่กระทบผลผลิต (อากาศ/ปุ๋ย/สายพันธุ์) เทียบผลจริงPhase 3
  • พยากรณ์วันเก็บเกี่ยวที่เหมาะสมจากข้อมูลการเจริญเติบโตPhase 3
Database

3. ฐานข้อมูล (Database)

แต่ละเอนทิตีคือ 1 ตารางในฐานข้อมูล พร้อมคำอธิบายว่าแทนอะไรในโลกจริง และแต่ละฟิลด์เก็บอะไร ชนิดข้อมูลแบบไหน

harvest_record Phase 1

บันทึกการเก็บเกี่ยว — บันทึกการเก็บเกี่ยวจริงแต่ละครั้ง ผูกกับแผนการเพาะปลูกหนึ่งรอบ พืชบางชนิด (เช่น ผัก/ผลไม้) อาจเก็บเกี่ยวหลายครั้งต่อรอบแบบทยอยเก็บ

ความสัมพันธ์: ผูกกับ planting_plan และ field/field_zone เป็นต้นทางให้สร้าง stock_lot ในโมดูลคลังสินค้า

ฟิลด์ชนิดข้อมูลเก็บอะไร
idเลขอ้างอิง/UUID (PK)รหัสประจำแถวนี้ ไม่ซ้ำกัน สร้างอัตโนมัติ
planting_plan_idเลขอ้างอิง (FK → planting_plan)เก็บเกี่ยวของแผนปลูกรอบไหน
field_id / field_zone_idเลขอ้างอิง (FK)เก็บเกี่ยวจากแปลงหรือโซนไหน
harvest_dateวันที่ (date)วันที่เก็บเกี่ยวจริง
quantity_harvestedตัวเลข (decimal)ปริมาณที่เก็บได้ในครั้งนี้
unitข้อความ (text)หน่วยนับ เช่น กก., ตัน, ลูก, ถุง
is_final_harvestจริง/เท็จ (boolean)เป็นการเก็บเกี่ยวครั้งสุดท้ายของรอบนี้ไหม ถ้าใช่จะปิดรอบแผนอัตโนมัติ
stock_lot_refข้อความ (text, ว่างได้)เลขที่ stock_lot ที่สร้างในโมดูลคลังสินค้าจากการเก็บเกี่ยวครั้งนี้

harvest_loss Phase 1

ความสูญเสียหลังเก็บเกี่ยว — บันทึกของเสีย/ความเสียหายระหว่างเก็บเกี่ยวหรือขนย้าย ใช้วิเคราะห์อัตราสูญเสียเทียบผลผลิตรวม

ความสัมพันธ์: ผูกกับ harvest_record หนึ่งครั้งเก็บเกี่ยวอาจมีหลายรายการความสูญเสีย

ฟิลด์ชนิดข้อมูลเก็บอะไร
idเลขอ้างอิง/UUID (PK)รหัสประจำแถวนี้ ไม่ซ้ำกัน สร้างอัตโนมัติ
harvest_record_idเลขอ้างอิง (FK → harvest_record)สูญเสียเกิดขึ้นตอนเก็บเกี่ยวครั้งไหน
loss_quantityตัวเลข (decimal)ปริมาณที่สูญเสียไป หน่วยเดียวกับ harvest_record.unit
loss_reasonตัวเลือกคงที่ (enum)สาเหตุ เลือกได้เฉพาะ: pest_damage, transport_damage, quality_reject, other

harvest_labor Phase 2

แรงงานที่เก็บเกี่ยว — บันทึกว่าพนักงานคนไหนเก็บเกี่ยวได้ปริมาณเท่าไหร่ ใช้ส่งต่อคำนวณค่าแรงตามผลงาน

ความสัมพันธ์: ผูกกับ harvest_record และ employee ในโมดูลบุคลากรและแรงงาน

ฟิลด์ชนิดข้อมูลเก็บอะไร
idเลขอ้างอิง/UUID (PK)รหัสประจำแถวนี้ ไม่ซ้ำกัน สร้างอัตโนมัติ
harvest_record_idเลขอ้างอิง (FK → harvest_record)เป็นส่วนหนึ่งของการเก็บเกี่ยวครั้งไหน
employee_idเลขอ้างอิง (FK → employee)ใครเป็นคนเก็บเกี่ยว
quantity_collectedตัวเลข (decimal)ปริมาณที่พนักงานคนนี้เก็บได้จริง ใช้คำนวณ piece rate
API

4. API

Endpoint หลักที่ต้องมีสำหรับ MVP (Phase 1) และที่ตามมาใน Phase 2

MethodEndpointคำอธิบายPhase
GET/crop/harvest-recordsดึงประวัติการเก็บเกี่ยว (filter: planting_plan_id, field_id, date_from, date_to) — ดึงจาก harvest_record1
POST/crop/harvest-recordsบันทึกการเก็บเกี่ยวใหม่ (ตรวจสอบ PHI ก่อน ถ้าไม่ผ่านให้ reject) — บันทึกลง harvest_record (อ้างอิง planting_plan_id จากโมดูลแผนการเพาะปลูก, field_id/field_zone_id จากโมดูลผังแปลงและที่ดิน)1
POST/crop/harvest-records/{id}/lossesบันทึกความสูญเสียของการเก็บเกี่ยวครั้งนี้ — บันทึกลง harvest_loss (อ้างอิง harvest_record_id)1
GET/crop/harvest-records/{id}/lossesดึงรายการความสูญเสียของการเก็บเกี่ยวครั้งนี้ — ดึงจาก harvest_loss1
POST/crop/planting-plans/{id}/close-harvestปิดรอบแผน อัปเดตผลจริงและสร้าง stock_lot อัตโนมัติ — ดึงจาก harvest_record (SUM quantity_harvested ของรอบนี้) แล้วบันทึกลง planting_plan.status และ yield_estimate.actual_yield (อ้างอิงจากโมดูลแผนการเพาะปลูก), land_use_history.yield_result (อ้างอิงจากโมดูลผังแปลงและที่ดิน) และสร้าง stock_lot ใหม่ (อ้างอิงจากโมดูลคลังสินค้า)1
GET/crop/reports/yield-per-raiผลผลิตต่อไร่ (filter: field_id, crop_variety_id, period) — ดึงจาก harvest_record (SUM quantity_harvested) และ field/field_zone.area_rai (อ้างอิงจากโมดูลผังแปลงและที่ดิน), crop_variety_id (อ้างอิงจากโมดูลแผนการเพาะปลูก)1
GET/crop/reports/yield-comparisonเปรียบเทียบผลผลิตรอบปัจจุบันกับย้อนหลัง — ดึงจาก harvest_record ของรอบปัจจุบันและรอบก่อนหน้าที่ field/field_zone และ crop_variety เดียวกัน (อ้างอิง field_zone จากโมดูลผังแปลงและที่ดิน, crop_variety จากโมดูลแผนการเพาะปลูก)1
GET/crop/harvest-laborดึงข้อมูลแรงงานที่เก็บเกี่ยวต่อครั้ง — ดึงจาก harvest_labor2
POST/crop/harvest-laborบันทึกปริมาณที่พนักงานแต่ละคนเก็บได้ — บันทึกลง harvest_labor (อ้างอิง harvest_record_id, employee_id จากโมดูลบุคลากรและแรงงาน)2

Business Rules & Formulas

6. สูตรคำนวณและกฎทางธุรกิจ (Business Rules & Formulas)

ตรรกะที่ dev ต้อง implement จริงเบื้องหลัง entity/endpoint ด้านบน

ตรวจสอบ PHI ก่อนบันทึกเก็บเกี่ยว (Pre-Harvest Safety Gate)

Phase 1

เรียกใช้กฎจากโมดูล "การให้น้ำ ปุ๋ย และยา" ทุกครั้งก่อนบันทึก ห้าม implement ซ้ำเอง

before insert harvest_record:
  call is_safe_to_harvest(field_id, harvest_date)
  (จากโมดูลการให้น้ำ ปุ๋ย และยา)

ถ้า false -> reject การบันทึก
  พร้อมแจ้งวันที่ปลอดภัยที่แท้จริง (safe_harvest_date)

ผลผลิตต่อไร่ (Yield per Rai)

Phase 1

รวมทุกครั้งที่เก็บเกี่ยวของรอบเดียวกัน หารด้วยพื้นที่จริง

yield_per_rai =
  SUM(harvest_record.quantity_harvested)
  ของ planting_plan เดียวกัน
  / field_or_zone.area_rai

อัตราสูญเสียหลังเก็บเกี่ยว (Post-Harvest Loss Rate)

Phase 1

ใช้ติดตามว่าสูญเสียมากผิดปกติหรือไม่ในแต่ละรอบ

loss_rate_pct =
  SUM(harvest_loss.loss_quantity)
  / SUM(harvest_record.quantity_harvested)
  × 100

ปิดรอบแผนอัตโนมัติ (Auto-Close Planting Plan)

Phase 1

ทำงานอัตโนมัติทันทีที่บันทึก harvest_record ที่ is_final_harvest = true

ถ้า harvest_record.is_final_harvest = true:
  -> planting_plan.status = harvested
  -> yield_estimate.actual_yield =
       SUM(quantity_harvested ทั้งหมดของรอบนี้)
  -> land_use_history.yield_result =
       yield_estimate.actual_yield
       (ในโมดูลผังแปลงและที่ดิน)

เปรียบเทียบผลผลิตรอบปัจจุบันกับย้อนหลัง

Phase 1

เทียบกับรอบก่อนหน้าของแปลง/โซนเดียวกันที่ปลูกพันธุ์เดียวกัน

yield_variance_pct =
  (current_yield_per_rai - previous_yield_per_rai)
  / previous_yield_per_rai × 100

previous_yield_per_rai = รอบก่อนหน้าล่าสุด
  ของ field/zone เดียวกัน ที่ crop_variety เดียวกัน

7. หน้าจอที่ต้องมี (Screens/Pages)

รายชื่อหน้าจอที่ต้องมีจริงในโมดูลนี้ พร้อมส่วนประกอบหลักของแต่ละหน้า — ใช้เป็น checklist ออกแบบ UI ต่อได้ตรง ๆ ไม่ต้องนั่งไล่จากฟังก์ชัน/entity เอง

แดชบอร์ดการเก็บเกี่ยว (Harvest Dashboard) Phase 1

หน้าแรกที่ผู้จัดการแปลง/เจ้าของฟาร์มเปิดดูภาพรวมการเก็บเกี่ยวประจำวัน

  • การ์ดสรุป: ผลผลิตรวมวันนี้/เดือนนี้ (SUM quantity_harvested), loss_rate_pct เฉลี่ย, จำนวน planting_plan ที่ยังไม่ปิด
  • ตารางการเก็บเกี่ยวล่าสุด: harvest_date, field/zone, quantity_harvested, unit, is_final_harvest
  • ตัวกรองช่วงวันที่/field_id ใช้ร่วมกับทุกวิดเจ็ต
  • ปุ่ม "บันทึกเก็บเกี่ยวใหม่" ลิงก์ไปฟอร์มบันทึก

รายการบันทึกการเก็บเกี่ยว (Harvest Records List) Phase 1

ดูและค้นหาประวัติการเก็บเกี่ยวทั้งหมด

  • ตารางรายการ: harvest_date, planting_plan_id, field_id/field_zone_id, quantity_harvested, unit, is_final_harvest, stock_lot_ref
  • ตัวกรอง: planting_plan_id, field_id, date_from/date_to (ตรงกับพารามิเตอร์ของ GET /crop/harvest-records)
  • คลิกแต่ละแถวเปิดหน้ารายละเอียด, ปุ่ม "บันทึกเก็บเกี่ยวใหม่"

ฟอร์มบันทึกการเก็บเกี่ยวใหม่ (New Harvest Record) Phase 1

บันทึกเก็บเกี่ยวจริง โดยต้องผ่านการตรวจสอบ PHI ก่อนเสมอ

  • ฟอร์ม: planting_plan_id, field_id/field_zone_id, harvest_date, quantity_harvested, unit, checkbox is_final_harvest
  • เรียก is_safe_to_harvest ก่อน submit — ถ้าไม่ผ่าน แสดง error พร้อม safe_harvest_date และปิดปุ่มบันทึก
  • ปุ่ม "บันทึก" เรียก POST /crop/harvest-records

รายละเอียดการเก็บเกี่ยว (Harvest Record Detail) Phase 1

ดูข้อมูลการเก็บเกี่ยวครั้งเดียว พร้อมความสูญเสียที่เกี่ยวข้องและปิดรอบแผน

  • ข้อมูลหลัก: harvest_date, quantity_harvested, unit, stock_lot_ref, is_final_harvest
  • ตารางความสูญเสียที่ผูกกับ record นี้ (loss_quantity, loss_reason) จาก GET /crop/harvest-records/{id}/losses
  • ปุ่ม "บันทึกความสูญเสีย" เปิดฟอร์มย่อย, ปุ่ม "ปิดรอบแผน" แสดงเมื่อ is_final_harvest = true

บันทึกความสูญเสียหลังเก็บเกี่ยว (Post-Harvest Loss) Phase 1

บันทึกและดูของเสีย/ความเสียหายที่เกิดระหว่างเก็บเกี่ยวหรือขนย้าย

  • ฟอร์มบันทึก: loss_quantity, loss_reason (dropdown: pest_damage, transport_damage, quality_reject, other)
  • ตารางความสูญเสียของ harvest_record นี้ แยกยอดตาม loss_reason
  • ปุ่ม "บันทึก" เรียก POST /crop/harvest-records/{id}/losses

ปิดรอบแผนการเพาะปลูก (Close Harvest) Phase 1

ยืนยันปิดรอบแผน พร้อมเทียบผลจริงกับประมาณการก่อนกดปิดจริง

  • สรุปยอด SUM(quantity_harvested) ทั้งรอบ เทียบกับ yield_estimate เดิม
  • พรีวิวผลลัพธ์: planting_plan.status → harvested, land_use_history.yield_result ที่จะถูกอัปเดต
  • ปุ่ม "ยืนยันปิดรอบ" เรียก POST /crop/planting-plans/{id}/close-harvest

รายงานผลผลิตต่อไร่ (Yield per Rai Report) Phase 1

ดูผลผลิตต่อไร่แยกตามแปลง/พันธุ์/ช่วงเวลา

  • ตาราง/กราฟ yield_per_rai แยกตาม field_id, crop_variety_id
  • ตัวกรอง: field_id, crop_variety_id, period (ตรงกับ GET /crop/reports/yield-per-rai)
  • ปุ่ม export ตาราง

รายงานเปรียบเทียบผลผลิตย้อนหลัง (Yield Comparison) Phase 1

เทียบผลผลิตรอบปัจจุบันกับรอบก่อนหน้าของแปลง/พันธุ์เดียวกัน

  • กราฟ/ตาราง yield_variance_pct ต่อ field/zone จาก GET /crop/reports/yield-comparison
  • ตัวกรอง field_id, crop_variety_id
  • ไฮไลต์แถวที่ yield_variance_pct ผิดปกติ (ติดลบมาก)

รายงานอัตราสูญเสีย (Post-Harvest Loss Rate Report) Phase 1

ติดตาม loss_rate_pct รายรอบ/แปลง ว่าสูงผิดปกติหรือไม่

  • ตาราง loss_rate_pct แยกตาม planting_plan/field พร้อมสัดส่วนตาม loss_reason
  • ตัวกรองช่วงวันที่/field_id
  • ไฮไลต์แถวที่ loss_rate_pct เกิน threshold ที่กำหนด

บันทึกแรงงานเก็บเกี่ยว (Harvest Labor Entry) Phase 2

บันทึกปริมาณที่พนักงานแต่ละคนเก็บเกี่ยวได้ต่อครั้ง สำหรับคำนวณค่าแรงตามผลงาน

  • ตารางรายชื่อพนักงาน (employee_id) กับ quantity_collected ผูกกับ harvest_record_id
  • ฟอร์มเพิ่มรายการต่อคน เรียก POST /crop/harvest-labor
  • แจ้งเตือนถ้า SUM(quantity_collected) ไม่เท่ากับ quantity_harvested ของ record นั้น

รายงานผลงานแรงงานเก็บเกี่ยว (Harvest Labor Report) Phase 2

ดูผลงานสะสมของพนักงานแต่ละคนเพื่อส่งต่อคำนวณค่าแรง piece rate

  • ตารางสรุป quantity_collected รวมต่อ employee_id ตามช่วงวันที่ จาก GET /crop/harvest-labor
  • ตัวกรองพนักงาน/ช่วงวันที่
  • ปุ่ม export ส่งต่อโมดูลบุคลากรและแรงงาน

รับผลผลิตเข้าคลัง (Warehouse Receiving View) Phase 1

มุมมองอ่านอย่างเดียวสำหรับพนักงานคลังสินค้าตรวจรับผลผลิตที่เก็บเกี่ยวแล้ว

  • ตารางการเก็บเกี่ยวที่มี stock_lot_ref แล้ว: harvest_date, quantity_harvested, unit, stock_lot_ref
  • ตัวกรอง field_id/ช่วงวันที่
  • ลิงก์ไปดู stock_lot ในโมดูลคลังสินค้า/สต็อก (อ่านอย่างเดียว)
