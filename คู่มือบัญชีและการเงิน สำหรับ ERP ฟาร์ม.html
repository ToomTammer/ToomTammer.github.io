Core Module 1/7 · Accounting & Finance — Dev-Ready Spec

โมดูลบัญชีและการเงิน (Accounting & Finance)

สเปกสำหรับเริ่มพัฒนาได้ทันที ครอบคลุมขอบเขตและจุดเชื่อมต่อกับโมดูลอื่น ฟังก์ชันหลักแยก MVP กับที่เพิ่มทีหลังได้ โครงสร้างฐานข้อมูล API หลักที่ต้องมี และสิทธิ์การเข้าถึงตามบทบาท

ส่วนหนึ่งของ คู่มือ ERP สำหรับธุรกิจฟาร์ม อัปเดต 18 ก.ค. 2569
1. ขอบเขตและจุดเชื่อมต่อ (Scope & Integration) 2. ฟังก์ชันหลัก (Core Functions) 3. ฐานข้อมูล (Database) 4. API 5. สิทธิ์การเข้าถึง (Roles) 6. สูตรคำนวณ (Formulas) 7. หน้าจอที่ต้องมี (Screens)
Scope & Integration

1. ขอบเขตและจุดเชื่อมต่อ (Scope & Integration Points)

โมดูลนี้เป็นปลายทางที่รับรายการจากโมดูลอื่นมาบันทึกเป็นบัญชีอัตโนมัติ ไม่ควรให้ผู้ใช้คีย์ข้อมูลซ้ำในสองระบบ

อยู่ในขอบเขต

  • ผังบัญชีและบัญชีแยกประเภท (Chart of Accounts, GL)
  • ลูกหนี้-เจ้าหนี้การค้าและการรับ-จ่ายชำระ
  • การจัดสรรต้นทุนสู่ศูนย์ต้นทุน/รอบผลิต
  • งบการเงิน งบประมาณ พยากรณ์กระแสเงินสด
  • เอกสารภาษีและการประเมินมูลค่าสินทรัพย์ชีวภาพ

อยู่นอกขอบเขต (รับข้อมูลจากโมดูลอื่น)

  • ใบสั่งซื้อ/ใบสั่งขาย และราคาต่อเกรด — จาก จัดซื้อ / ขายและลูกค้า
  • การตัดสต็อกและต้นทุนวัตถุดิบ — จาก คลังสินค้า/สต็อก
  • ค่าแรงและค่าจ้าง — จาก บุคลากรและแรงงาน
  • ค่าเสื่อมราคาเครื่องจักร — จาก สินทรัพย์และเครื่องจักร
  • น้ำหนัก/พื้นที่/อายุต่อรุ่น — จาก ปศุสัตว์ / พืชไร่-พืชสวน
โมดูลต้นทางเหตุการณ์ที่ทำให้เกิดข้อมูลสิ่งที่บัญชีต้องทำPhase
ขายและลูกค้าออกใบส่งของ/ปิดคำสั่งขายสร้าง AR invoice + journal entry อัตโนมัติPhase 1
จัดซื้อรับสินค้าตาม PO / ได้รับใบกำกับภาษีซื้อสร้าง AP invoice + journal entry อัตโนมัติPhase 1
คลังสินค้า/สต็อกตัดสต็อกอาหารสัตว์/ปุ๋ย/ยาโพสต์ journal entry ต้นทุนขาย (COGS)Phase 1
บุคลากรและแรงงานปิดรอบเงินเดือนโพสต์ journal entry ค่าแรงPhase 1
ธนาคาร (statement)นำเข้ารายการเดินบัญชีกระทบยอดเงินสด (reconciliation)Phase 2
สินทรัพย์และเครื่องจักรคำนวณค่าเสื่อมประจำเดือนโพสต์ journal entry ค่าเสื่อมราคาPhase 2
ปศุสัตว์ / พืชไร่-พืชสวนบันทึกน้ำหนัก/พื้นที่ต่อ batchใช้จัดสรรต้นทุนต่อหน่วยผลผลิตPhase 2
กรมสรรพากร (e-Tax)ถึงกำหนดยื่นแบบสร้าง/ส่ง tax_documentPhase 2
ปศุสัตว์ / พืชไร่-พืชสวนอัปเดตน้ำหนัก/อายุ ณ วันประเมินคำนวณมูลค่าสินทรัพย์ชีวภาพPhase 3
Core Functions

2. ฟังก์ชันหลัก (Core Functions)

แยกชัดว่าอะไรต้องใช้งานได้ตั้งแต่วันแรก (MVP) และอะไรเพิ่มทีหลังได้โดยไม่กระทบการใช้งานพื้นฐาน

MVP — ต้องมีวันแรก Phase 1

  • จัดการผังบัญชี (สร้าง/แก้ไข/ปิดใช้งานบัญชี)
  • บันทึกรายการบัญชีรายวัน ทั้งแบบ manual และอัตโนมัติจากโมดูลอื่น
  • ออกใบแจ้งหนี้ขาย (AR invoice) ผูกกับคำสั่งขาย
  • บันทึกใบแจ้งหนี้ซื้อ (AP invoice) ผูกกับคำสั่งซื้อ
  • บันทึกรับชำระ/จ่ายชำระเงิน ผูกกับใบแจ้งหนี้
  • ดูงบกำไรขาดทุนอย่างง่าย แยกตามศูนย์ต้นทุน
  • ดูรายงานอายุลูกหนี้/เจ้าหนี้ (AR/AP Aging)
  • ปิดงวดบัญชีรายเดือนพื้นฐาน (period close)

เพิ่มทีหลังได้

  • จัดสรรต้นทุนต่อหน่วยผลผลิต/ต่อรอบผลิต (batch costing)Phase 2
  • พยากรณ์กระแสเงินสดตามฤดูกาลผลิตPhase 2
  • กระทบยอดธนาคารอัตโนมัติจาก statementPhase 2
  • จัดทำเอกสารภาษี/เชื่อมต่อ e-Tax invoicePhase 2
  • รับค่าเสื่อมราคาสินทรัพย์จากโมดูล AssetPhase 2
  • ประเมินมูลค่าสินทรัพย์ชีวภาพ (fair value)Phase 3
  • งบประมาณเทียบผลจริง (budget vs actual)Phase 3
  • งบการเงินรวมหลายฟาร์ม/นิติบุคคลPhase 3
  • วิเคราะห์ต้นทุนจริงเทียบมาตรฐาน (cost variance)Phase 3
Database

3. ฐานข้อมูล (Database)

แต่ละเอนทิตีคือ 1 ตารางในฐานข้อมูล — พร้อมคำอธิบายว่าเอนทิตีนั้นแทนอะไรในโลกจริง และแต่ละฟิลด์เก็บอะไร ชนิดข้อมูลแบบไหน

chart_of_accounts Phase 1

ผังบัญชี — รายชื่อบัญชีทั้งหมดที่ใช้บันทึกรายการทางการเงิน เปรียบเหมือนสารบัญหมวดหมู่เงินเข้า-เงินออกของฟาร์ม

ความสัมพันธ์: อ้างอิงตัวเอง (self-reference) เพื่อทำบัญชีแม่-ลูก เช่น "เงินสด" เป็นบัญชีย่อยของ "สินทรัพย์หมุนเวียน"

ฟิลด์ชนิดข้อมูลเก็บอะไร
idเลขอ้างอิง/UUID (PK)รหัสประจำแถวนี้ ไม่ซ้ำกัน สร้างอัตโนมัติ
account_codeข้อความ (text)เลขที่บัญชีที่มนุษย์อ่านได้ เช่น "1100" ใช้อ้างอิงในเอกสารบัญชีจริง
account_name_th / account_name_enข้อความ (text)ชื่อบัญชีภาษาไทย/อังกฤษ เช่น "เงินสด" / "Cash"
account_typeตัวเลือกคงที่ (enum)หมวดบัญชี เลือกได้เฉพาะ: asset, liability, equity, revenue, expense, biological_asset
parent_account_idเลขอ้างอิง (FK → chart_of_accounts)ถ้าเป็นบัญชีย่อย ชี้ไปยังบัญชีแม่ ปล่อยว่างได้ถ้าเป็นบัญชีระดับบนสุด
is_activeจริง/เท็จ (boolean)บัญชีนี้ยังเปิดใช้งานอยู่ไหม ปิดแล้วจะเลือกใช้ในรายการใหม่ไม่ได้ แต่ประวัติเก่ายังอยู่

cost_center Phase 1

ศูนย์ต้นทุน — ตัวแทนของ "พื้นที่/หน่วยงาน" ที่ต้องการแยกต้นทุนและรายได้ออกจากกัน เช่น ทั้งฟาร์ม แปลง โรงเรือน หรือรอบผลิตหนึ่งรุ่น

ความสัมพันธ์: อ้างอิงตัวเอง (แม่-ลูก) และผูกกับรุ่นเลี้ยง/รอบปลูกจริงในโมดูลปศุสัตว์-พืชผ่าน ref_batch_id

ฟิลด์ชนิดข้อมูลเก็บอะไร
idเลขอ้างอิง/UUID (PK)รหัสประจำแถวนี้ ไม่ซ้ำกัน สร้างอัตโนมัติ
codeข้อความ (text)รหัสย่อของศูนย์ต้นทุน เช่น "FARM-A-HOUSE-2"
nameข้อความ (text)ชื่อเต็มที่คนอ่านเข้าใจ เช่น "โรงเรือนไก่ไข่ เบอร์ 2"
typeตัวเลือกคงที่ (enum)ระดับของศูนย์ต้นทุนนี้ เลือกได้เฉพาะ: farm, plot, house, batch
parent_cost_center_idเลขอ้างอิง (FK → cost_center)ศูนย์ต้นทุนแม่ เช่น โรงเรือนนี้อยู่ใต้ฟาร์มไหน
ref_batch_idเลขอ้างอิง (FK → โมดูลปศุสัตว์/พืช)ถ้า type = batch ให้ชี้ไปยังรุ่นเลี้ยง/รอบปลูกจริง ปล่อยว่างได้ถ้าไม่ใช่ระดับ batch — เป็น FK แบบ polymorphic เพราะฟาร์มปศุสัตว์กับพืชมีเอนทิตีต้นทางคนละตัวกัน: ฟาร์มปศุสัตว์ชี้ไปที่ animal_group (โมดูลทะเบียนสัตว์), ฟาร์มพืชชี้ไปที่ planting_plan (โมดูลแผนการเพาะปลูก) — ดู ref_batch_type ด้านล่างเพื่อรู้ว่าจะ join กับตารางไหน
ref_batch_typeตัวเลือกคงที่ (enum, ว่างได้)บอกว่า ref_batch_id ชี้ไปยังตารางไหน เลือกได้เฉพาะ: animal_group, planting_plan — ต้องมีค่าคู่กับ ref_batch_id เสมอถ้า type = batch

accounting_period Phase 1

งวดบัญชี — ตัวแทนของ 1 เดือนบัญชี ใช้เก็บสถานะว่างวดนั้นปิดแล้วหรือยัง เพื่อล็อกไม่ให้มีการสร้าง/แก้ไข journal_entry ย้อนเข้าไปในงวดที่ปิดแล้ว

ความสัมพันธ์: ไม่มี FK เข้า/ออกตรง ๆ แต่ระบบต้องเช็ค entry_date ของ journal_entry เทียบกับงวดนี้ก่อนบันทึกทุกครั้ง

ฟิลด์ชนิดข้อมูลเก็บอะไร
idเลขอ้างอิง/UUID (PK)รหัสประจำแถวนี้ ไม่ซ้ำกัน สร้างอัตโนมัติ
periodข้อความ (text)งวดบัญชี รูปแบบ "YYYY-MM" เช่น "2026-08" ต้องไม่ซ้ำกัน
statusตัวเลือกคงที่ (enum)สถานะงวด เลือกได้เฉพาะ: open, closed
closed_atวันที่-เวลา (timestamp, ว่างได้)วันเวลาที่ปิดงวด ปล่อยว่างถ้ายัง open
closed_byเลขอ้างอิง (FK → ผู้ใช้, ว่างได้)ใครเป็นคนกดปิดงวด

หมายเหตุ ห้ามสร้างหรือแก้ไข journal_entry ที่ entry_date ตกอยู่ในงวดที่ status = closed — enforce ที่ระดับ API/database เท่านั้น

journal_entry + journal_entry_line Phase 1

รายการบัญชีรายวัน — journal_entry คือ "ใบบันทึกรายการ" หนึ่งใบ (เช่น 1 การขาย = 1 entry) ส่วน journal_entry_line คือรายละเอียดว่าเงินไหลเข้า-ออกบัญชีไหนบ้างภายในใบนั้น

ความสัมพันธ์: 1 journal_entry มีได้หลาย journal_entry_line และผลรวม debit ต้องเท่ากับผลรวม credit เสมอ ไม่งั้นบันทึกไม่ผ่าน

ฟิลด์ชนิดข้อมูลเก็บอะไร
idเลขอ้างอิง/UUID (PK)รหัสประจำแถวนี้ ไม่ซ้ำกัน สร้างอัตโนมัติ
entry_noข้อความ (text)เลขที่เอกสารอ้างอิง สร้างอัตโนมัติ
entry_dateวันที่ (date)วันที่ทำรายการ
source_moduleตัวเลือกคงที่ (enum)ใครสร้างรายการนี้ เลือกได้เฉพาะ: manual, sales, procurement, inventory, hr, asset, biological_asset
source_ref_idข้อความ (text)เลขอ้างอิงเอกสารต้นทาง เช่น เลขที่ใบขายที่ทำให้เกิดรายการนี้
statusตัวเลือกคงที่ (enum)สถานะใบบันทึกรายการ เลือกได้เฉพาะ: draft, posted, reversed — draft แก้ไข/ลบได้ตามปกติ, posted ห้ามแก้ไข/ลบตรง ๆ (ดูหมายเหตุด้านล่าง), reversed คือใบที่ถูกกลับรายการแล้ว
(line) idเลขอ้างอิง/UUID (PK)รหัสประจำบรรทัดนี้ ไม่ซ้ำกัน สร้างอัตโนมัติ
(line) journal_entry_idเลขอ้างอิง (FK → journal_entry)บรรทัดนี้เป็นของใบบันทึกรายการไหน
(line) account_idเลขอ้างอิง (FK → chart_of_accounts)บรรทัดนี้ลงบัญชีไหน
(line) cost_center_idเลขอ้างอิง (FK → cost_center)บรรทัดนี้ลงศูนย์ต้นทุนไหน ปล่อยว่างได้ถ้าไม่เจาะจง
(line) debit / creditตัวเลข (decimal)จำนวนเงินฝั่งเดบิต/เครดิตของบรรทัดนี้ — มีค่าใดค่าหนึ่งเท่านั้น อีกฝั่งเป็น 0

หมายเหตุ journal_entry ที่ status = posted ห้ามแก้ไข/ลบตรง ๆ ต้องออกรายการกลับรายการ (reversal entry) เท่านั้น เพื่อรักษา audit trail — ควร enforce ที่ระดับ database/API ไม่ใช่แค่ UI

ar_invoice Phase 1

ใบแจ้งหนี้ลูกหนี้ — ใบเรียกเก็บเงินที่ฟาร์มออกให้ลูกค้า เช่น พ่อค้าคนกลาง โมเดิร์นเทรด หรือผู้ส่งออก หลังขายผลผลิต

ความสัมพันธ์: ผูกกับลูกค้าและคำสั่งขายที่มาจากโมดูลขาย

ฟิลด์ชนิดข้อมูลเก็บอะไร
idเลขอ้างอิง/UUID (PK)รหัสประจำแถวนี้ ไม่ซ้ำกัน สร้างอัตโนมัติ
invoice_noข้อความ (text)เลขที่ใบแจ้งหนี้
customer_idเลขอ้างอิง (FK → ลูกค้า)ลูกค้ารายไหนเป็นหนี้
sales_order_refข้อความ (text)เลขที่คำสั่งขายอ้างอิงจากโมดูลขาย
grade / weight / moistureข้อความ/ตัวเลขเกรด น้ำหนัก ความชื้นของสินค้า ที่ใช้คำนวณราคาขาย ณ วันนั้น
total_amountตัวเลข (decimal)ยอดเงินรวมที่ต้องเรียกเก็บ
due_dateวันที่ (date)กำหนดชำระเงิน
statusตัวเลือกคงที่ (enum)สถานะใบแจ้งหนี้ เลือกได้เฉพาะ: draft, issued, partially_paid, paid, overdue

ap_invoice Phase 1

ใบแจ้งหนี้เจ้าหนี้ — ใบเรียกเก็บเงินที่ผู้ขาย (อาหารสัตว์ ปุ๋ย พันธุ์พืช) ส่งมาเรียกเก็บจากฟาร์ม

ความสัมพันธ์: ผูกกับผู้ขายและใบสั่งซื้อที่มาจากโมดูลจัดซื้อ

ฟิลด์ชนิดข้อมูลเก็บอะไร
idเลขอ้างอิง/UUID (PK)รหัสประจำแถวนี้ ไม่ซ้ำกัน สร้างอัตโนมัติ
invoice_noข้อความ (text)เลขที่ใบแจ้งหนี้จากผู้ขาย
vendor_idเลขอ้างอิง (FK → ผู้ขาย)เป็นหนี้ผู้ขายรายไหน
purchase_order_refข้อความ (text)เลขที่ใบสั่งซื้ออ้างอิงจากโมดูลจัดซื้อ
total_amountตัวเลข (decimal)ยอดเงินรวมที่ต้องจ่าย
due_dateวันที่ (date)กำหนดจ่ายเงิน

Business Rules & Formulas

6. สูตรคำนวณและกฎทางธุรกิจ (Business Rules & Formulas)

ตรรกะที่ dev ต้อง implement จริงเบื้องหลัง entity/endpoint ด้านบน — เป็นสูตรมาตรฐานทั่วไป ควรให้ผู้สอบบัญชียืนยันก่อนใช้งานจริง โดยเฉพาะส่วนสินทรัพย์ชีวภาพ

กฎ Debit/Credit ตามประเภทบัญชี

Phase 1

ทุก journal_entry ต้อง validate ว่าผลรวม debit เท่ากับผลรวม credit ก่อนบันทึก ไม่งั้น API ต้อง reject

account_typeDebit ทำให้ยอดCredit ทำให้ยอด
asset / biological_assetเพิ่มลด
expenseเพิ่มลด
liabilityลดเพิ่ม
equityลดเพิ่ม
revenueลดเพิ่ม
 
validate: SUM(line.debit) == SUM(line.credit)
          WHERE line.journal_entry_id = X
-> ถ้าไม่เท่ากัน reject การบันทึก

ยอดคงเหลือบัญชี (Account Balance)

Phase 1

ยอดคงเหลือของบัญชีไม่ได้เก็บเป็นฟิลด์ตรง ๆ ในฐานข้อมูล แต่คำนวณจาก journal_entry_line ทุกครั้งที่ต้องใช้ (ป้องกันปัญหา balance ไม่ sync กับรายการจริง) — นับเฉพาะ journal_entry ที่ status = posted เท่านั้น

raw_balance(account_id) = SUM(line.debit) - SUM(line.credit)
    WHERE line.account_id = account_id
      AND line.journal_entry.status = 'posted'

balance(account_id) =
    ถ้า account_type อยู่ในกลุ่ม "Debit ทำให้ยอดเพิ่ม" (asset, biological_asset, expense)
        -> raw_balance(account_id)
    ถ้า account_type อยู่ในกลุ่ม "Credit ทำให้ยอดเพิ่ม" (liability, equity, revenue)
        -> raw_balance(account_id) × -1

ใช้ต่อ: งบทดลอง (trial balance) และงบแสดงฐานะการเงิน (balance sheet) คือการเรียก balance() นี้วนทุกบัญชีใน chart_of_accounts ตามช่วงวันที่ที่ต้องการ ส่วน opening_cash ในสูตรพยากรณ์กระแสเงินสดด้านล่างก็คือ balance() ของบัญชีกลุ่ม "เงินสด/เงินฝากธนาคาร" ณ วันที่เริ่มพยากรณ์

ต้นทุนต่อหน่วยผลผลิต (Cost per Unit)

Phase 2

ต้นทุนทางตรง (ระบุ cost_center ตรงอยู่แล้ว) ลงตรง ๆ ส่วนต้นทุนร่วม/ทางอ้อมต้องจัดสรรตามเกณฑ์ที่เลือก (พื้นที่ / จำนวนตัว / สัดส่วนรายได้)

allocated_cost(X) = shared_cost_total
    × ( base(X) / SUM(base(all cost centers)) )

cost_per_unit(X) = ( direct_cost(X) + allocated_cost(X) )
    / output_quantity(X)

ตัวอย่าง: ค่าน้ำ-ไฟส่วนกลาง 10,000 บาท จัดสรรตามจำนวนตัวสัตว์ โรงเรือน A มี 500 ตัว จากทั้งหมด 2,000 ตัว → ได้รับจัดสรร 10,000 × (500/2000) = 2,500 บาท

มูลค่ายุติธรรมสินทรัพย์ชีวภาพ (Biological Asset Fair Value)

Phase 3

คำนวณใหม่ทุกรอบประเมิน แล้วรับรู้ผลต่างเป็นกำไร/ขาดทุนเข้า journal_entry อัตโนมัติ

fair_value = weight_or_age × market_price_ref
net_value  = fair_value - cost_to_sell

period_gain_loss = net_value(รอบนี้) - net_value(รอบก่อน)
-> กำไร: Debit biological_asset / Credit รายได้จากการเปลี่ยนแปลงมูลค่า
-> ขาดทุน: กลับด้าน

หมายเหตุ รอบเวลาประเมินและแหล่งอ้างอิงราคาตลาดที่เหมาะสม ควรปรึกษาผู้สอบบัญชีก่อนกำหนดเป็นค่ามาตรฐานในระบบ

ส่วนต่างต้นทุนจริงเทียบมาตรฐาน (Cost Variance)

Phase 3

เทียบต้นทุนจริงที่เกิดขึ้นกับต้นทุนมาตรฐานที่ตั้งไว้ล่วงหน้าต่อรอบผลิต เพื่อแจ้งเตือนความผิดปกติ

cost_variance = actual_cost - standard_cost
cost_variance_pct = (actual_cost - standard_cost)
    / standard_cost × 100

flag เตือนถ้า |cost_variance_pct| > threshold (เช่น 10%)

พยากรณ์กระแสเงินสด (Cash Flow Forecast)

Phase 2

ประมาณเงินสดคงเหลือ ณ วันที่ในอนาคต จากใบแจ้งหนี้ที่ยังไม่ชำระและรายจ่ายประจำที่คาดว่าจะเกิด

projected_cash(T) = opening_cash
  + SUM(ar_invoice.total_amount
        WHERE due_date <= T AND status != paid)
  - SUM(ap_invoice.total_amount
        WHERE due_date <= T AND status != paid)
  - SUM(recurring_expense
        WHERE expected_date <= T)

7. หน้าจอที่ต้องมี (Screens/Pages)

รายชื่อหน้าจอที่ต้องมีจริงในโมดูลนี้ พร้อมส่วนประกอบหลักของแต่ละหน้า — ใช้เป็น checklist ออกแบบ UI ต่อได้ตรง ๆ ไม่ต้องนั่งไล่จากฟังก์ชัน/entity เอง

แดชบอร์ดบัญชี (Accounting Dashboard) Phase 1

หน้าแรกที่เจ้าของฟาร์ม/นักบัญชีเปิดดูภาพรวมการเงินประจำวัน

  • การ์ดสรุป: ยอดเงินสดคงเหลือ, ลูกหนี้คงค้างรวม, เจ้าหนี้คงค้างรวม
  • กราฟกำไรขาดทุนย่อ 6 เดือนล่าสุด แยกตามศูนย์ต้นทุน
  • รายการแจ้งเตือน: ใบแจ้งหนี้เลยกำหนด, งวดบัญชียังไม่ปิด
  • ตัวกรองช่วงวันที่/ศูนย์ต้นทุนที่ใช้ร่วมกับทุกวิดเจ็ต

ผังบัญชี (Chart of Accounts) Phase 1

จัดการรายชื่อบัญชีทั้งหมด แบบโครงสร้างแม่-ลูก

  • รายการบัญชีแบบ tree ยุบ/ขยายตาม parent_account_id
  • ฟอร์มสร้าง/แก้ไขบัญชี: account_code, ชื่อไทย/อังกฤษ, account_type, บัญชีแม่
  • ปุ่มปิดใช้งานบัญชี (is_active) พร้อมเตือนถ้ามีรายการผูกอยู่

รายการบัญชีรายวัน (Journal Entries) Phase 1

ดูและบันทึกรายการบัญชีทั้งที่มาจากระบบอัตโนมัติและคีย์เอง

  • ตารางรายการ: entry_no, entry_date, source_module, ยอดรวม debit/credit, status
  • ตัวกรอง: ช่วงวันที่, cost_center_id, source_module, status
  • ปุ่ม "สร้างรายการใหม่" — ฟอร์มคีย์บรรทัด debit/credit หลายบรรทัด พร้อม validate ยอดรวมให้เท่ากันก่อน submit
  • หน้ารายละเอียด 1 รายการ พร้อมปุ่ม "กลับรายการ (reversal)" ถ้า status = posted

ใบแจ้งหนี้ลูกหนี้ (AR Invoices) Phase 1

ออกและติดตามใบแจ้งหนี้ที่เรียกเก็บจากลูกค้า

  • ตารางรายการ: invoice_no, ลูกค้า, total_amount, due_date, status พร้อม badge สีตามสถานะ
  • ตัวกรองตามสถานะ (draft/issued/overdue/paid) และลูกค้า
  • หน้ารายละเอียดใบแจ้งหนี้ + ปุ่ม "บันทึกรับชำระ" เปิดฟอร์ม payment (มีช่องอัปโหลดไฟล์แนบ attachment_url ไม่บังคับ เช่น สลิปโอนเงิน)

ใบแจ้งหนี้เจ้าหนี้ (AP Invoices) Phase 1

บันทึกและติดตามใบแจ้งหนี้จากผู้ขายที่ต้องจ่าย

  • ตารางรายการ: invoice_no, ผู้ขาย, total_amount, due_date, status
  • ฟอร์มบันทึกใบแจ้งหนี้ใหม่ผูกกับ purchase_order_ref
  • หน้ารายละเอียด + ปุ่ม "บันทึกจ่ายชำระ" เปิดฟอร์ม payment (มีช่องอัปโหลดไฟล์แนบ attachment_url ไม่บังคับ เช่น สลิปโอนเงิน)

รายงานอายุลูกหนี้/เจ้าหนี้ (AR/AP Aging) Phase 1

ดูภาพรวมหนี้ค้างจ่าย/ค้างรับแยกตามช่วงอายุ

  • ตารางแยกตาม bucket: current, 1-30, 31-60, 61-90, เกิน 90 วัน
  • สลับดูฝั่งลูกหนี้/เจ้าหนี้ด้วยแท็บ
  • คลิกแต่ละแถวลิงก์กลับไปหน้ารายละเอียดใบแจ้งหนี้

งบการเงิน (Financial Statements) Phase 1

งบกำไรขาดทุน งบทดลอง และงบแสดงฐานะการเงิน สำหรับดูผลประกอบการ

  • แท็บสลับ 3 งบ: กำไรขาดทุน, งบทดลอง, งบแสดงฐานะการเงิน
  • ตัวกรอง: ช่วงงวด, cost_center_id (สำหรับกำไรขาดทุน)
  • ปุ่ม export PDF/Excel

ปิดงวดบัญชี (Period Close) Phase 1

ล็อกงวดบัญชีที่ตรวจสอบเสร็จแล้ว ป้องกันการแก้ไขย้อนหลัง

  • รายการ accounting_period ทั้งหมดพร้อมสถานะ open/closed
  • ปุ่ม "ปิดงวด" พร้อม checklist เตือนก่อนปิด (เช่น มี journal_entry สถานะ draft ค้างอยู่ไหม)

ศูนย์ต้นทุน (Cost Centers) Phase 1

จัดการโครงสร้างศูนย์ต้นทุนที่ใช้แยกกำไรขาดทุนรายพื้นที่/รอบผลิต

  • รายการแบบ tree ตาม parent_cost_center_id (farm → plot/house → batch)
  • ฟอร์มสร้าง/แก้ไข พร้อมเลือก ref_batch_type + ref_batch_id ถ้า type = batch

พยากรณ์กระแสเงินสด (Cash Flow Forecast) Phase 2

ดูแนวโน้มเงินสดล่วงหน้าจากใบแจ้งหนี้ที่ยังไม่ครบกำหนด

  • กราฟเส้นแนวโน้มเงินสดตามวันที่เลือกล่วงหน้า
  • ตารางรายการที่กระทบกระแสเงินสดในช่วงที่เลือก

กระทบยอดธนาคาร (Bank Reconciliation) Phase 2

นำเข้า bank statement มาจับคู่กับรายการ payment ในระบบ

  • ปุ่มนำเข้าไฟล์ statement + ตารางพรีวิวก่อน import
  • หน้าจับคู่รายการ statement กับ payment แบบ side-by-side พร้อมไฮไลต์ที่จับคู่ไม่ได้

เอกสารภาษี (Tax Documents) Phase 2

จัดทำและติดตามการยื่นแบบภาษีที่เกี่ยวข้องกับใบแจ้งหนี้

  • ตารางรายการแยกตาม doc_type (ภ.ง.ด.1/3/53, ภ.พ.30) และงวด
  • ปุ่มสร้างเอกสารจากใบแจ้งหนี้ที่เลือก + สถานะร่าง/ยื่นแล้ว

ประเมินมูลค่าสินทรัพย์ชีวภาพ (Biological Asset Valuation) Phase 3

บันทึกและดูประวัติการประเมินมูลค่าสัตว์/พืชที่ยังไม่ขาย

  • ฟอร์มบันทึกรอบประเมิน: เลือก cost_center (type=batch), weight_or_age, market_price_ref
  • กราฟแนวโน้ม net_value รายรอบประเมินของแต่ละ batch

งบประมาณเทียบผลจริง (Budget vs Actual) Phase 3

เทียบยอดที่ตั้งงบไว้กับยอดจริงที่เกิดขึ้นรายศูนย์ต้นทุน/บัญชี

  • ตารางเทียบ planned_amount vs actual (จาก journal_entry) พร้อม % variance
  • ตัวกรองรอบงบประมาณ + ศูนย์ต้นทุน
