โมดูลตรวจสอบย้อนกลับ (Traceability)

สเปกสำหรับเริ่มพัฒนาได้ทันที ครอบคลุมขอบเขตและจุดเชื่อมต่อกับโมดูลอื่น ฟังก์ชันหลักแยก MVP กับที่เพิ่มทีหลังได้ โครงสร้างฐานข้อมูล API หลักที่ต้องมี สิทธิ์การเข้าถึงตามบทบาท และสูตรคำนวณ/กฎทางธุรกิจ

ส่วนหนึ่งของ คู่มือ ERP สำหรับธุรกิจฟาร์ม อัปเดต 18 ก.ค. 2569
1. ขอบเขตและจุดเชื่อมต่อ (Scope & Integration) 2. ฟังก์ชันหลัก (Core Functions) 3. ฐานข้อมูล (Database) 4. API 5. สิทธิ์การเข้าถึง (Roles) 6. สูตรคำนวณ (Formulas)
Scope & Integration

1. ขอบเขตและจุดเชื่อมต่อ (Scope & Integration Points)

โมดูลนี้คล้าย "รายงานและแดชบอร์ด" ตรงที่ไม่ได้เป็นเจ้าของข้อมูลการผลิต/ขายเอง แต่เป็นชั้นเชื่อมโยงข้อมูลข้ามโมดูลทั้งฝั่งพืชและปศุสัตว์เข้าด้วยกัน ตั้งแต่ต้นทาง (แปลง/สัตว์) จนถึงลูกค้าที่ซื้อสินค้าไป (farm-to-table)

อยู่ในขอบเขต

  • สร้างรหัสติดตาม/QR code ต่อ lot สินค้า (Trace Code Generation)
  • เชื่อมโยงข้อมูลตลอดห่วงโซ่ตั้งแต่ต้นทางถึงปลายทาง
  • ค้นหาประวัติย้อนกลับจาก lot ที่ขายแล้ว (Backward Trace)
  • ค้นหาไปข้างหน้าเพื่อประเมินผลกระทบการเรียกคืน (Forward Trace / Recall)
  • สร้างรายงานตรวจสอบย้อนกลับสำหรับผู้ตรวจประเมิน

อยู่นอกขอบเขต (อ่านข้อมูลจากโมดูลอื่น ไม่คำนวณซ้ำ)

  • ไม่ได้เป็นเจ้าของข้อมูลการผลิต/ขายเอง — อ่านจาก stock_lot (คลังสินค้า), harvest_record/dispatch_record (พืช/ปศุสัตว์), sales_order/delivery_note (ขาย)
  • ไม่คำนวณต้นทุน/คุณภาพซ้ำ — ใช้ค่าที่โมดูลต้นทางบันทึกไว้แล้ว
  • การขอรับรองมาตรฐาน GAP/GMP จริง — เป็นของ มาตรฐานฟาร์ม
โมดูลต้นทางข้อมูลที่ดึงมาใช้ทำอะไรใน TraceabilityPhase
คลังสินค้า/สต็อกstock_lot ที่สร้างจากการเก็บเกี่ยว/คัดแยกจุดเริ่มต้นของ trace codePhase 1
การเก็บเกี่ยว / คัดแยกและส่งขายharvest_record / dispatch_record ที่ทำให้เกิด lotเชื่อมโยงย้อนกลับไปยังแปลง/สัตว์ต้นทางPhase 1
แผนการเพาะปลูก / ทะเบียนสัตว์planting_plan / animal_group ต้นทางเชื่อมโยงไปยังพันธุ์พืช/สายพันธุ์สัตว์Phase 1
การให้น้ำ ปุ๋ย และยา / อาหารสัตว์ / สุขภาพและวัคซีนpesticide_application, treatment_record ฯลฯแสดงประวัติสารเคมี/ยาที่ใช้ในรอบนั้นPhase 1
ขายและลูกค้าsales_order, delivery_noteเชื่อมโยงไปข้างหน้าถึงลูกค้าที่ซื้อ lot นี้Phase 1
Core Functions

2. ฟังก์ชันหลัก (Core Functions)

แยกชัดว่าอะไรต้องใช้งานได้ตั้งแต่วันแรก (MVP) และอะไรเพิ่มทีหลังได้โดยไม่กระทบการติดตามพื้นฐาน

MVP — ต้องมีวันแรก Phase 1

  • สร้างรหัสติดตามอัตโนมัติทุกครั้งที่มี stock_lot ใหม่
  • เชื่อมโยง trace code กับต้นทาง (แปลง/สัตว์, รอบผลิต, พันธุ์/สายพันธุ์)
  • เชื่อมโยง trace code กับปัจจัยการผลิตที่ใช้ (ปุ๋ย/สารเคมี/ยา/อาหาร)
  • ค้นหาประวัติย้อนกลับจาก lot หรือ trace code หนึ่ง
  • ค้นหาไปข้างหน้าว่า lot ต้นทางถูกขายให้ลูกค้าที่ไหนบ้าง
  • พิมพ์/แสดง QR code สำหรับติดฉลากสินค้า

เพิ่มทีหลังได้

  • สร้างรายงานตรวจสอบย้อนกลับพร้อมส่งผู้ตรวจประเมิน (export PDF)Phase 2
  • แจ้งเตือนอัตโนมัติเมื่อพบปัญหาที่ต้นทางว่ากระทบ lot ที่ขายไปแล้วบ้างPhase 2
  • เชื่อม blockchain/ระบบภายนอกยืนยันความถูกต้องของข้อมูลPhase 3
  • พอร์ทัลให้ลูกค้าปลายทางสแกน QR code ดูประวัติสินค้าเองPhase 3
Database

3. ฐานข้อมูล (Database)

แต่ละเอนทิตีคือ 1 ตารางในฐานข้อมูล พร้อมคำอธิบายว่าแทนอะไรในโลกจริง และแต่ละฟิลด์เก็บอะไร ชนิดข้อมูลแบบไหน

trace_code Phase 1

รหัสติดตาม — รหัส/QR code เฉพาะของแต่ละ lot สินค้า ใช้เป็นจุดเข้าหลักในการค้นหาประวัติย้อนกลับ

ความสัมพันธ์: ผูกกับ stock_lot (จากโมดูลคลังสินค้า) แบบหนึ่งต่อหนึ่ง

ฟิลด์ชนิดข้อมูลเก็บอะไร
stock_lot_refข้อความ (อ้างอิง stock_lot)รหัสนี้เป็นของ lot ไหนในคลังสินค้า
trace_codeข้อความ (unique)รหัสที่ใช้พิมพ์เป็น QR code บนฉลากสินค้า
generated_dateวันที่ (date)วันที่สร้างรหัสนี้
qr_image_refข้อความ (text, ว่างได้)ตำแหน่งที่เก็บรูปภาพ QR ที่สร้างไว้

trace_link Phase 1

การเชื่อมโยงย้อนกลับ — บันทึกความสัมพันธ์ระหว่าง trace_code กับเอนทิตีต้นทางในโมดูลอื่นที่เกี่ยวข้อง เช่น harvest_record, animal_group, pesticide_application, sales_order

ความสัมพันธ์: ผูกกับ trace_code และอ้างอิงเอนทิตีต้นทางแบบยืดหยุ่น (source_module + source_entity + source_ref_id) เพื่อรองรับได้ทั้งฝั่งพืชและปศุสัตว์

ฟิลด์ชนิดข้อมูลเก็บอะไร
trace_code_idเลขอ้างอิง (FK → trace_code)เป็นการเชื่อมโยงของรหัสติดตามไหน
source_moduleตัวเลือกคงที่ (enum)ข้อมูลนี้มาจากโมดูลไหน เลือกได้เฉพาะ: crop, livestock, procurement, sales
source_entityข้อความ (text)ชื่อเอนทิตีต้นทาง เช่น "harvest_record", "animal_group", "pesticide_application"
source_ref_idข้อความ (text)เลขอ้างอิงของรายการต้นทางนั้น
link_typeตัวเลือกคงที่ (enum)ประเภทการเชื่อมโยง เลือกได้เฉพาะ: origin (ต้นทางหลัก), input (ปัจจัยการผลิตที่ใช้), destination (ปลายทางที่ขายไป)

recall_event Phase 2

เหตุการณ์เรียกคืนสินค้า — บันทึกกรณีที่ต้องเรียกคืนสินค้าเนื่องจากพบปัญหาที่ต้นทาง ใช้ค้นหาว่ากระทบลูกค้ารายไหนบ้างผ่าน forward trace

ความสัมพันธ์: ผูกกับ trace_code ที่ได้รับผลกระทบ

ฟิลด์ชนิดข้อมูลเก็บอะไร
trace_code_idเลขอ้างอิง (FK → trace_code)เรียกคืน lot ไหน
reasonข้อความ (text)สาเหตุที่ต้องเรียกคืน
initiated_dateวันที่ (date)วันที่เริ่มดำเนินการเรียกคืน
affected_customer_refsข้อความ (list)รายชื่อลูกค้าที่ได้รับผลกระทบ คำนวณจาก forward trace
statusตัวเลือกคงที่ (enum)สถานะ เลือกได้เฉพาะ: investigating, in_progress, resolved

traceability_report Phase 2

รายงานตรวจสอบย้อนกลับ — เอกสารสรุปประวัติทั้งหมดของ lot หนึ่ง จัดรูปแบบพร้อมส่งให้ผู้ตรวจประเมินมาตรฐานหรือลูกค้าส่งออก

ความสัมพันธ์: ผูกกับ trace_code หนึ่งรายงานต่อหนึ่งรหัส

ฟิลด์ชนิดข้อมูลเก็บอะไร
trace_code_idเลขอ้างอิง (FK → trace_code)รายงานนี้เป็นของรหัสติดตามไหน
generated_dateวันที่ (date)วันที่สร้างรายงาน
generated_byเลขอ้างอิง (FK → user)ใครเป็นคนสร้างรายงาน
file_refข้อความ (text)ตำแหน่งที่เก็บไฟล์ PDF ที่สร้างขึ้น

Business Rules & Formulas

6. สูตรคำนวณและกฎทางธุรกิจ (Business Rules & Formulas)

ตรรกะที่ dev ต้อง implement จริงเบื้องหลัง entity/endpoint ด้านบน

สร้างรหัสติดตามอัตโนมัติ (Trace Code Generation)

Phase 1

ทำงานทันทีที่มี stock_lot ใหม่เกิดขึ้นไม่ว่าจากพืชหรือปศุสัตว์

trace_code =
  [FARM_CODE] - [YYYYMMDD] - [STOCK_LOT_ID]

สร้างอัตโนมัติทุกครั้งที่มี stock_lot ใหม่
  (ไม่ว่าจะมาจาก harvest_record หรือ dispatch_record)

สร้างการเชื่อมโยงอัตโนมัติจากเหตุการณ์โมดูลอื่น

Phase 1

กฎที่ทำให้ข้อมูลเชื่อมกันเองโดยไม่ต้องให้ผู้ใช้คีย์ย้อนหลัง

harvest_record/dispatch_record สร้าง stock_lot ใหม่
  -> สร้าง trace_link (link_type = origin)
     ไปยัง planting_plan / animal_group ต้นทาง

pesticide_application/treatment_record เกิดขึ้น
  ในช่วงเวลาของ planting_plan/animal_group เดียวกัน
  -> สร้าง trace_link (link_type = input)

sales_order/delivery_note อ้างอิง stock_lot นี้
  -> สร้าง trace_link (link_type = destination)

ค้นหาย้อนกลับแบบไล่ลำดับ (Recursive Backward Trace)

Phase 1

แสดงเป็นลำดับเวลาตั้งแต่ต้นทางจนถึงการเก็บเกี่ยว/คัดแยก

backward_trace(trace_code) =
  ไล่ trace_link ทุกแถวที่
  link_type IN (origin, input) ของ trace_code นี้
  เรียงตามเวลาเป็น timeline เดียว

ประเมินผลกระทบไปข้างหน้า (Forward Impact Assessment)

Phase 1

ใช้ตอนต้องเรียกคืนสินค้า เพื่อรู้ว่ากระทบลูกค้ารายไหนบ้าง

forward_trace(trace_code) =
  ไล่ trace_link ที่ link_type = destination
  หา sales_order/delivery_note/ลูกค้าทั้งหมด

ถ้าสร้าง recall_event:
  affected_customer_refs = ผลลัพธ์จาก forward_trace ทั้งหมด

ตรวจสอบความสมบูรณ์ของห่วงโซ่ (Trace Chain Completeness)

Phase 1

ป้องกันไม่ให้ขายสินค้าที่ตรวจสอบย้อนกลับไม่ได้เข้าโมเดิร์นเทรด/ส่งออก

is_trace_complete(trace_code) =
  มี trace_link (link_type = origin) อย่างน้อย 1 รายการ
  AND มีข้อมูล input ตามที่กำหนดสำหรับชนิดสินค้านั้น
      (พืช: ต้องมี planting_plan link
       ปศุสัตว์: ต้องมี animal_group link)

ถ้าไม่ครบ -> flag เตือนว่าข้อมูลย้อนกลับไม่สมบูรณ์
  ก่อนอนุมัติขายเข้าโมเดิร์นเทรด/ส่งออก
เอกสารนี้เป็นสเปกเริ่มพัฒนาโมดูล "ตรวจสอบย้อนกลับ" ควรรีวิวโครงสร้างฐานข้อมูลกับทีม dev จริงก่อนเริ่ม implement ← กลับไปภาพรวม ERP ฟาร์ม
