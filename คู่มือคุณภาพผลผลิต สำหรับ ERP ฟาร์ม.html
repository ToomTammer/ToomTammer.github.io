โมดูลคุณภาพผลผลิต (Produce Quality)

สเปกสำหรับเริ่มพัฒนาได้ทันที ครอบคลุมขอบเขตและจุดเชื่อมต่อกับโมดูลอื่น ฟังก์ชันหลักแยก MVP กับที่เพิ่มทีหลังได้ โครงสร้างฐานข้อมูล API หลักที่ต้องมี สิทธิ์การเข้าถึงตามบทบาท และสูตรคำนวณ/กฎทางธุรกิจ

ส่วนหนึ่งของ คู่มือ ERP สำหรับธุรกิจฟาร์ม อัปเดต 18 ก.ค. 2569
1. ขอบเขตและจุดเชื่อมต่อ (Scope & Integration) 2. ฟังก์ชันหลัก (Core Functions) 3. ฐานข้อมูล (Database) 4. API 5. สิทธิ์การเข้าถึง (Roles) 6. สูตรคำนวณ (Formulas) 7. หน้าจอที่ต้องมี (Screens)
Scope & Integration

1. ขอบเขตและจุดเชื่อมต่อ (Scope & Integration Points)

โมดูลนี้รับผลผลิตดิบจากการเก็บเกี่ยวมาคัดเกรดละเอียด แล้วแบ่งสต็อกและเชื่อมราคาตามเกรดให้โมดูลขายใช้ต่อ — ทำให้ผลผลิตเกรดต่างกันขายได้ราคาต่างกันแทนที่จะขายรวมราคาเดียว

อยู่ในขอบเขต

  • มาตรฐานเกรดต่อชนิดพืช (Grading Standard)
  • บันทึกผลตรวจสอบและคัดเกรดผลผลิตละเอียด (ขนาด, ความหวาน, ความชื้น, ตำหนิ)
  • แบ่งสต็อกใหม่ตามเกรดที่คัดได้
  • เชื่อมราคารับซื้อ/ราคาแนะนำกับแต่ละเกรด
  • ดูสรุปสัดส่วนเกรดต่อรอบผลิต

อยู่นอกขอบเขต (รับ/ส่งข้อมูลกับโมดูลอื่น)

  • ผลผลิตดิบที่ยังไม่คัดเกรด — รับจาก การเก็บเกี่ยว (stock_lot ที่สร้างไว้)
  • การสร้าง lot ใหม่ตามเกรดที่คัดแล้ว — ส่งต่อให้ คลังสินค้า/สต็อก จัดการ
  • ราคาขายจริงตามเกรด — ส่งไปที่ ขายและลูกค้า ใช้ตั้งราคาตอนขาย
โมดูลที่เกี่ยวข้องเหตุการณ์สิ่งที่คุณภาพผลผลิตต้องทำPhase
การเก็บเกี่ยวสร้าง stock_lot ผลผลิตดิบใหม่รับมาคัดเกรดละเอียดPhase 1
คุณภาพผลผลิต (ตัวเอง) → คลังสินค้า/สต็อกคัดเกรดเสร็จสมบูรณ์แบ่ง stock_lot ใหม่ตามเกรดที่ได้Phase 1
คุณภาพผลผลิต (ตัวเอง) → ขายและลูกค้ามีผลผลิตพร้อมขายแยกตามเกรดให้ข้อมูลเกรด+ราคาแนะนำไปใช้ตั้งราคาขายPhase 1
ขายและลูกค้าลูกค้าต้องการเกรดเฉพาะตรวจสอบว่ามีสต็อกเกรดนั้นพอไหมPhase 2
Core Functions

2. ฟังก์ชันหลัก (Core Functions)

แยกชัดว่าอะไรต้องใช้งานได้ตั้งแต่วันแรก (MVP) และอะไรเพิ่มทีหลังได้โดยไม่กระทบการคัดเกรดพื้นฐาน

MVP — ต้องมีวันแรก Phase 1

  • ตั้งเกณฑ์มาตรฐานเกรดต่อชนิดพืช (ขนาด/ความหวาน/ความชื้น/ตำหนิ)
  • บันทึกผลตรวจคุณภาพและคัดเกรดผลผลิตแต่ละ lot
  • แบ่งสต็อกใหม่ตามเกรดที่คัดได้ พร้อมแจ้งคลังสร้าง lot แยกเกรด
  • เชื่อมราคารับซื้อ/ราคาแนะนำกับแต่ละเกรด
  • ดูสรุปสัดส่วนเกรดต่อรอบผลิต

เพิ่มทีหลังได้

  • เชื่อมกับอุปกรณ์วัดคุณภาพดิจิทัล (เครื่องวัด Brix/ความชื้น)Phase 2
  • ตรวจสอบสต็อกเกรดที่ต้องการก่อนยืนยันคำสั่งขายPhase 2
  • วิเคราะห์แนวโน้มคุณภาพเทียบปัจจัยการดูแล (ปุ๋ย/น้ำ) ย้อนหลังPhase 2
  • ถ่ายภาพ/AI ช่วยคัดเกรดอัตโนมัติPhase 3
  • พยากรณ์สัดส่วนเกรดล่วงหน้าจากข้อมูลการดูแลระหว่างรอบPhase 3
Database

3. ฐานข้อมูล (Database)

แต่ละเอนทิตีคือ 1 ตารางในฐานข้อมูล พร้อมคำอธิบายว่าแทนอะไรในโลกจริง และแต่ละฟิลด์เก็บอะไร ชนิดข้อมูลแบบไหน

grading_standard Phase 1

มาตรฐานเกรด — เกณฑ์ที่ใช้ตัดสินว่าผลผลิตเป็นเกรดอะไร ต่อชนิดพืชหนึ่งชนิด เช่น เกรด A ต้องมีขนาด ≥ 6 ซม. ความหวาน ≥ 12 Brix

ความสัมพันธ์: ผูกกับ crop_variety จากโมดูลแผนการเพาะปลูก ถูกอ้างอิงจาก quality_inspection ตอนตัดสินเกรด

ฟิลด์ชนิดข้อมูลเก็บอะไร
idเลขอ้างอิง/UUID (PK)รหัสประจำแถวนี้ ไม่ซ้ำกัน สร้างอัตโนมัติ
crop_variety_idเลขอ้างอิง (FK → crop_variety)มาตรฐานนี้ใช้กับพืชพันธุ์ไหน
gradeข้อความ/ตัวเลือกคงที่ (enum)ชื่อเกรด เช่น A, B, C, reject
min_size / max_sizeตัวเลข (decimal, ว่างได้)ช่วงขนาดที่ยอมรับสำหรับเกรดนี้
min_brixตัวเลข (decimal, ว่างได้)ค่าความหวานขั้นต่ำที่ต้องผ่านสำหรับเกรดนี้
max_moisture_pctตัวเลข (decimal, ว่างได้)ความชื้นสูงสุดที่ยอมรับได้
defect_tolerance_pctตัวเลข (decimal, ว่างได้)สัดส่วนตำหนิสูงสุดที่ยอมรับได้สำหรับเกรดนี้

quality_inspection Phase 1

การตรวจสอบคุณภาพ — บันทึกผลตรวจคุณภาพจริงของ lot ผลผลิตหนึ่ง ก่อนตัดสินว่าจัดเป็นเกรดอะไรเทียบกับมาตรฐานที่ตั้งไว้

ความสัมพันธ์: ผูกกับ stock_lot (จากโมดูลคลังสินค้า ที่มาจาก harvest_record) และอ้างอิง grading_standard ที่ใช้ตัดสิน

ฟิลด์ชนิดข้อมูลเก็บอะไร
idเลขอ้างอิง/UUID (PK)รหัสประจำแถวนี้ ไม่ซ้ำกัน สร้างอัตโนมัติ
stock_lot_refข้อความ (อ้างอิง stock_lot)ตรวจ lot ไหนในคลัง
inspection_dateวันที่ (date)วันที่ตรวจสอบ
inspected_byเลขอ้างอิง (FK → user)ใครเป็นคนตรวจ
measured_size / measured_brix / measured_moisture_pctตัวเลข (decimal, ว่างได้)ค่าที่วัดได้จริง แล้วแต่ว่าพืชชนิดนั้นวัดค่าไหนบ้าง
defect_pctตัวเลข (decimal, ว่างได้)สัดส่วนตำหนิที่พบจริง
assigned_gradeข้อความ/ตัวเลือกคงที่ (enum)เกรดที่ตัดสินได้จากผลวัดเทียบ grading_standard

grade_stock_split Phase 1

การแบ่งสต็อกตามเกรด — บันทึกว่าจาก lot ต้นฉบับหนึ่ง แบ่งออกเป็นสต็อกย่อยตามเกรดเท่าไหร่ ก่อนส่งไปสร้าง lot ใหม่ในคลังสินค้า

ความสัมพันธ์: ผูกกับ quality_inspection และเป็นต้นทางให้สร้าง stock_lot ใหม่ (แยกตามเกรด) ในโมดูลคลังสินค้า

ฟิลด์ชนิดข้อมูลเก็บอะไร
idเลขอ้างอิง/UUID (PK)รหัสประจำแถวนี้ ไม่ซ้ำกัน สร้างอัตโนมัติ
quality_inspection_idเลขอ้างอิง (FK → quality_inspection)แบ่งสต็อกจากผลตรวจครั้งไหน
gradeข้อความ/ตัวเลือกคงที่ (enum)สต็อกส่วนนี้เป็นเกรดอะไร
quantityตัวเลข (decimal)ปริมาณของเกรดนี้ที่แบ่งออกมา
new_stock_lot_refข้อความ (text, ว่างได้)เลขที่ lot ใหม่ที่สร้างในคลังสำหรับเกรดนี้โดยเฉพาะ

grade_price Phase 1

ราคาต่อเกรด — ราคารับซื้อ/ราคาแนะนำต่อเกรดของพืชแต่ละชนิด ใช้อ้างอิงตอนตั้งราคาขาย

ความสัมพันธ์: ผูกกับ crop_variety และ grade ถูกอ้างอิงจากโมดูลขายและลูกค้าตอนตั้งราคา

ฟิลด์ชนิดข้อมูลเก็บอะไร
idเลขอ้างอิง/UUID (PK)รหัสประจำแถวนี้ ไม่ซ้ำกัน สร้างอัตโนมัติ
crop_variety_idเลขอ้างอิง (FK → crop_variety)ราคานี้ใช้กับพืชพันธุ์ไหน
gradeข้อความ/ตัวเลือกคงที่ (enum)ราคานี้เป็นของเกรดไหน
price_per_unitตัวเลข (decimal)ราคาต่อหน่วยของเกรดนี้
effective_dateวันที่ (date)วันที่ราคานี้เริ่มมีผล

Business Rules & Formulas

6. สูตรคำนวณและกฎทางธุรกิจ (Business Rules & Formulas)

ตรรกะที่ dev ต้อง implement จริงเบื้องหลัง entity/endpoint ด้านบน

ตัดสินเกรดอัตโนมัติจากผลวัด (Auto Grade Assignment)

Phase 1

ตรวจไล่จากเกรดสูงสุดลงมา ตัวแรกที่ผ่านทุกเกณฑ์คือเกรดที่กำหนดให้

assigned_grade =
  grading_standard ตัวแรก (เรียงจากเกรดสูงสุด) ที่:
    measured_size อยู่ในช่วง [min_size, max_size]
    AND measured_brix >= min_brix
    AND measured_moisture_pct <= max_moisture_pct
    AND defect_pct <= defect_tolerance_pct

ถ้าไม่เข้าเกณฑ์เกรดใดเลย -> assigned_grade = reject

สัดส่วนเกรดต่อรอบผลิต (Grade Distribution)

Phase 1

ใช้ดูภาพรวมว่ารอบนี้ได้เกรดดีมากน้อยแค่ไหน

grade_distribution(planting_plan) =
  สำหรับแต่ละ grade:
    SUM(grade_stock_split.quantity WHERE grade = X)
    / SUM(quantity ทั้งหมดของรอบนี้) × 100

มูลค่ารวมตามเกรด (Value by Grade)

Phase 1

ใช้เทียบว่าการคัดเกรดทำให้มูลค่ารวมเพิ่มขึ้นจริงเมื่อเทียบกับขายรวมราคาเดียว

total_value(planting_plan) =
  SUM( grade_stock_split.quantity × grade_price.price_per_unit )
  ต่อทุกเกรดของรอบนี้

ราคาที่ใช้ ณ วันที่ขายจริง (Effective Price Lookup)

Phase 1

ราคาต่อเกรดเปลี่ยนได้ตามเวลา ต้องดึงราคาที่มีผล ณ วันนั้นจริง ๆ

effective_price(crop_variety, grade, date) =
  grade_price ที่ effective_date <= date
  เรียงจากวันที่ล่าสุดก่อน แล้วเลือกแถวแรก

เตือนอัตราของเสีย/reject สูงผิดปกติ (Reject Rate Alert)

Phase 2

ช่วยจับสัญญาณปัญหาการดูแลพืชตั้งแต่เนิ่น ๆ ก่อนเสียหายมากในรอบถัดไป

reject_rate_pct =
  SUM(quantity WHERE grade = reject)
  / SUM(quantity ทั้งหมด) × 100

reject_rate_pct > threshold (เช่น 15%)
  -> flag เตือนให้ตรวจสอบสาเหตุ
     (ปุ๋ย/สารเคมี/สภาพอากาศ/ช่วงเก็บเกี่ยว)
Screens

7. หน้าจอที่ต้องมี (Screens/Pages)

รายชื่อหน้าจอที่ต้องมีจริงในโมดูลนี้ พร้อมส่วนประกอบหลักของแต่ละหน้า — ใช้เป็น checklist ออกแบบ UI ต่อได้ตรง ๆ ไม่ต้องนั่งไล่จากฟังก์ชัน/entity เอง

แดชบอร์ดคุณภาพผลผลิต (Quality Dashboard) Phase 1

หน้าแรกที่เจ้าของฟาร์ม/ผู้ตรวจสอบคุณภาพเปิดดูภาพรวมคุณภาพผลผลิตประจำรอบ

  • การ์ดสรุปสัดส่วนเกรด (grade_distribution) ต่อรอบผลิตล่าสุด และ reject_rate_pct พร้อมสถานะเตือนถ้าเกิน threshold
  • กราฟแนวโน้มสัดส่วนเกรดย้อนหลัง (จาก GET /crop/reports/grade-distribution)
  • รายการ quality_inspection ล่าสุด พร้อมลิงก์เข้าหน้ารายละเอียด
  • ตัวกรอง: crop_variety_id, ช่วงวันที่ inspection_date

มาตรฐานเกรด (Grading Standards) Phase 1

จัดการเกณฑ์มาตรฐานเกรดต่อชนิด/พันธุ์พืชที่ใช้ตัดสินเกรดผลผลิต

  • ตารางรายการ: crop_variety_id, grade, min_size/max_size, min_brix, max_moisture_pct, defect_tolerance_pct (GET /crop/grading-standards)
  • ตัวกรอง: crop_variety_id
  • ปุ่ม "เพิ่มมาตรฐานใหม่" เปิดฟอร์มตั้งเกณฑ์เกรด (POST /crop/grading-standards)
  • ปุ่มแก้ไขต่อแถว เปิดฟอร์มแก้เกณฑ์เดิม (PATCH /crop/grading-standards/{id})

บันทึกผลตรวจสอบคุณภาพ (New Quality Inspection) Phase 1

ฟอร์มให้ผู้ตรวจสอบคุณภาพกรอกค่าที่วัดได้จริงของ lot หนึ่ง แล้วให้ระบบตัดสินเกรดอัตโนมัติ

  • เลือก stock_lot_ref, inspection_date, inspected_by (ค่าเริ่มต้น = ผู้ใช้ที่ล็อกอิน)
  • ช่องกรอกค่าที่วัด: measured_size, measured_brix, measured_moisture_pct, defect_pct
  • ปุ่ม "บันทึกและคำนวณเกรด" เรียก POST /crop/quality-inspections คำนวณ assigned_grade ตามสูตร Auto Grade Assignment
  • แสดง assigned_grade ที่ระบบตัดสินให้ทันทีหลังบันทึกสำเร็จ

ประวัติการตรวจสอบคุณภาพ (Quality Inspection List) Phase 1

ดูประวัติการตรวจสอบคุณภาพทั้งหมด ค้นย้อนหลังได้ตาม lot หรือเกรด

  • ตารางรายการ: stock_lot_ref, inspection_date, inspected_by, assigned_grade (GET /crop/quality-inspections)
  • ตัวกรอง: ช่วงวันที่ inspection_date, assigned_grade, stock_lot_ref
  • คลิกแถวเข้าหน้ารายละเอียดการตรวจสอบ

รายละเอียดการตรวจสอบ & แบ่งสต็อกตามเกรด (Inspection Detail & Stock Split) Phase 1

ดูค่าที่วัดได้เทียบกับเกณฑ์มาตรฐาน แล้วสั่งแบ่งสต็อกตามเกรดที่ตัดสินได้

  • แสดงค่าที่วัด (measured_size/measured_brix/measured_moisture_pct/defect_pct) เทียบเกณฑ์ grading_standard ที่ใช้ตัดสิน
  • ตาราง grade_stock_split ที่เกิดจากการตรวจนี้: grade, quantity, new_stock_lot_ref
  • ปุ่ม "แบ่งสต็อกตามเกรด" เรียก POST /crop/quality-inspections/{id}/split-stock แจ้งคลังสร้าง lot ใหม่

ราคาต่อเกรด (Grade Prices) Phase 1

จัดการราคารับซื้อ/ราคาแนะนำต่อเกรดของแต่ละพันธุ์พืช

  • ตารางรายการ: crop_variety_id, grade, price_per_unit, effective_date (GET /crop/grade-prices)
  • ตัวกรอง: crop_variety_id, grade
  • ปุ่ม "ตั้งราคาใหม่" เปิดฟอร์มบันทึกราคา+วันที่มีผล (POST /crop/grade-prices)
  • แถบ "ราคาปัจจุบัน" ดึงราคาที่มีผล ณ วันนี้ต่อเกรด/พันธุ์ (GET /crop/grade-prices/current)

รายงานสัดส่วน & มูลค่าตามเกรด (Grade Distribution & Value Report) Phase 1

สรุปสัดส่วนเกรดและมูลค่ารวมของรอบผลิต ใช้เทียบว่าคัดเกรดแล้วมูลค่าเพิ่มขึ้นจริงแค่ไหน

  • กราฟวงกลม/แท่งสัดส่วนเกรดต่อรอบผลิต (สูตร Grade Distribution)
  • ตารางมูลค่ารวมตามเกรด = SUM(grade_stock_split.quantity × grade_price.price_per_unit) ต่อเกรด (สูตร Value by Grade)
  • ตัวกรอง: รอบผลิต/planting_plan, crop_variety_id, ช่วงวันที่

เตือนอัตราของเสียสูงผิดปกติ (Reject Rate Alert) Phase 2

รายการแจ้งเตือนเมื่อสัดส่วนของเสีย/reject ของรอบผลิตใดสูงเกินเกณฑ์

  • รายการ flag ที่ reject_rate_pct เกิน threshold (ค่าเริ่มต้น 15%) พร้อมรอบผลิต/พันธุ์ที่เกี่ยวข้อง
  • ช่องปรับค่า threshold ที่ใช้แจ้งเตือน
  • ลิงก์จากแต่ละแถวไปหน้าวิเคราะห์แนวโน้มคุณภาพเพื่อหาสาเหตุ

ตั้งค่าเชื่อมต่ออุปกรณ์วัดคุณภาพดิจิทัล (Device Integration Settings) Phase 2

เชื่อมเครื่องวัด Brix/ความชื้นเข้ากับระบบ เพื่อลดการกรอกค่าด้วยมือ

  • ฟอร์มตั้งค่าการเชื่อมต่อเครื่องวัด (ชนิดอุปกรณ์, พอร์ต/API key)
  • สวิตช์เปิด/ปิดการเติมค่า measured_brix/measured_moisture_pct อัตโนมัติในหน้าบันทึกผลตรวจ
  • บันทึกสถานะการซิงค์ล่าสุดจากอุปกรณ์

ตรวจสอบสต็อกเกรดก่อนยืนยันคำสั่งขาย (Grade Stock Availability) Phase 2

ให้พนักงานขายเช็กว่ามีสต็อกเกรดที่ลูกค้าต้องการเพียงพอก่อนยืนยันคำสั่งขาย

  • ตารางสต็อกคงเหลือแยกตามเกรด อ้างอิง new_stock_lot_ref จาก grade_stock_split
  • ตัวกรอง: crop_variety_id, grade
  • ปุ่ม "ยืนยันสต็อกพอสำหรับคำสั่งขาย" ส่งผลกลับให้โมดูลขายและลูกค้า

วิเคราะห์แนวโน้มคุณภาพเทียบปัจจัยการดูแล (Quality Trend Analysis) Phase 2

ดูว่าค่าคุณภาพที่วัดได้เปลี่ยนแปลงตามการให้น้ำ/ปุ๋ยอย่างไรในแต่ละรอบ

  • กราฟเส้นค่า measured_brix, measured_moisture_pct, defect_pct ย้อนหลัง เทียบเวลากับบันทึกการให้น้ำ/ปุ๋ย
  • ตัวกรอง: crop_variety_id, ช่วงเวลา
  • ตารางสรุปความสัมพันธ์เบื้องต้นระหว่างปัจจัยดูแลกับ assigned_grade

ถ่ายภาพ/AI คัดเกรดอัตโนมัติ (AI Photo Grading) Phase 3

ใช้ภาพถ่ายผลผลิตช่วยเสนอเกรดอัตโนมัติ ลดเวลาตรวจด้วยมือ

  • ปุ่มถ่ายภาพ/อัปโหลดภาพผลผลิตต่อ lot
  • แสดงเกรดที่ AI เสนอเทียบกับ assigned_grade เดิม ให้ผู้ตรวจสอบยืนยันหรือแก้ไข

พยากรณ์สัดส่วนเกรดล่วงหน้า (Grade Distribution Forecast) Phase 3

คาดการณ์สัดส่วนเกรดของรอบผลิตถัดไปจากข้อมูลการดูแลระหว่างรอบ

  • กราฟพยากรณ์สัดส่วนเกรดของรอบผลิตที่กำลังจะเก็บเกี่ยว
  • ตัวกรอง: crop_variety_id, รอบผลิต/planting_plan ที่จะถึง
