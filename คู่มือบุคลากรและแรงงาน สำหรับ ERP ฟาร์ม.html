Core Module 5/7 · HR & Labor — Dev-Ready Spec

โมดูลบุคลากรและแรงงาน (HR & Labor)

สเปกสำหรับเริ่มพัฒนาได้ทันที ครอบคลุมขอบเขตและจุดเชื่อมต่อกับโมดูลอื่น ฟังก์ชันหลักแยก MVP กับที่เพิ่มทีหลังได้ โครงสร้างฐานข้อมูล API หลักที่ต้องมี สิทธิ์การเข้าถึงตามบทบาท และสูตรคำนวณ/กฎทางธุรกิจ

ส่วนหนึ่งของ คู่มือ ERP สำหรับธุรกิจฟาร์ม อัปเดต 18 ก.ค. 2569
1. ขอบเขตและจุดเชื่อมต่อ (Scope & Integration) 2. ฟังก์ชันหลัก (Core Functions) 3. ฐานข้อมูล (Database) 4. API 5. สิทธิ์การเข้าถึง (Roles) 6. สูตรคำนวณ (Formulas) 7. หน้าจอที่ต้องมี (Screens)
Scope & Integration

1. ขอบเขตและจุดเชื่อมต่อ (Scope & Integration Points)

จุดเด่นของฟาร์มคือค่าแรงมักผูกกับผลงานจริง (จับสัตว์ได้กี่ตัว เก็บผลผลิตได้กี่กก.) ไม่ใช่แค่เวลาเข้า-ออกงาน โมดูลนี้ต้องรับข้อมูลผลงานจากหน้างานมาคำนวณเงินเดือนให้ถูกต้อง

อยู่ในขอบเขต

  • ทะเบียนพนักงาน (Employee Master) ทั้งประจำและรายวัน
  • บันทึกเวลาเข้า-ออกงาน (Attendance) และ OT
  • ค่าแรงตามผลงาน (Piece Rate)
  • ใบลาและวันลาคงเหลือ
  • คำนวณเงินเดือนและปิดรอบจ่าย (Payroll Run)

อยู่นอกขอบเขต (รับ/ส่งข้อมูลกับโมดูลอื่น)

  • ปริมาณผลงานที่ทำได้จริง (จับสัตว์/เก็บเกี่ยว) — รับจาก ปศุสัตว์ / พืชไร่-พืชสวน
  • การบันทึกค่าแรงเป็นรายการบัญชี — ส่งต่อให้ บัญชีและการเงิน
  • งบประมาณค่าแรงต่อศูนย์ต้นทุน — รับจาก บัญชีและการเงิน
  • การยื่นประกันสังคม/ภาษีหัก ณ ที่จ่ายต่อหน่วยงานรัฐ — เป็นเอกสารส่งออก ไม่ใช่ระบบยื่นอัตโนมัติ
โมดูลที่เกี่ยวข้องเหตุการณ์สิ่งที่ HR ต้องทำPhase
ปศุสัตว์ / พืชไร่-พืชสวนบันทึกผลงานที่ทำจริงต่อคน (จับสัตว์/เก็บเกี่ยว)ดึงมาคำนวณค่าแรงตามผลงาน (piece rate)Phase 1
HR (ตัวเอง) → บัญชีและการเงินปิดรอบเงินเดือนส่งข้อมูลโพสต์ journal entry ค่าแรงเข้าศูนย์ต้นทุนPhase 1
บัญชีและการเงินตั้งงบประมาณค่าแรงต่อศูนย์ต้นทุนเทียบค่าแรงจริงกับงบที่ตั้งไว้Phase 2
หน่วยงานรัฐ (ภายนอก)ถึงกำหนดยื่นประกันสังคม/ภาษีหัก ณ ที่จ่ายรายเดือนสร้างรายงาน/แบบยื่นให้พร้อมส่งPhase 2
Core Functions

2. ฟังก์ชันหลัก (Core Functions)

แยกชัดว่าอะไรต้องใช้งานได้ตั้งแต่วันแรก (MVP) และอะไรเพิ่มทีหลังได้โดยไม่กระทบการจ่ายเงินเดือนพื้นฐาน

MVP — ต้องมีวันแรก Phase 1

  • จัดการทะเบียนพนักงาน แยกประเภทประจำ/รายวัน
  • บันทึกเวลาเข้า-ออกงานรายวัน
  • บันทึกผลงานรายบุคคลสำหรับค่าแรงตามผลงาน (piece rate)
  • คำนวณค่าแรงตามประเภทการจ้าง (รายเดือน/รายวัน/ตามผลงาน)
  • บันทึกวันลาและคำนวณวันลาคงเหลือ
  • คำนวณค่าล่วงเวลา (OT) ตามชั่วโมงที่ทำเกิน
  • ปิดรอบเงินเดือนและส่งข้อมูลเข้าบัญชี

เพิ่มทีหลังได้

  • จัดตารางกะทำงานล่วงหน้า (shift scheduling)Phase 2
  • คำนวณประกันสังคม/ภาษีหัก ณ ที่จ่ายอัตโนมัติPhase 2
  • เทียบค่าแรงจริงกับงบประมาณต่อศูนย์ต้นทุนPhase 2
  • แอปมือถือให้พนักงานเช็คอิน/ดูสลิปเงินเดือนของตัวเองPhase 2
  • วิเคราะห์ประสิทธิภาพแรงงาน (ผลงานต่อคน/ต่อชั่วโมง)Phase 3
  • พยากรณ์ความต้องการแรงงานตามฤดูกาล/รอบผลิตPhase 3
Database

3. ฐานข้อมูล (Database)

แต่ละเอนทิตีคือ 1 ตารางในฐานข้อมูล พร้อมคำอธิบายว่าแทนอะไรในโลกจริง และแต่ละฟิลด์เก็บอะไร ชนิดข้อมูลแบบไหน

position Phase 1

ตำแหน่งงาน — รายชื่อตำแหน่งทั้งหมดที่มีในฟาร์ม เช่น ผู้จัดการฟาร์ม หัวหน้าคนงาน คนงานทั่วไป สัตวแพทย์ประจำฟาร์ม แยกเป็นตารางต่างหากจาก employee เพราะแต่ละตำแหน่งมีข้อมูลของตัวเอง (ไม่ใช่ enum คงที่) และหลายฟาร์มมักมีชื่อตำแหน่งไม่เหมือนกัน

ความสัมพันธ์: เป็นต้นทางให้ employee.position_id — 1 ตำแหน่งมีได้หลายพนักงาน

ฟิลด์ชนิดข้อมูลเก็บอะไร
idเลขอ้างอิง/UUID (PK)รหัสประจำแถวนี้ ไม่ซ้ำกัน สร้างอัตโนมัติ
titleข้อความ (text)ชื่อตำแหน่ง เช่น "หัวหน้าคนงาน"
departmentข้อความ (text, ว่างได้)ฝ่าย/แผนกที่ตำแหน่งนี้อยู่ เช่น "ฝ่ายผลิต" ปล่อยว่างได้ถ้าฟาร์มเล็กไม่แบ่งแผนก
is_activeจริง/เท็จ (boolean)ยังเปิดรับ/ใช้ตำแหน่งนี้อยู่ไหม ปิดแล้วพนักงานเก่าที่อยู่ตำแหน่งนี้ไม่หายไป แค่เลือกใช้กับคนใหม่ไม่ได้

employee Phase 1

พนักงาน — ทะเบียนคนทำงานทุกคนของฟาร์ม ทั้งพนักงานประจำและแรงงานรายวัน/ตามฤดูกาล

ความสัมพันธ์: ผูกกับ attendance, piece_work_record, leave_request และ payroll_run_line, ผูกกับ position

ฟิลด์ชนิดข้อมูลเก็บอะไร
idเลขอ้างอิง/UUID (PK)รหัสประจำแถวนี้ ไม่ซ้ำกัน สร้างอัตโนมัติ
employee_codeข้อความ (text)รหัสพนักงานที่ใช้อ้างอิงภายในระบบ
nameข้อความ (text)ชื่อ-นามสกุลพนักงาน
position_idเลขอ้างอิง (FK → position)ตำแหน่งงานปัจจุบันของพนักงานคนนี้
employment_typeตัวเลือกคงที่ (enum)ประเภทการจ้าง เลือกได้เฉพาะ: permanent, daily, seasonal
wage_typeตัวเลือกคงที่ (enum)วิธีคิดค่าแรง เลือกได้เฉพาะ: monthly, daily_rate, piece_rate
base_wageตัวเลข (decimal)อัตราค่าจ้างพื้นฐาน หน่วยขึ้นกับ wage_type (ต่อเดือน/ต่อวัน/ต่อหน่วยผลงาน)
default_cost_center_idเลขอ้างอิง (FK → cost_center)พื้นที่/โรงเรือนที่ทำงานประจำ
social_security_noข้อความ (text, ว่างได้)เลขที่ผู้ประกันตน
is_activeจริง/เท็จ (boolean)ยังทำงานอยู่ไหม

attendance Phase 1

บันทึกเวลาเข้า-ออกงาน — เวลาทำงานจริงของพนักงานแต่ละวัน ใช้คำนวณค่าแรงรายวันและค่าล่วงเวลา

ความสัมพันธ์: ผูกกับ employee และ cost_center (ทำงานที่ไหนวันนั้น อาจต่างจาก default_cost_center_id)

ฟิลด์ชนิดข้อมูลเก็บอะไร
idเลขอ้างอิง/UUID (PK)รหัสประจำแถวนี้ ไม่ซ้ำกัน สร้างอัตโนมัติ
employee_idเลขอ้างอิง (FK → employee)ใครมาทำงาน
work_dateวันที่ (date)วันที่ทำงาน
cost_center_idเลขอ้างอิง (FK → cost_center)ทำงานที่พื้นที่ไหนในวันนั้น
clock_in / clock_outเวลา (datetime)เวลาที่เข้างานและออกงานจริง
hours_workedตัวเลข (decimal)ชั่วโมงทำงานที่คำนวณได้จาก clock_in/clock_out
overtime_hoursตัวเลข (decimal)ชั่วโมงที่ทำเกินเวลามาตรฐานในวันนั้น

piece_work_record Phase 1

บันทึกผลงานตามชิ้น/หน่วย — ปริมาณงานที่ทำได้จริงต่อคนต่อวัน สำหรับพนักงานที่จ้างแบบค่าแรงตามผลงาน เช่น จับไก่ได้กี่ตัว เก็บผลไม้ได้กี่กิโลกรัม

ความสัมพันธ์: ผูกกับ employee และ cost_center (batch) ที่รับข้อมูลผลงานมาจากโมดูลปศุสัตว์/พืช

ฟิลด์ชนิดข้อมูลเก็บอะไร
idเลขอ้างอิง/UUID (PK)รหัสประจำแถวนี้ ไม่ซ้ำกัน สร้างอัตโนมัติ
employee_idเลขอ้างอิง (FK → employee)ใครเป็นคนทำงานนี้
cost_center_idเลขอ้างอิง (FK → cost_center)ทำผลงานให้รุ่นเลี้ยง/รอบปลูกไหน
work_dateวันที่ (date)วันที่ทำผลงานนี้
task_typeข้อความ/ตัวเลือกคงที่ (enum)ประเภทงาน เช่น catching (จับสัตว์), harvesting (เก็บเกี่ยว), sorting (คัดแยก)
quantity_completedตัวเลข (decimal)ปริมาณงานที่ทำได้จริง เช่น จำนวนตัว หรือน้ำหนักกิโลกรัม
rate_per_unitตัวเลข (decimal)อัตราค่าแรงต่อหน่วยผลงาน ณ วันนั้น

leave_request Phase 1

ใบลา — คำขอลาของพนักงาน ใช้คำนวณวันลาคงเหลือและตัดเงินเดือนกรณีลาไม่มีสิทธิ์

ความสัมพันธ์: ผูกกับ employee และผู้อนุมัติ (user)

ฟิลด์ชนิดข้อมูลเก็บอะไร
idเลขอ้างอิง/UUID (PK)รหัสประจำแถวนี้ ไม่ซ้ำกัน สร้างอัตโนมัติ
employee_idเลขอ้างอิง (FK → employee)ใครขอลา
leave_typeตัวเลือกคงที่ (enum)ประเภทการลา เลือกได้เฉพาะ: sick, personal, vacation, unpaid
start_date / end_dateวันที่ (date)ช่วงวันที่ลา
statusตัวเลือกคงที่ (enum)สถานะ เลือกได้เฉพาะ: pending, approved, rejected
approved_byเลขอ้างอิง (FK → user, ว่างได้)ใครเป็นคนอนุมัติ
attachment_urlข้อความ (text, nullable)ลิงก์ไฟล์แนบ (เช่น ใบรับรองแพทย์สำหรับการลาป่วยที่สแกน) อัปโหลดไปยัง cloud storage ไม่บังคับกรอก

payroll_run + payroll_run_line Phase 1

รอบเงินเดือน — payroll_run คือการปิดรอบจ่ายเงินหนึ่งรอบ (เช่น รายเดือนหรือรายปักษ์สำหรับแรงงานรายวัน) payroll_run_line คือยอดเงินได้-หักของพนักงานแต่ละคนในรอบนั้น

ความสัมพันธ์: ผูกกับ employee และเมื่อ post แล้วจะส่งข้อมูลไปสร้าง journal entry ค่าแรงที่โมดูลบัญชี

ฟิลด์ชนิดข้อมูลเก็บอะไร
idเลขอ้างอิง/UUID (PK)รหัสประจำแถวนี้ ไม่ซ้ำกัน สร้างอัตโนมัติ
periodข้อความ/วันที่งวดเงินเดือนนี้ครอบคลุมช่วงไหน
statusตัวเลือกคงที่ (enum)สถานะ เลือกได้เฉพาะ: draft, calculated, approved, paid, posted
(line) idเลขอ้างอิง/UUID (PK)รหัสประจำบรรทัดนี้ ไม่ซ้ำกัน สร้างอัตโนมัติ
(line) payroll_run_idเลขอ้างอิง (FK → payroll_run)บรรทัดนี้เป็นของรอบเงินเดือนไหน
(line) employee_idเลขอ้างอิง (FK → employee)เงินเดือนงวดนี้ของใคร
(line) cost_center_idเลขอ้างอิง (FK → cost_center)ศูนย์ต้นทุนที่ปันค่าแรงนี้ไป — snapshot จาก employee.default_cost_center_id ตอนคำนวณ payroll (ถ้าพนักงานทำงานหลายพื้นที่ในงวดเดียว ให้ใช้พื้นที่ที่ทำงานมากที่สุดในงวดนั้นแทน ยังไม่รองรับการแบ่งสัดส่วนต่อคนใน Phase 1)
(line) gross_payตัวเลข (decimal)เงินได้รวมก่อนหัก (ฐานค่าจ้าง + OT + piece rate)
(line) social_security_deduction / tax_deductionตัวเลข (decimal)ยอดหักประกันสังคมและภาษี ณ ที่จ่าย
(line) net_payตัวเลข (decimal)เงินได้สุทธิที่จ่ายจริงให้พนักงาน
API

4. API

Endpoint หลักที่ต้องมีสำหรับ MVP (Phase 1) และที่ตามมาใน Phase 2

MethodEndpointคำอธิบายPhase
GET/hr/positionsดึงรายชื่อตำแหน่งงานทั้งหมด — ดึงจาก position1
POST/hr/positionsสร้างตำแหน่งงานใหม่ — บันทึกลง position1
GET/hr/employeesดึงรายชื่อพนักงานทั้งหมด (filter: position_id) — ดึงจาก employee, position1
POST/hr/employeesสร้างพนักงานใหม่ — บันทึกลง employee (อ้างอิง position_id จาก position, default_cost_center_id จาก cost_center ของโมดูลบัญชีและการเงิน)1
PATCH/hr/employees/{id}แก้ไข/ปิดใช้งานพนักงาน — บันทึกลง employee1
POST/hr/attendanceบันทึกเวลาเข้า-ออกงาน — บันทึกลง attendance (อ้างอิง employee_id จาก employee, cost_center_id จาก cost_center ของโมดูลบัญชีและการเงิน) — ถ้าผู้เรียกเป็นหัวหน้างาน ระบบต้องปฏิเสธถ้า employee_id ที่ระบุไม่ได้อยู่ในทีมที่ตนดูแล (บังคับที่ backend ไม่ใช่แค่ซ่อนปุ่มใน UI)1
GET/hr/attendanceดึงประวัติเวลาเข้า-ออกงาน (filter: employee_id, date_from, date_to, scope=my_team) — ดึงจาก attendance — scope=my_team บังคับกรองเฉพาะพนักงานในทีมของผู้เรียก ใช้โดยหน้า "ทีมของฉัน"1
POST/hr/piece-work-recordsบันทึกผลงานตามชิ้น/หน่วย — บันทึกลง piece_work_record (อ้างอิง employee_id จาก employee, cost_center_id จาก cost_center ของโมดูลบัญชีและการเงิน, รับ quantity_completed จากโมดูลทะเบียนสัตว์หรือการเก็บเกี่ยว)1
GET/hr/piece-work-recordsดึงประวัติผลงานตามชิ้น/หน่วย — ดึงจาก piece_work_record1
POST/hr/leave-requestsยื่นใบลา — บันทึกลง leave_request (อ้างอิง employee_id จาก employee) (รับ attachment_url ได้ถ้ามีไฟล์แนบ)1
POST/hr/leave-requests/{id}/approveอนุมัติ/ปฏิเสธใบลา — บันทึกลง leave_request (อ้างอิง approved_by จาก user ของโมดูลผู้ใช้งานและสิทธิ์การเข้าถึง) — ถ้าผู้เรียกเป็นหัวหน้างาน ระบบต้องปฏิเสธถ้าใบลานั้นไม่ใช่ของพนักงานในทีมที่ตนดูแล1

POST/hr/payroll-runs/{id}/approveอนุมัติรอบเงินเดือน — บันทึกลง payroll_run1
POST/hr/payroll-runs/{id}/postปิดรอบและส่งข้อมูลเข้าบัญชี — บันทึกลง payroll_run และส่งข้อมูลไปสร้าง journal entry ที่โมดูลบัญชีและการเงิน ผ่าน /accounting/journal-entries/from-source (อ้างอิง cost_center_id จาก payroll_run_line)1
GET/hr/reports/labor-cost-by-cost-centerต้นทุนแรงงานแยกตามศูนย์ต้นทุน — ดึงจาก payroll_run_line (อ้างอิง cost_center จากโมดูลบัญชีและการเงิน)1
POST/hr/shift-schedulesจัดตารางกะทำงานล่วงหน้า — บันทึกลง shift_schedule (ยังไม่มี entity นี้ในสเปกนี้ ต้องเพิ่ม)2

Business Rules & Formulas

6. สูตรคำนวณและกฎทางธุรกิจ (Business Rules & Formulas)

ตรรกะที่ dev ต้อง implement จริงเบื้องหลัง entity/endpoint ด้านบน

ค่าแรงตามผลงาน (Piece Rate Pay)

Phase 1

รวมทุกบันทึกผลงานของพนักงานในรอบเงินเดือนนั้น

piece_pay(employee, period) =
  SUM( quantity_completed × rate_per_unit )
  ต่อทุก piece_work_record ของพนักงานในรอบนั้น

ค่าล่วงเวลา (Overtime Pay)

Phase 1

อัตราต่อชั่วโมงคำนวณจากฐานค่าจ้างตามประเภทการจ้าง

hourly_rate =
  monthly: base_wage / standard_hours_per_month
  daily_rate: base_wage / 8

overtime_pay = overtime_hours × hourly_rate × ot_multiplier
  (ot_multiplier ตัวอย่าง: 1.5 วันทำงานปกติ, 3.0 วันหยุด)

เงินได้รวม (Gross Pay)

Phase 1

รวมทุกองค์ประกอบเงินได้ก่อนหักภาษี/ประกันสังคม

gross_pay = base_wage_for_period
          + overtime_pay
          + piece_pay
          - unpaid_leave_deduction

หักวันลาไม่มีสิทธิ์ (Unpaid Leave Deduction)

Phase 1

ใช้กับพนักงานรายเดือนที่ลาเกินสิทธิ์หรือลาแบบไม่รับค่าจ้าง

daily_rate_equiv = base_wage / working_days_in_period

unpaid_leave_deduction =
  unpaid_leave_days × daily_rate_equiv

หักประกันสังคม (Social Security Deduction)

Phase 2

คำนวณจากฐานเงินได้ที่ไม่เกินเพดานตามกฎหมาย

social_security_deduction =
  MIN(gross_pay, ceiling_wage) × ss_rate

หมายเหตุ: ceiling_wage และ ss_rate เปลี่ยนแปลงได้ตามประกาศสำนักงานประกันสังคม ต้องตั้งเป็นค่าปรับได้ในระบบ ไม่ hardcode และควรตรวจสอบอัตราปัจจุบันกับฝ่ายบุคคล/สำนักงานบัญชีก่อนใช้งานจริง

หักภาษี ณ ที่จ่าย (Withholding Tax Deduction)

Phase 2

คำนวณตามอัตราภาษีเงินได้บุคคลธรรมดาแบบขั้นบันได (progressive) จากเงินได้สุทธิทั้งปีเทียบเป็นรายงวด แล้วยอดสะสมทั้งปีต้องยื่นแบบ ภ.ง.ด.1 (หัก ณ ที่จ่ายเงินเดือน) ที่โมดูลบัญชีทุกเดือน

annualized_income = gross_pay × pay_periods_per_year
tax_annual = progressive_tax_table(annualized_income - deductions)
tax_deduction = tax_annual / pay_periods_per_year

หมายเหตุ: ตารางอัตราภาษีขั้นบันไดและค่าลดหย่อนเปลี่ยนแปลงได้ตามประกาศกรมสรรพากร ต้องตั้งเป็นค่าปรับได้ในระบบ ไม่ hardcode และควรให้สำนักงานบัญชียืนยันก่อนใช้งานจริง — ยอด tax_deduction สะสมของทุกคนในรอบต้องส่งไปสร้าง tax_document (doc_type = ภ.ง.ด.1, period = งวดนี้) ที่โมดูลบัญชีตอน post payroll_run เดียวกับที่โพสต์ journal entry ค่าแรง

เงินได้สุทธิ (Net Pay)

Phase 1

ยอดที่จ่ายจริงให้พนักงานหลังหักทุกรายการ

net_pay = gross_pay
        - social_security_deduction
        - tax_deduction
Screens

7. หน้าจอที่ต้องมี (Screens/Pages)

รายชื่อหน้าจอที่ต้องมีจริงในโมดูลนี้ พร้อมส่วนประกอบหลักของแต่ละหน้า — ใช้เป็น checklist ออกแบบ UI ต่อได้ตรง ๆ ไม่ต้องนั่งไล่จากฟังก์ชัน/entity เอง

ทะเบียนตำแหน่งงาน (Positions) Phase 1

จัดการรายชื่อตำแหน่งงานทั้งหมดในฟาร์มก่อนผูกกับพนักงาน

  • ตารางรายการ: title, department, is_active
  • ตัวกรอง: department, is_active
  • ปุ่ม "เพิ่มตำแหน่งใหม่" — ฟอร์มคีย์ title, department
  • ปุ่มปิดใช้งานตำแหน่ง (is_active=false) พร้อมเตือนถ้ามี employee.position_id ผูกอยู่

ทะเบียนพนักงาน (Employee Directory) Phase 1

ดูและจัดการข้อมูลพนักงานทุกคน ทั้งประจำและรายวัน

  • ตารางรายการ: employee_code, name, position_id, employment_type, wage_type, is_active
  • ตัวกรอง: position_id, employment_type, wage_type, is_active
  • ปุ่ม "เพิ่มพนักงานใหม่" — ฟอร์มคีย์ employee_code, name, position_id, employment_type, wage_type, base_wage, default_cost_center_id, social_security_no
  • หน้ารายละเอียดพนักงาน 1 คน พร้อมปุ่มแก้ไข/ปิดใช้งาน (PATCH /hr/employees/{id})

บันทึกเวลาเข้า-ออกงาน (Attendance) Phase 1

คีย์เวลาเข้า-ออกงานรายวันของพนักงานทั้งฟาร์ม — อยู่ในเมนู HR สำหรับเจ้าหน้าที่ HR/ธุรการเท่านั้น หัวหน้างานที่ต้องการบันทึกเฉพาะทีมตนเองให้ใช้เมนู "ทีมของฉัน" แทน

  • ตารางรายการ: work_date, employee_id, cost_center_id, clock_in, clock_out, hours_worked, overtime_hours
  • ตัวกรอง: employee_id, date_from, date_to, cost_center_id
  • ปุ่ม "บันทึกเวลา" — ฟอร์มเลือกพนักงาน + คีย์ clock_in/clock_out หรือคำนวณ hours_worked/overtime_hours อัตโนมัติ

บันทึกผลงานตามชิ้น/หน่วย (Piece Work Records) Phase 1

คีย์ปริมาณผลงานจริงต่อคนต่อวัน สำหรับพนักงานที่จ้างแบบ piece_rate

  • ตารางรายการ: work_date, employee_id, cost_center_id, task_type, quantity_completed, rate_per_unit
  • ตัวกรอง: employee_id, cost_center_id, task_type, date_from, date_to
  • ปุ่ม "บันทึกผลงาน" — ฟอร์มเลือกพนักงาน + cost_center + task_type + คีย์ quantity_completed (rate_per_unit ดึงจาก employee.base_wage ให้ แก้ไขได้)

ใบลาและอนุมัติ (Leave Requests) Phase 1

ภาพรวมใบลาทั้งฟาร์ม — อยู่ในเมนู HR สำหรับเจ้าหน้าที่ HR/ธุรการตรวจสอบ/อนุมัติซ้ำได้ทุกใบ หัวหน้างานที่ต้องการอนุมัติเฉพาะทีมตนเองให้ใช้เมนู "ทีมของฉัน" แทน

  • ตารางรายการ: employee_id, leave_type, start_date, end_date, status พร้อม badge สีตามสถานะ
  • ตัวกรอง: employee_id, leave_type, status
  • ปุ่ม "ยื่นใบลาใหม่" — ฟอร์มเลือก leave_type, start_date/end_date
  • ฟอร์มมีช่องอัปโหลดไฟล์แนบ (attachment_url) ไม่บังคับ เช่น ใบรับรองแพทย์
  • ปุ่ม "อนุมัติ/ปฏิเสธ" ในหน้ารายละเอียด (บันทึก approved_by, เปลี่ยน status)

รายงานวันลาคงเหลือ (Leave Balance Report) Phase 1

สรุปวันลาที่ใช้ไปและคงเหลือของพนักงานแต่ละคน

  • ตารางรายการ: employee_id, name, leave_type, วันลาที่ใช้ไป, วันลาคงเหลือ
  • ตัวกรอง: employee_id, position_id, leave_type
  • ปุ่ม "ส่งออกรายงาน" (CSV/Excel) สำหรับ HR ใช้ตรวจสอบทั้งฟาร์ม

ทีมของฉัน — ภาพรวมทีมวันนี้ (My Team Overview) Phase 1

หน้าแรกของเมนู "ทีมของฉัน" สำหรับหัวหน้างาน/ผู้จัดการฟาร์ม-แปลง เห็นเฉพาะพนักงานในทีมที่ตนดูแล — คนละหน้ากับเมนู HR ที่สงวนไว้สำหรับเจ้าหน้าที่ HR/ธุรการ

  • การ์ดสรุป: จำนวนใบลารอฉันอนุมัติ, จำนวนคนในทีมที่ลาวันนี้, จำนวนคนที่ยังไม่คีย์เวลาเข้างานวันนี้
  • รายชื่อลูกทีมวันนี้พร้อมสถานะ: เข้างานแล้ว/ยังไม่เข้างาน/ลาวันนี้ — คลิกชื่อไปหน้ารายละเอียดพนักงาน (อ่านอย่างเดียว ไม่แก้ทะเบียนพนักงานได้ ต้องผ่าน HR)
  • ทีมที่แสดงมาจาก employee ที่มี default_cost_center_id อยู่ในความดูแลของผู้เรียก (backend กรอง ไม่ใช่ query parameter ที่ผู้ใช้เลือกเองได้)

ทีมของฉัน — คิวอนุมัติใบลา (My Team Leave Approval) Phase 1

อนุมัติ/ปฏิเสธใบลาเฉพาะของลูกทีมตนเอง แยกจากหน้า "ใบลาและอนุมัติ" ของ HR ที่เห็นทั้งฟาร์ม

  • ตารางกรองอัตโนมัติเฉพาะ status=pending ของทีมตนเอง (GET /hr/leave-requests?scope=my_team) — ไม่ต้องเลือก employee_id เอง
  • คอลัมน์: employee_id, leave_type, start_date, end_date, จำนวนวัน, ไฟล์แนบ (ถ้ามี)
  • ปุ่ม "อนุมัติ"/"ปฏิเสธ" ต่อแถวโดยตรง ไม่ต้องเข้าหน้ารายละเอียด (POST /hr/leave-requests/{id}/approve)
  • แท็บ "ประวัติ" ดูใบลาของทีมที่อนุมัติ/ปฏิเสธไปแล้วย้อนหลังได้

ทีมของฉัน — บันทึกเวลาเข้า-ออกงาน (My Team Attendance) Phase 1

คีย์เวลาเข้า-ออกงานเฉพาะลูกทีมตนเองประจำวัน แยกจากหน้า Attendance ของ HR ที่เห็นทั้งฟาร์ม

  • ตารางรายชื่อลูกทีมของวันนี้ (หรือวันที่เลือก) พร้อมช่องคีย์ clock_in/clock_out แก้ได้ในตารางเลยไม่ต้องเปิดฟอร์มแยก
  • hours_worked/overtime_hours คำนวณอัตโนมัติทันทีที่คีย์ครบ
  • ตัวกรองย้อนหลัง: date_from, date_to (ยังคง scope เฉพาะทีมตนเองเสมอ)

รอบเงินเดือน (Payroll Runs) Phase 1

รายการรอบเงินเดือนทั้งหมด ใช้ติดตามสถานะแต่ละงวด

  • ตารางรายการ: period, status (draft/calculated/approved/paid/posted)
  • ตัวกรอง: status, period
  • ปุ่ม "เริ่มรอบเงินเดือนใหม่" (POST /hr/payroll-runs) — คีย์ period

รายละเอียดรอบเงินเดือน (Payroll Run Detail) Phase 1

ดูและดำเนินการรอบเงินเดือนหนึ่งรอบ ทีละบรรทัดต่อพนักงาน

  • ตารางบรรทัด (payroll_run_line): employee_id, cost_center_id, gross_pay, social_security_deduction, tax_deduction, net_pay
  • ตัวกรอง: cost_center_id, employee_id
  • ปุ่ม "คำนวณ" (POST .../calculate), "อนุมัติ" (POST .../approve), "ปิดรอบและส่งเข้าบัญชี" (POST .../post) — ปุ่มแสดง/ซ่อนตาม status ปัจจุบัน

สลิปเงินเดือนของฉัน (My Payslip) Phase 1

หน้า self-service ให้พนักงานทั่วไปดูสลิปเงินเดือนและวันลาคงเหลือของตัวเอง

  • รายละเอียด payroll_run_line ของตัวเองต่องวด: gross_pay, social_security_deduction, tax_deduction, net_pay
  • สรุปวันลาคงเหลือของตัวเอง (จาก /hr/reports/leave-balance กรองเฉพาะ employee_id ตัวเอง)
  • ตัวกรอง: period (เลือกดูงวดก่อนหน้า)

รายงานต้นทุนแรงงานตามศูนย์ต้นทุน (Labor Cost by Cost Center) Phase 1

สรุปค่าแรงจริงที่เกิดขึ้นแยกตามพื้นที่/รุ่นเลี้ยง/รอบปลูก สำหรับเจ้าของฟาร์มและ HR

  • ตารางรายการ: cost_center_id, ยอดรวม gross_pay, net_pay ต่องวด
  • ตัวกรอง: cost_center_id, period, date_from, date_to
  • กราฟแท่งเทียบต้นทุนแรงงานระหว่างศูนย์ต้นทุน

จัดตารางกะทำงาน (Shift Scheduling) Phase 2

จัดตารางกะทำงานล่วงหน้าให้พนักงานแต่ละคน/ทีม

  • ปฏิทินรายสัปดาห์/รายเดือนแสดงกะของพนักงานแต่ละคน
  • ตัวกรอง: cost_center_id, employee_id, ช่วงวันที่
  • ปุ่ม "สร้างตารางกะ" (POST /hr/shift-schedules) — เลือกพนักงาน + วัน/เวลา

เทียบค่าแรงจริงกับงบประมาณ (Labor Budget vs Actual) Phase 2

เทียบค่าแรงจริงต่อศูนย์ต้นทุนกับงบประมาณที่ตั้งไว้จากโมดูลบัญชีและการเงิน

  • ตารางรายการ: cost_center_id, งบประมาณค่าแรง, ค่าแรงจริง (gross_pay รวม), ส่วนต่าง %
  • ตัวกรอง: cost_center_id, period
  • ไฮไลต์แถวที่เกินงบด้วยสี (ใช้ phase-tag style เดียวกับสถานะ)

วิเคราะห์ประสิทธิภาพแรงงาน (Labor Productivity Analytics) Phase 3

วิเคราะห์ผลงานต่อคน/ต่อชั่วโมง จาก piece_work_record และ attendance

  • กราฟ quantity_completed ต่อ hours_worked แยกตาม employee_id, task_type
  • ตัวกรอง: cost_center_id, task_type, ช่วงวันที่
  • จัดอันดับพนักงานตามผลงานเฉลี่ยต่อชั่วโมง

พยากรณ์ความต้องการแรงงาน (Labor Demand Forecast) Phase 3

คาดการณ์จำนวนแรงงานที่ต้องใช้ตามฤดูกาล/รอบผลิตล่วงหน้า

  • กราฟแนวโน้ม attendance/piece_work_record ย้อนหลังเทียบรอบผลิตที่จะมาถึง
  • ตัวกรอง: cost_center_id, ประเภทรอบผลิต
  • ตัวเลขแนะนำจำนวนแรงงานที่ควรเตรียมต่อ cost_center
