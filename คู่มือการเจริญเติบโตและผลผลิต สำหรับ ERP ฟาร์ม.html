โมดูลการเจริญเติบโตและผลผลิต (Growth & Yield)

สเปกสำหรับเริ่มพัฒนาได้ทันที ครอบคลุมขอบเขตและจุดเชื่อมต่อกับโมดูลอื่น ฟังก์ชันหลักแยก MVP กับที่เพิ่มทีหลังได้ โครงสร้างฐานข้อมูล API หลักที่ต้องมี สิทธิ์การเข้าถึงตามบทบาท และสูตรคำนวณ/กฎทางธุรกิจ

ส่วนหนึ่งของ คู่มือ ERP สำหรับธุรกิจฟาร์ม อัปเดต 18 ก.ค. 2569

Scope & Integration

1. ขอบเขตและจุดเชื่อมต่อ (Scope & Integration Points)

โมดูลนี้ครอบคลุมสัตว์สองแบบ: สัตว์ที่เลี้ยงเพื่อน้ำหนัก/เนื้อ (ติดตามน้ำหนัก+ADG) และสัตว์ที่ให้ผลผลิตต่อเนื่อง เช่น วัวนม ไก่ไข่ (ติดตามผลผลิตรายวัน) เป็นแหล่งข้อมูลน้ำหนักหลักที่โมดูลอาหารสัตว์ใช้คำนวณ FCR

อยู่ในขอบเขต

  • บันทึกน้ำหนักตัว (Weight Record)
  • คำนวณอัตราการเติบโตต่อวัน (ADG)
  • บันทึกผลผลิตรายวัน (Daily Yield) — นม ไข่ หรือเนื้อ
  • เป้าหมายน้ำหนัก/ผลผลิตตามมาตรฐาน
  • แจ้งเตือนเมื่อสัตว์/ฝูงถึงเกณฑ์พร้อมขาย

อยู่นอกขอบเขต (รับ/ส่งข้อมูลกับโมดูลอื่น)

  • ทะเบียนสัตว์/ฝูง — รับจาก ทะเบียนสัตว์
  • น้ำหนักแรกเกิดตั้งต้น — รับจาก ผสมพันธุ์และตั้งท้อง
  • น้ำหนักที่เพิ่มขึ้นสำหรับคำนวณ FCR — ส่งต่อให้ อาหารสัตว์
  • การคัดแยกและขายจริงเมื่อถึงเกณฑ์ — ส่งต่อให้ คัดแยกและส่งขาย
  • ผลผลิตนม/ไข่ที่พร้อมขาย — ส่งต่อให้ คลังสินค้า/สต็อก
โมดูลที่เกี่ยวข้องเหตุการณ์สิ่งที่การเจริญเติบโตฯ ต้องทำPhase
ทะเบียนสัตว์มีสัตว์/ฝูงพร้อมติดตามอ้างอิง animal_id/animal_group_idPhase 1
ผสมพันธุ์และตั้งท้องมีน้ำหนักแรกเกิดตั้งต้นใช้เป็นจุดเริ่มต้นคำนวณ ADGPhase 1
การเจริญเติบโตฯ (ตัวเอง) → อาหารสัตว์มีน้ำหนักที่เพิ่มขึ้นล่าสุดให้ total_weight_gain ไปคำนวณ FCRPhase 1
การเจริญเติบโตฯ (ตัวเอง) → คัดแยกและส่งขายสัตว์/ฝูงถึงเกณฑ์น้ำหนักพร้อมขายแจ้งเตือนความพร้อมPhase 1
การเจริญเติบโตฯ (ตัวเอง) → คลังสินค้า/สต็อกบันทึกผลผลิตนม/ไข่รายวันสร้างสต็อกสินค้าสำเร็จรูปPhase 1
Core Functions

2. ฟังก์ชันหลัก (Core Functions)

แยกชัดว่าอะไรต้องใช้งานได้ตั้งแต่วันแรก (MVP) และอะไรเพิ่มทีหลังได้โดยไม่กระทบการติดตามพื้นฐาน

MVP — ต้องมีวันแรก Phase 1

  • บันทึกน้ำหนักตัวเป็นระยะ
  • คำนวณอัตราการเติบโตต่อวัน (ADG) อัตโนมัติ
  • บันทึกผลผลิตรายวัน (นม/ไข่/เนื้อ) ต่อตัว/ฝูง
  • ตั้งเป้าหมายน้ำหนัก/ผลผลิตตามมาตรฐานต่อช่วงอายุ
  • แจ้งเตือนเมื่อสัตว์/ฝูงถึงเกณฑ์น้ำหนักพร้อมขาย
  • ดูกราฟการเติบโตเทียบเป้าหมายมาตรฐาน

เพิ่มทีหลังได้

  • เปรียบเทียบอัตราการเติบโต/ผลผลิตระหว่างฝูงPhase 2
  • เชื่อมเครื่องชั่งอัตโนมัติ/เซนเซอร์บันทึกน้ำหนักโดยตรงPhase 2
  • พยากรณ์วันที่จะถึงน้ำหนักเป้าหมายจากแนวโน้มที่ผ่านมาPhase 2
  • วิเคราะห์ปัจจัยที่กระทบการเติบโต (อาหาร/สุขภาพ/สภาพแวดล้อม)Phase 3
  • พยากรณ์ผลผลิตล่วงหน้าทั้งฝูงจากข้อมูลย้อนหลังPhase 3
Database

3. ฐานข้อมูล (Database)

แต่ละเอนทิตีคือ 1 ตารางในฐานข้อมูล พร้อมคำอธิบายว่าแทนอะไรในโลกจริง และแต่ละฟิลด์เก็บอะไร ชนิดข้อมูลแบบไหน

weight_record Phase 1

บันทึกน้ำหนัก — บันทึกน้ำหนักตัวสัตว์ที่ชั่งได้เป็นระยะ ใช้คำนวณอัตราการเติบโตและเป็นข้อมูลหลักที่โมดูลอาหารสัตว์ดึงไปใช้คำนวณ FCR

ความสัมพันธ์: ผูกกับ animal/animal_group จากโมดูลทะเบียนสัตว์

ฟิลด์ชนิดข้อมูลเก็บอะไร
idเลขอ้างอิง/UUID (PK)รหัสประจำแถวนี้ ไม่ซ้ำกัน สร้างอัตโนมัติ
animal_id / animal_group_idเลขอ้างอิง (FK)ชั่งน้ำหนักสัตว์ตัวไหนหรือฝูงไหน
weigh_dateวันที่ (date)วันที่ชั่งน้ำหนัก
weight_valueตัวเลข (decimal)น้ำหนักที่ชั่งได้ (เฉลี่ยต่อตัว ถ้าเป็นการชั่งแทนทั้งฝูง)
sample_sizeตัวเลข (integer, ว่างได้)จำนวนตัวที่สุ่มชั่ง ถ้าเป็นการชั่งแทนทั้งฝูงแทนการชั่งทุกตัว

daily_yield_record Phase 1

บันทึกผลผลิตรายวัน — บันทึกผลผลิตที่เก็บได้รายวัน เช่น ปริมาณนม จำนวนไข่ ใช้กับสัตว์ที่ให้ผลผลิตต่อเนื่อง ไม่ใช่แค่ชั่งน้ำหนักครั้งเดียวตอนขาย

ความสัมพันธ์: ผูกกับ animal/animal_group เป็นต้นทางสร้างสต็อกสินค้าสำเร็จรูปในโมดูลคลังสินค้า

ฟิลด์ชนิดข้อมูลเก็บอะไร
idเลขอ้างอิง/UUID (PK)รหัสประจำแถวนี้ ไม่ซ้ำกัน สร้างอัตโนมัติ
animal_id / animal_group_idเลขอ้างอิง (FK)ผลผลิตนี้มาจากสัตว์ตัวไหนหรือฝูงไหน
record_dateวันที่ (date)วันที่เก็บผลผลิต
yield_typeตัวเลือกคงที่ (enum)ประเภทผลผลิต เลือกได้เฉพาะ: milk, egg, meat
quantityตัวเลข (decimal)ปริมาณที่เก็บได้จริงในวันนั้น
unitข้อความ (text)หน่วยนับ เช่น ลิตร, ฟอง, กก.

growth_target_standard Phase 1

เป้าหมายมาตรฐาน — กำหนดน้ำหนัก/ผลผลิตที่ควรได้ตามช่วงอายุของสัตว์แต่ละชนิด ใช้เทียบกับผลจริงเพื่อดูว่าฝูงโตตามเกณฑ์หรือไม่

ความสัมพันธ์: ผูกกับ species (จากโมดูลทะเบียนสัตว์)

ฟิลด์ชนิดข้อมูลเก็บอะไร
idเลขอ้างอิง/UUID (PK)รหัสประจำแถวนี้ ไม่ซ้ำกัน สร้างอัตโนมัติ
speciesข้อความ/ตัวเลือกคงที่ (enum)เป้าหมายนี้ใช้กับสัตว์ชนิดไหน
age_daysตัวเลข (integer)อายุเป็นวันที่เป้าหมายนี้ใช้อ้างอิง
target_weightตัวเลข (decimal, ว่างได้)น้ำหนักเป้าหมาย ณ อายุนั้น
target_daily_yieldตัวเลข (decimal, ว่างได้)ผลผลิตรายวันเป้าหมาย ณ อายุนั้น สำหรับสัตว์ให้ผลผลิตต่อเนื่อง

market_readiness_alert Phase 1

การแจ้งเตือนพร้อมขาย — แจ้งเตือนเมื่อสัตว์/ฝูงถึงเกณฑ์น้ำหนักที่กำหนดว่าพร้อมส่งขาย

ความสัมพันธ์: ผูกกับ animal/animal_group ใช้ส่งต่อให้โมดูลคัดแยกและส่งขายตัดสินใจ

ฟิลด์ชนิดข้อมูลเก็บอะไร
idเลขอ้างอิง/UUID (PK)รหัสประจำแถวนี้ ไม่ซ้ำกัน สร้างอัตโนมัติ
animal_id / animal_group_idเลขอ้างอิง (FK)แจ้งเตือนนี้เกี่ยวกับสัตว์ตัวไหนหรือฝูงไหน
triggered_dateวันที่ (date)วันที่ระบบตรวจพบว่าถึงเกณฑ์
current_weight / target_weightตัวเลข (decimal)น้ำหนักปัจจุบันเทียบกับเป้าหมายที่กำหนดว่าพร้อมขาย
statusตัวเลือกคงที่ (enum)สถานะ เลือกได้เฉพาะ: pending, acknowledged, sold

Business Rules & Formulas

6. สูตรคำนวณและกฎทางธุรกิจ (Business Rules & Formulas)

ตรรกะที่ dev ต้อง implement จริงเบื้องหลัง entity/endpoint ด้านบน

คำนวณอัตราการเติบโตต่อวัน (ADG)

Phase 1

คำนวณระหว่างการชั่งสองครั้งล่าสุด

ADG =
  (current_weight - previous_weight)
  / (current_weigh_date - previous_weigh_date)

เทียบน้ำหนัก/ผลผลิตจริงกับเป้าหมาย

Phase 1

ใช้ดูว่าฝูงโตตามแผนหรือช้า/เร็วกว่าที่ควร

weight_variance_pct =
  (actual_weight - target_weight) / target_weight × 100

แจ้งเตือนพร้อมขาย (Market Readiness Trigger)

Phase 1

ทำงานอัตโนมัติทุกครั้งที่มีการบันทึกน้ำหนักใหม่

ถ้า current_weight >= target_weight
   (ของช่วงอายุที่กำหนดว่าพร้อมขาย)

-> สร้าง market_readiness_alert (status = pending)

ผลผลิตสะสมต่อรอบ (Cumulative Yield per Cycle)

Phase 1

ใช้สรุปผลผลิตรวมของฝูงในแต่ละรอบ/ช่วงเวลา

total_yield(animal_group, period) =
  SUM(daily_yield_record.quantity)
  ในช่วงเวลาที่กำหนด

พยากรณ์วันที่จะถึงน้ำหนักเป้าหมาย

Phase 2

ช่วยวางแผนวันขายล่วงหน้าจากแนวโน้มการเติบโตจริง

days_to_target =
  (target_weight - current_weight) / recent_adg

recent_adg = ADG เฉลี่ยจากการชั่ง 2-3 ครั้งล่าสุด
