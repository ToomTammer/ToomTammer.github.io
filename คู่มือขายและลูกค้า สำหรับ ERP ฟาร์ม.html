โมดูลขายและลูกค้า (Sales & CRM)

สเปกสำหรับเริ่มพัฒนาได้ทันที ครอบคลุมขอบเขตและจุดเชื่อมต่อกับโมดูลอื่น ฟังก์ชันหลักแยก MVP กับที่เพิ่มทีหลังได้ โครงสร้างฐานข้อมูล API หลักที่ต้องมี สิทธิ์การเข้าถึงตามบทบาท และสูตรคำนวณ/กฎทางธุรกิจ

ส่วนหนึ่งของ คู่มือ ERP สำหรับธุรกิจฟาร์ม อัปเดต 18 ก.ค. 2569
1. ขอบเขตและจุดเชื่อมต่อ (Scope & Integration) 2. ฟังก์ชันหลัก (Core Functions) 3. ฐานข้อมูล (Database) 4. API 5. สิทธิ์การเข้าถึง (Roles) 6. สูตรคำนวณ (Formulas)
Scope & Integration

1. ขอบเขตและจุดเชื่อมต่อ (Scope & Integration Points)

โมดูลนี้ครอบคลุมตั้งแต่ตกลงราคากับลูกค้าจนถึงส่งของจริง ส่วนการตัดสต็อกและออกใบแจ้งหนี้ให้โมดูลปลายทางทำต่อ ไม่ต้องคีย์ซ้ำ

อยู่ในขอบเขต

  • ฐานข้อมูลลูกค้า (Customer Master) — พ่อค้าคนกลาง โมเดิร์นเทรด ผู้ส่งออก
  • ใบสั่งขาย (Sales Order) และการคัดเกรด/ตั้งราคา
  • ใบส่งของ (Delivery Note) และการชั่งน้ำหนักจริง
  • ประวัติราคาขายย้อนหลังต่อลูกค้า
  • การจองผลผลิตล่วงหน้า (Forward Sale)

อยู่นอกขอบเขต (รับ/ส่งข้อมูลกับโมดูลอื่น)

  • การตัดสต็อกสินค้าสำเร็จรูปเมื่อขาย — ส่งต่อให้ คลังสินค้า/สต็อก
  • การสร้างใบแจ้งหนี้ลูกหนี้และบันทึกบัญชี — ส่งต่อให้ บัญชีและการเงิน
  • ข้อมูลผลผลิตพร้อมขาย (น้ำหนัก/เกรด/ปริมาณ) — รับจาก ปศุสัตว์ / พืชไร่-พืชสวน
  • วงเงินเครดิตที่อนุมัติ/ยอดค้างชำระ — รับจาก บัญชีและการเงิน
โมดูลที่เกี่ยวข้องเหตุการณ์สิ่งที่ขายต้องทำPhase
ปศุสัตว์ / พืชไร่-พืชสวนบันทึกผลผลิตพร้อมขาย (น้ำหนัก/เกรด/ปริมาณ)เปิดสต็อกสินค้าสำเร็จรูปให้ขายได้Phase 1
ขาย (ตัวเอง) → คลังสินค้า/สต็อกออกใบส่งของและปิดคำสั่งขายแจ้งตัดสต็อกสินค้าสำเร็จรูปตาม FIFOPhase 1
ขาย (ตัวเอง) → บัญชีและการเงินปิดใบส่งของส่งข้อมูลให้สร้าง AR invoicePhase 1
บัญชีและการเงินลูกค้ามียอดค้างชำระเกินวงเงินตรวจสอบวงเงินเครดิตก่อนยืนยันคำสั่งขายใหม่Phase 2
ตลาดสินค้าเกษตร (ภายนอก)ราคาตลาดอ้างอิงเปลี่ยนแปลงรายวันใช้ช่วยตั้งราคาขายตามเกรดPhase 2
ปศุสัตว์ / พืชไร่-พืชสวนมีแผนเก็บเกี่ยว/จับขายล่วงหน้ารับจองผลผลิตล่วงหน้าจากลูกค้าPhase 2
Core Functions

2. ฟังก์ชันหลัก (Core Functions)

แยกชัดว่าอะไรต้องใช้งานได้ตั้งแต่วันแรก (MVP) และอะไรเพิ่มทีหลังได้โดยไม่กระทบการขายพื้นฐาน

MVP — ต้องมีวันแรก Phase 1

  • จัดการฐานข้อมูลลูกค้า (สร้าง/แก้ไข/ปิดใช้งาน)
  • สร้าง/แก้ไขใบสั่งขายพร้อมรายการสินค้า
  • คัดเกรดและคำนวณราคาตามน้ำหนัก/เกรด/ความชื้น ณ วันขาย
  • ออกใบส่งของ ผูกกับใบสั่งขาย และแจ้งคลังตัดสต็อก
  • ติดตามสถานะคำสั่งขายตลอดวงจร (draft ถึง invoiced)
  • ดูประวัติการขาย/ราคาย้อนหลังต่อลูกค้า
  • ยกเลิกใบสั่งขายที่ยังไม่ส่งของ

เพิ่มทีหลังได้

  • รับจองผลผลิตล่วงหน้า (forward sale) พร้อมเงินมัดจำPhase 2
  • เชื่อมราคาตลาดอ้างอิงรายวันช่วยตั้งราคาขายPhase 2
  • ตรวจสอบวงเงินเครดิตก่อนยืนยันคำสั่งขายPhase 2
  • ส่วนลดตามปริมาณ/ลูกค้าประจำPhase 2
  • วิเคราะห์ลูกค้า (ปริมาณซื้อ/ตรงเวลาชำระ/ความถี่)Phase 3
  • พยากรณ์ยอดขายจากแผนการผลิตล่วงหน้าPhase 3
  • Portal ให้ลูกค้าดูสถานะคำสั่งซื้อของตัวเองPhase 3
Database

3. ฐานข้อมูล (Database)

แต่ละเอนทิตีคือ 1 ตารางในฐานข้อมูล พร้อมคำอธิบายว่าแทนอะไรในโลกจริง และแต่ละฟิลด์เก็บอะไร ชนิดข้อมูลแบบไหน

customer Phase 1

ลูกค้า — ฐานข้อมูลผู้ซื้อผลผลิตของฟาร์ม เช่น พ่อค้าคนกลาง โมเดิร์นเทรด ผู้ส่งออก โรงงานแปรรูป

ความสัมพันธ์: ผูกกับ sales_order ที่สร้างขึ้น และกับ ar_invoice ในโมดูลบัญชีและการเงิน

ฟิลด์ชนิดข้อมูลเก็บอะไร
idเลขอ้างอิง/UUID (PK)รหัสประจำแถวนี้ ไม่ซ้ำกัน สร้างอัตโนมัติ
customer_codeข้อความ (text)รหัสลูกค้าที่ใช้อ้างอิงภายในระบบ
nameข้อความ (text)ชื่อลูกค้า/บริษัท
customer_typeตัวเลือกคงที่ (enum)ประเภทลูกค้า เลือกได้เฉพาะ: middleman, modern_trade, exporter, processor, other
contact_phone / contact_addressข้อความ (text)ช่องทางติดต่อลูกค้า
credit_limitตัวเลข (decimal)วงเงินเครดิตสูงสุดที่ให้ซื้อค้างจ่ายได้
payment_terms_daysตัวเลข (integer)จำนวนวันเครดิตที่ตกลงกัน
is_activeจริง/เท็จ (boolean)ยังซื้อขายกันอยู่ไหม

sales_order + sales_order_line Phase 1

ใบสั่งขาย — ข้อตกลงซื้อขายกับลูกค้าก่อนส่งของจริง sales_order_line คือรายการสินค้าแต่ละบรรทัดพร้อมข้อมูลเกรด/น้ำหนักที่ใช้คำนวณราคา

ความสัมพันธ์: ผูกกับ customer, อ้างอิงผลผลิตจากโมดูลปศุสัตว์/พืช, และเป็นต้นทางให้ delivery_note กับ ar_invoice

ฟิลด์ชนิดข้อมูลเก็บอะไร
idเลขอ้างอิง/UUID (PK)รหัสประจำแถวนี้ ไม่ซ้ำกัน สร้างอัตโนมัติ
so_noข้อความ (text)เลขที่ใบสั่งขาย
customer_idเลขอ้างอิง (FK → customer)ขายให้ลูกค้ารายไหน
order_dateวันที่ (date)วันที่ตกลงซื้อขาย
statusตัวเลือกคงที่ (enum)สถานะ เลือกได้เฉพาะ: draft, confirmed, delivered, invoiced, cancelled
(line) idเลขอ้างอิง/UUID (PK)รหัสประจำบรรทัดนี้ ไม่ซ้ำกัน สร้างอัตโนมัติ
(line) sales_order_idเลขอ้างอิง (FK → sales_order)บรรทัดนี้เป็นของใบสั่งขายไหน
(line) item_idเลขอ้างอิง (FK → รายการสินค้าในคลัง)ขายสินค้าอะไร
(line) gradeข้อความ/ตัวเลือกคงที่ (enum)เกรดที่ตกลงซื้อขาย เช่น A, B, C
(line) weight / moistureตัวเลข (decimal)น้ำหนักและความชื้นโดยประมาณที่ใช้ตั้งราคาตอนสั่งขาย
(line) quantity / unit_priceตัวเลข (decimal)ปริมาณและราคาต่อหน่วยที่ตกลง

delivery_note Phase 1

ใบส่งของ — เอกสารยืนยันว่าส่งสินค้าจริงให้ลูกค้าแล้ว ใช้เป็นหลักฐานตัดสต็อกและออกใบแจ้งหนี้

ความสัมพันธ์: ผูกกับ sales_order ส่งข้อมูลไปตัดสต็อกที่โมดูลคลังสินค้า และสร้าง ar_invoice ที่โมดูลบัญชี

ฟิลด์ชนิดข้อมูลเก็บอะไร
idเลขอ้างอิง/UUID (PK)รหัสประจำแถวนี้ ไม่ซ้ำกัน สร้างอัตโนมัติ
dn_noข้อความ (text)เลขที่ใบส่งของ
sales_order_idเลขอ้างอิง (FK → sales_order)ส่งของตามใบสั่งขายใบไหน
delivery_dateวันที่ (date)วันที่ส่งของจริง
delivered_byเลขอ้างอิง (FK → user)ใครเป็นคนส่ง/ชั่งของ
actual_weightตัวเลข (decimal, ว่างได้)น้ำหนักจริงตอนชั่งส่งของ อาจต่างจากที่ประเมินไว้ตอนสั่งขาย
total_amountตัวเลข (decimal)ยอดเงินรวมของใบส่งของนี้ คำนวณจาก final_amount ของทุกบรรทัด (ดูสูตรในหัวข้อ 6) แล้วบันทึกเป็นค่านิ่งตอนปิดใบส่งของ เพื่อให้ ar_invoice.total_amount ที่โมดูลบัญชีดึงไปใช้มีค่าคงที่ ไม่ต้องคำนวณซ้ำ
due_dateวันที่ (date)กำหนดชำระเงิน = delivery_date + customer.payment_terms_days คำนวณตอนปิดใบส่งของ ส่งต่อให้ ar_invoice.due_date

หมายเหตุ ปิดใบส่งของ (status ของ sales_order เปลี่ยนเป็น invoiced) จะยิง event ให้โมดูลบัญชีสร้าง ar_invoice + journal entry อัตโนมัติผ่าน POST /accounting/journal-entries/from-source (source_module = sales) โดยส่ง total_amount, due_date, customer_id, sales_order_ref ไปด้วย — ดู endpoint ด้านล่าง

price_history Phase 2

ประวัติราคาขาย — บันทึกราคาขายย้อนหลังต่อลูกค้าและสินค้า ใช้เปรียบเทียบและต่อรองราคาครั้งต่อไป

ความสัมพันธ์: ผูกกับ customer และรายการสินค้า สร้างอัตโนมัติทุกครั้งที่ปิดใบสั่งขาย

ฟิลด์ชนิดข้อมูลเก็บอะไร
idเลขอ้างอิง/UUID (PK)รหัสประจำแถวนี้ ไม่ซ้ำกัน สร้างอัตโนมัติ
customer_id / item_idเลขอ้างอิง (FK)ราคานี้เกิดขึ้นกับลูกค้ารายไหน สินค้าตัวไหน
gradeข้อความ/ตัวเลือกคงที่ (enum)เกรดของสินค้าตอนขาย
priceตัวเลข (decimal)ราคาต่อหน่วยที่ขายจริง
effective_dateวันที่ (date)วันที่ราคานี้มีผลจริง

forward_sale Phase 2

การจองผลผลิตล่วงหน้า — ลูกค้าตกลงซื้อทั้งรุ่นก่อนเก็บเกี่ยว/จับขายจริง ป้องกันความเสี่ยงหาตลาดไม่ทันตอนผลผลิตพร้อม

ความสัมพันธ์: ผูกกับ customer และ cost_center (batch จากโมดูลปศุสัตว์/พืช) ที่จองซื้อ

ฟิลด์ชนิดข้อมูลเก็บอะไร
idเลขอ้างอิง/UUID (PK)รหัสประจำแถวนี้ ไม่ซ้ำกัน สร้างอัตโนมัติ
customer_idเลขอ้างอิง (FK → customer)ลูกค้ารายไหนจองซื้อ
cost_center_idเลขอ้างอิง (FK → cost_center)จองซื้อรุ่นเลี้ยง/รอบปลูกไหน
agreed_priceตัวเลข (decimal)ราคาที่ตกลงล็อคไว้ล่วงหน้า
estimated_quantityตัวเลข (decimal)ปริมาณที่คาดว่าจะได้และตกลงซื้อ
deposit_amountตัวเลข (decimal, ว่างได้)เงินมัดจำที่รับไว้ล่วงหน้า

ราคาตามเกรด/น้ำหนัก/ความชื้น

Phase 1

ราคาฐานปรับตามคุณภาพสินค้าจริง ณ วันขาย ไม่ใช่ราคาคงที่ตายตัว

line_total = quantity × unit_price

ตัวอย่างการปรับราคาตามความชื้น:
  ราคาฐาน 30 บาท/กก.
  ถ้าความชื้น > 15% หัก 2% ต่อทุก 1% ที่เกิน

ปรับยอดจากน้ำหนักจริงตอนส่งของ

Phase 1

ใช้น้ำหนักจริงตอนชั่งส่งของคิดเงินจริง ไม่ใช่น้ำหนักที่ประเมินไว้ตอนสั่งขาย

variance_qty = delivery_note.actual_weight
             - sales_order_line.weight (ประมาณการ)

final_amount = delivery_note.actual_weight × unit_price

ตรวจสอบวงเงินเครดิต (Credit Limit Check)

Phase 2

ป้องกันไม่ให้ลูกค้าซื้อค้างจ่ายเกินวงเงินที่อนุมัติไว้

outstanding_balance(customer) =
  SUM(ar_invoice.total_amount WHERE status != paid)

outstanding_balance + new_order_amount > customer.credit_limit
  -> flag เตือน (หรือบล็อกยืนยันคำสั่งขาย
     ถ้า policy ฟาร์มกำหนดให้บล็อก)

ราคาแนะนำตามตลาดและเกรด

Phase 2

ช่วยพนักงานขายตั้งราคาตามราคาตลาดอ้างอิงรายวัน

suggested_price = market_price_ref × grade_multiplier

grade_multiplier ตัวอย่าง:
  เกรด A = 1.0
  เกรด B = 0.85
  เกรด C = 0.7

เงินมัดจำจองผลผลิตล่วงหน้า

Phase 2

ตอนส่งของจริง ออกใบแจ้งหนี้เฉพาะยอดที่เหลือ ไม่ใช่ยอดเต็ม

remaining_balance =
  (agreed_price × actual_delivered_quantity)
  - deposit_amount

-> ออก ar_invoice ด้วยยอด remaining_balance

ส่วนลดตามปริมาณ (Volume Discount)

Phase 2

ให้ราคาดีขึ้นเมื่อซื้อปริมาณมากตามช่วงที่กำหนดไว้ล่วงหน้า

quantity >= tier_threshold
  -> apply discount_pct ตาม tier ที่กำหนด

final_unit_price = unit_price × (1 - discount_pct)

หมายเหตุ: tier_threshold และ discount_pct ควรตั้งเป็นค่าปรับได้ต่อสินค้า ไม่ hardcode
