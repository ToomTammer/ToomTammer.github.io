Core Module 6/7 · Asset & Equipment — Dev-Ready Spec

โมดูลสินทรัพย์และเครื่องจักร (Asset & Equipment)

สเปกสำหรับเริ่มพัฒนาได้ทันที ครอบคลุมขอบเขตและจุดเชื่อมต่อกับโมดูลอื่น ฟังก์ชันหลักแยก MVP กับที่เพิ่มทีหลังได้ โครงสร้างฐานข้อมูล API หลักที่ต้องมี สิทธิ์การเข้าถึงตามบทบาท และสูตรคำนวณ/กฎทางธุรกิจ

ส่วนหนึ่งของ คู่มือ ERP สำหรับธุรกิจฟาร์ม อัปเดต 18 ก.ค. 2569

Scope & Integration

1. ขอบเขตและจุดเชื่อมต่อ (Scope & Integration Points)

โมดูลนี้ดูแลทรัพย์สินถาวรของฟาร์มตั้งแต่ซื้อเข้ามาจนถึงจำหน่ายออก ทั้งเรื่องซ่อมบำรุงและค่าเสื่อมราคา ไม่ทับซ้อนกับคลังสินค้าที่ดูแลของใช้สิ้นเปลือง

อยู่ในขอบเขต

  • ทะเบียนสินทรัพย์/เครื่องจักร (Asset Master)
  • แผนซ่อมบำรุงเชิงป้องกัน (Preventive Maintenance)
  • บันทึกการซ่อมบำรุงจริง ทั้งตามแผนและซ่อมฉุกเฉิน
  • ค่าเสื่อมราคา (Depreciation)
  • การจองคิวใช้เครื่องจักรร่วม

อยู่นอกขอบเขต (รับ/ส่งข้อมูลกับโมดูลอื่น)

  • การซื้อสินทรัพย์ใหม่ — มาจาก จัดซื้อ ผ่านใบรับสินค้า
  • อะไหล่/น้ำมันเครื่องที่เบิกใช้ซ่อมบำรุง — ตัดสต็อกจาก คลังสินค้า/สต็อก
  • ค่าแรงช่างซ่อมประจำ — อ้างอิงจาก บุคลากรและแรงงาน
  • การบันทึกค่าเสื่อมราคาเป็นรายการบัญชี — ส่งต่อให้ บัญชีและการเงิน
โมดูลที่เกี่ยวข้องเหตุการณ์สิ่งที่ Asset ต้องทำPhase
จัดซื้อรับสินทรัพย์ใหม่เข้าฟาร์ม (ผ่านใบรับสินค้า)สร้างทะเบียนสินทรัพย์ใหม่และเริ่มคิดค่าเสื่อมPhase 1
Asset (ตัวเอง) → บัญชีและการเงินปิดรอบบัญชีรายเดือนส่งค่าเสื่อมราคาเป็น journal entryPhase 1
คลังสินค้า/สต็อกเบิกอะไหล่/น้ำมันเครื่องมาซ่อมบำรุงตัดสต็อกอะไหล่ที่ใช้ในงานซ่อมนั้นPhase 1
บุคลากรและแรงงานช่างซ่อมประจำทำงานซ่อมบำรุงอ้างอิงค่าแรงช่างเข้างานซ่อมนั้นPhase 2
จัดซื้อถึงรอบต้องเปลี่ยนอะไหล่ตามแผน PMเสนอสร้างใบขอซื้ออะไหล่ล่วงหน้าPhase 2
Core Functions

2. ฟังก์ชันหลัก (Core Functions)

แยกชัดว่าอะไรต้องใช้งานได้ตั้งแต่วันแรก (MVP) และอะไรเพิ่มทีหลังได้โดยไม่กระทบการดูแลสินทรัพย์พื้นฐาน

MVP — ต้องมีวันแรก Phase 1

  • จัดการทะเบียนสินทรัพย์/เครื่องจักร (สร้าง/แก้ไข/จำหน่าย)
  • ตั้งตารางซ่อมบำรุงเชิงป้องกัน (PM) ตามเวลาหรือชั่วโมงใช้งาน
  • บันทึกการซ่อมบำรุงจริง ทั้งตามแผนและซ่อมฉุกเฉิน
  • คำนวณค่าเสื่อมราคารายเดือนอัตโนมัติ
  • แจ้งเตือนเมื่อถึงกำหนดซ่อมบำรุง
  • ดูประวัติการซ่อมบำรุงต่อสินทรัพย์
  • ปิดทะเบียนสินทรัพย์ที่จำหน่ายออก/เลิกใช้งาน

เพิ่มทีหลังได้

  • จองคิวใช้เครื่องจักรร่วม เช่น รถไถคันเดียวใช้หลายแปลงPhase 2
  • เชื่อมกับจัดซื้อเสนอซื้ออะไหล่ล่วงหน้าตามแผน PMPhase 2
  • บันทึกชั่วโมงใช้งานจริงผ่านมิเตอร์/เซนเซอร์เพื่อคำนวณ PM แม่นยำขึ้นPhase 2
  • วิเคราะห์ต้นทุนซ่อมบำรุงสะสมเทียบมูลค่าสินทรัพย์ (ซ่อมต่อหรือซื้อใหม่)Phase 3
  • พยากรณ์การเสื่อมสภาพและวางแผนงบลงทุนทดแทนPhase 3
Database

3. ฐานข้อมูล (Database)

แต่ละเอนทิตีคือ 1 ตารางในฐานข้อมูล พร้อมคำอธิบายว่าแทนอะไรในโลกจริง และแต่ละฟิลด์เก็บอะไร ชนิดข้อมูลแบบไหน

asset Phase 1

สินทรัพย์/เครื่องจักร — ทะเบียนทรัพย์สินถาวรของฟาร์ม เช่น รถไถ รถบรรทุก โรงเรือน ปั๊มน้ำ เครื่องให้อาหารอัตโนมัติ

ความสัมพันธ์: ผูกกับ maintenance_schedule, maintenance_log, depreciation_entry และอาจอ้างอิงจาก purchase_order (โมดูลจัดซื้อ) ตอนซื้อเข้ามา

ฟิลด์ชนิดข้อมูลเก็บอะไร
idเลขอ้างอิง/UUID (PK)รหัสประจำแถวนี้ ไม่ซ้ำกัน สร้างอัตโนมัติ
asset_codeข้อความ (text)รหัสสินทรัพย์ที่ใช้อ้างอิงภายในระบบ
nameข้อความ (text)ชื่อสินทรัพย์ เช่น "รถไถคูโบต้า M6040"
categoryตัวเลือกคงที่ (enum)ประเภทสินทรัพย์ เลือกได้เฉพาะ: vehicle, machinery, building, equipment, other
purchase_date / purchase_costวันที่ / ตัวเลข (decimal)วันที่ซื้อ และราคาซื้อตั้งต้น
useful_life_yearsตัวเลข (integer)อายุการใช้งานประมาณการเป็นปี ใช้คำนวณค่าเสื่อม
salvage_valueตัวเลข (decimal)มูลค่าซากโดยประมาณ ณ สิ้นอายุการใช้งาน
default_cost_center_idเลขอ้างอิง (FK → cost_center)พื้นที่/หน่วยงานที่ใช้งานประจำ
statusตัวเลือกคงที่ (enum)สถานะ เลือกได้เฉพาะ: active, under_maintenance, disposed

maintenance_schedule Phase 1

แผนซ่อมบำรุงเชิงป้องกัน — กำหนดรอบการซ่อมบำรุงล่วงหน้าตามเวลาหรือชั่วโมงใช้งาน เพื่อป้องกันเครื่องเสียกะทันหัน

ความสัมพันธ์: ผูกกับ asset และเชื่อมกับ maintenance_log เมื่อถึงกำหนดและมีการซ่อมจริงตามแผน

ฟิลด์ชนิดข้อมูลเก็บอะไร
idเลขอ้างอิง/UUID (PK)รหัสประจำแถวนี้ ไม่ซ้ำกัน สร้างอัตโนมัติ
asset_idเลขอ้างอิง (FK → asset)แผนนี้เป็นของสินทรัพย์ตัวไหน
interval_typeตัวเลือกคงที่ (enum)วิธีนับรอบ เลือกได้เฉพาะ: time_based (ตามเวลา), usage_based (ตามชั่วโมงใช้งาน)
interval_valueตัวเลข (integer)ทุกกี่วัน หรือทุกกี่ชั่วโมงใช้งาน แล้วแต่ interval_type
last_done_date / last_done_usage_hoursวันที่ / ตัวเลขครั้งล่าสุดที่ทำ PM ไปเมื่อไหร่/ที่ชั่วโมงเท่าไหร่
next_due_date / next_due_usage_hoursวันที่ / ตัวเลขกำหนดครั้งถัดไป คำนวณอัตโนมัติจากค่าล่าสุด+interval_value

maintenance_log Phase 1

บันทึกการซ่อมบำรุง — บันทึกทุกครั้งที่มีการซ่อมบำรุงจริง ทั้งตามแผน PM และซ่อมฉุกเฉินนอกแผน

ความสัมพันธ์: ผูกกับ asset และ maintenance_schedule (ถ้าเป็นไปตามแผน) อาจอ้างอิงการเบิกอะไหล่จากโมดูลคลังสินค้า

ฟิลด์ชนิดข้อมูลเก็บอะไร
idเลขอ้างอิง/UUID (PK)รหัสประจำแถวนี้ ไม่ซ้ำกัน สร้างอัตโนมัติ
asset_idเลขอ้างอิง (FK → asset)ซ่อมบำรุงสินทรัพย์ตัวไหน
maintenance_schedule_idเลขอ้างอิง (FK → maintenance_schedule, ว่างได้)เป็นไปตามแผนไหน ถ้าเป็นซ่อมฉุกเฉินนอกแผนปล่อยว่าง
maintenance_typeตัวเลือกคงที่ (enum)ประเภทงานซ่อม เลือกได้เฉพาะ: preventive (ตามแผน), corrective (ซ่อมฉุกเฉิน)
maintenance_dateวันที่ (date)วันที่ซ่อมจริง
descriptionข้อความ (text)อาการที่พบและงานที่ทำ
costตัวเลข (decimal)ค่าใช้จ่ายรวมของการซ่อมครั้งนี้ (ค่าแรง + อะไหล่)
performed_byเลขอ้างอิง (FK → user/ผู้รับเหมา)ใครเป็นคนซ่อม

depreciation_entry Phase 1

รายการค่าเสื่อมราคา — บันทึกค่าเสื่อมที่คำนวณได้แต่ละงวด ก่อนส่งเป็นรายการบัญชี

ความสัมพันธ์: ผูกกับ asset และส่งข้อมูลไปโพสต์ journal entry ที่โมดูลบัญชีและการเงิน

ฟิลด์ชนิดข้อมูลเก็บอะไร
idเลขอ้างอิง/UUID (PK)รหัสประจำแถวนี้ ไม่ซ้ำกัน สร้างอัตโนมัติ
asset_idเลขอ้างอิง (FK → asset)ค่าเสื่อมของสินทรัพย์ตัวไหน
periodข้อความ/วันที่งวดบัญชีที่คำนวณค่าเสื่อมนี้
depreciation_amountตัวเลข (decimal)ค่าเสื่อมราคาของงวดนี้
accumulated_depreciationตัวเลข (decimal)ค่าเสื่อมสะสมตั้งแต่ซื้อมาจนถึงงวดนี้
book_valueตัวเลข (decimal)มูลค่าตามบัญชีคงเหลือ = purchase_cost - accumulated_depreciation

equipment_booking Phase 2

การจองใช้เครื่องจักรร่วม — ใช้จองคิวเครื่องจักรที่ต้องหมุนเวียนใช้หลายพื้นที่ เช่น รถไถคันเดียวใช้หลายแปลง

ความสัมพันธ์: ผูกกับ asset และ cost_center ที่จอง ใช้ตรวจสอบการจองซ้อนกัน

ฟิลด์ชนิดข้อมูลเก็บอะไร
idเลขอ้างอิง/UUID (PK)รหัสประจำแถวนี้ ไม่ซ้ำกัน สร้างอัตโนมัติ
asset_idเลขอ้างอิง (FK → asset)จองเครื่องจักรตัวไหน
cost_center_idเลขอ้างอิง (FK → cost_center)จองไปใช้พื้นที่/แปลงไหน
booking_date / start_time / end_timeวันที่ / เวลาช่วงเวลาที่จองใช้งาน
statusตัวเลือกคงที่ (enum)สถานะ เลือกได้เฉพาะ: requested, confirmed, in_use, completed, cancelled

Business Rules & Formulas

6. สูตรคำนวณและกฎทางธุรกิจ (Business Rules & Formulas)

ตรรกะที่ dev ต้อง implement จริงเบื้องหลัง entity/endpoint ด้านบน

ค่าเสื่อมราคาแบบเส้นตรง (Straight-Line Depreciation)

Phase 1

วิธีคิดค่าเสื่อมมาตรฐานที่ใช้กันทั่วไปสำหรับสินทรัพย์ฟาร์ม

monthly_depreciation =
  (purchase_cost - salvage_value)
  / (useful_life_years × 12)

accumulated_depreciation += monthly_depreciation
  (คำนวณทุกงวดจนครบ useful_life_years)

book_value = purchase_cost - accumulated_depreciation
  (ค่าต่ำสุดไม่ต่ำกว่า salvage_value)

กำหนดรอบ PM ถัดไป (Next Maintenance Due)

Phase 1

คำนวณต่างกันตามวิธีนับรอบที่ตั้งไว้ในแผนซ่อมบำรุง

time_based:
  next_due_date = last_done_date + interval_value (วัน)

usage_based:
  next_due_usage_hours =
    last_done_usage_hours + interval_value (ชั่วโมง)

แจ้งเตือนเมื่อ:
  today >= next_due_date - lead_time_days
  หรือ current_usage_hours >= next_due_usage_hours - lead_time_hours

ต้นทุนซ่อมบำรุงสะสม (Cumulative Maintenance Cost)

Phase 1

ช่วยตัดสินใจว่าควรซ่อมต่อหรือซื้อสินทรัพย์ใหม่ทดแทน

total_maintenance_cost(asset) =
  SUM(maintenance_log.cost) ต่อทุกรายการของสินทรัพย์นั้น

maintenance_to_value_ratio =
  total_maintenance_cost / purchase_cost

ratio > threshold (เช่น 50%)
  -> flag พิจารณาซื้อใหม่แทนซ่อมต่อ

ตรวจสอบการจองซ้อนกัน (Booking Conflict Check)

Phase 2

ป้องกันไม่ให้สองพื้นที่จองใช้เครื่องจักรตัวเดียวกันซ้อนเวลากัน

conflict = มี equipment_booking อื่นของ asset เดียวกัน
  ที่ (start_time, end_time) ทับซ้อนกับรายการที่จะจองใหม่
  AND status != cancelled

-> ถ้า conflict = true ห้ามยืนยันการจอง

อัตราการใช้งานเครื่องจักรร่วม (Utilization Rate)

Phase 2

ใช้ดูว่าเครื่องจักรที่มีอยู่คุ้มค่าหรือควรซื้อเพิ่ม

utilization_rate(asset, period) =
  SUM(booked_hours ในช่วง period)
  / total_available_hours_in_period

ตัวอย่าง: รถไถถูกจองใช้งานรวม 120 ชั่วโมงในเดือนที่มีชั่วโมงทำงานได้ทั้งหมด 200 ชั่วโมง = utilization 60%

เอกสารนี้เป็นสเปกเริ่มพัฒนาโมดูล "สินทรัพย์และเครื่องจักร" ควรรีวิวโครงสร้างฐานข้อมูลกับทีม dev จริงก่อนเริ่ม implement ← กลับไปภาพรวม ERP ฟาร์ม
