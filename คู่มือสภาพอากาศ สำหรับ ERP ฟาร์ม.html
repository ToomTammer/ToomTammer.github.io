โมดูลสภาพอากาศ (Weather)

สเปกสำหรับเริ่มพัฒนาได้ทันที ครอบคลุมขอบเขตและจุดเชื่อมต่อกับโมดูลอื่น ฟังก์ชันหลักแยก MVP กับที่เพิ่มทีหลังได้ โครงสร้างฐานข้อมูล API หลักที่ต้องมี สิทธิ์การเข้าถึงตามบทบาท และสูตรคำนวณ/กฎทางธุรกิจ

ส่วนหนึ่งของ คู่มือ ERP สำหรับธุรกิจฟาร์ม อัปเดต 18 ก.ค. 2569
1. ขอบเขตและจุดเชื่อมต่อ (Scope & Integration) 2. ฟังก์ชันหลัก (Core Functions) 3. ฐานข้อมูล (Database) 4. API 5. สิทธิ์การเข้าถึง (Roles) 6. สูตรคำนวณ (Formulas)
Scope & Integration

1. ขอบเขตและจุดเชื่อมต่อ (Scope & Integration Points)

โมดูลนี้ต่างจากโมดูลพืชอื่นตรงที่ไม่ได้เกิดจากการปฏิบัติงานในฟาร์ม แต่เป็นชั้นเชื่อมต่อข้อมูลจากผู้ให้บริการพยากรณ์อากาศภายนอก แล้วส่งคำแนะนำ/คำเตือนให้โมดูลอื่นตัดสินใจต่อ ไม่ได้เป็นเจ้าของข้อมูลพยากรณ์เอง

อยู่ในขอบเขต

  • เชื่อมต่อผู้ให้บริการพยากรณ์อากาศภายนอก
  • พยากรณ์อากาศล่วงหน้าเฉพาะจุดต่อแปลง (Field-specific Forecast)
  • บันทึกข้อมูลอากาศจริงย้อนหลังต่อพื้นที่
  • แจ้งเตือนความเสี่ยงภัยแล้ง/น้ำท่วม/อากาศสุดขั้ว
  • ประวัติอากาศย้อนหลังเพื่อวิเคราะห์เทียบผลผลิต

อยู่นอกขอบเขต (รับ/ส่งข้อมูลกับโมดูลอื่น)

  • พิกัด GPS ของแปลง — รับจาก ผังแปลงและที่ดิน
  • คำแนะนำวันเริ่มปลูก — ส่งต่อให้ แผนการเพาะปลูก
  • คำแนะนำเลื่อน/ข้ามการให้น้ำ — ส่งต่อให้ การให้น้ำ ปุ๋ย และยา
  • คำเตือนความเสี่ยงก่อนเก็บเกี่ยว — ส่งต่อให้ การเก็บเกี่ยว
  • ไม่ได้สร้าง/เป็นเจ้าของข้อมูลพยากรณ์เอง พึ่งพา external API เป็นแหล่งความจริง
โมดูลที่เกี่ยวข้องเหตุการณ์สิ่งที่สภาพอากาศต้องทำPhase
ผังแปลงและที่ดินมีพิกัด GPS ของแปลงใช้พิกัดสอบถามพยากรณ์เฉพาะจุดPhase 1
ผู้ให้บริการพยากรณ์อากาศ (ภายนอก)อัปเดตข้อมูลพยากรณ์รายวัน/รายชั่วโมงดึงเข้าระบบและแคชไว้ใช้Phase 1
สภาพอากาศ (ตัวเอง) → การให้น้ำ ปุ๋ย และยาพยากรณ์ฝนตกในไม่กี่วันข้างหน้าแนะนำเลื่อน/ข้ามการให้น้ำหรือฉีดพ่นPhase 1
สภาพอากาศ (ตัวเอง) → แผนการเพาะปลูกพยากรณ์ฝน/แล้งช่วงวางแผนปลูกแนะนำวันเริ่มปลูกที่เหมาะสมPhase 2
สภาพอากาศ (ตัวเอง) → การเก็บเกี่ยวพยากรณ์ฝนตกหนัก/พายุช่วงจะเก็บเกี่ยวแจ้งเตือนความเสี่ยงก่อนกำหนดเก็บเกี่ยวPhase 2
Core Functions

2. ฟังก์ชันหลัก (Core Functions)

แยกชัดว่าอะไรต้องใช้งานได้ตั้งแต่วันแรก (MVP) และอะไรเพิ่มทีหลังได้โดยไม่กระทบการเชื่อมต่อพยากรณ์พื้นฐาน

MVP — ต้องมีวันแรก Phase 1

  • เชื่อมต่อผู้ให้บริการพยากรณ์อากาศภายนอกโดยใช้พิกัด GPS ของแปลง
  • ดึงและแคชพยากรณ์อากาศรายวัน/รายชั่วโมงต่อแปลง
  • บันทึกข้อมูลอากาศจริงย้อนหลังต่อพื้นที่ (กรอกเองได้ถ้าไม่มีเซนเซอร์)
  • แจ้งเตือนความเสี่ยงฝนตกหนักในไม่กี่วันข้างหน้า
  • ดูประวัติอากาศย้อนหลังต่อแปลง

เพิ่มทีหลังได้

  • แนะนำวันเริ่มปลูกที่เหมาะสมจากพยากรณ์ให้แผนการเพาะปลูกPhase 2
  • แจ้งเตือนความเสี่ยงก่อนกำหนดเก็บเกี่ยว (ฝนตกหนัก/พายุ)Phase 2
  • แจ้งเตือนความเสี่ยงภัยแล้งระยะยาวPhase 2
  • ตั้งค่า threshold การแจ้งเตือนได้เองPhase 2
  • วิเคราะห์ความสัมพันธ์ระหว่างสภาพอากาศกับผลผลิต/คุณภาพย้อนหลังPhase 3
  • พยากรณ์ผลกระทบต่อผลผลิตล่วงหน้าจากแนวโน้มอากาศระยะยาวPhase 3
Database

3. ฐานข้อมูล (Database)

แต่ละเอนทิตีคือ 1 ตารางในฐานข้อมูล พร้อมคำอธิบายว่าแทนอะไรในโลกจริง และแต่ละฟิลด์เก็บอะไร ชนิดข้อมูลแบบไหน

weather_station_link Phase 1

การเชื่อมต่อพื้นที่กับแหล่งข้อมูลอากาศ — ผูกแปลง/โซนหนึ่งเข้ากับพิกัดที่ใช้สอบถามพยากรณ์จากผู้ให้บริการภายนอก

ความสัมพันธ์: ผูกกับ field/field_zone จากโมดูลผังแปลงและที่ดิน เป็นต้นทางให้ weather_forecast

ฟิลด์ชนิดข้อมูลเก็บอะไร
idเลขอ้างอิง/UUID (PK)รหัสประจำแถวนี้ ไม่ซ้ำกัน สร้างอัตโนมัติ
field_id / field_zone_idเลขอ้างอิง (FK)เชื่อมพยากรณ์นี้กับแปลงหรือโซนไหน
latitude / longitudeตัวเลข (decimal)พิกัดที่ใช้สอบถามพยากรณ์ ดึงมาจากขอบเขตแปลงหรือระบุเอง
providerข้อความ/ตัวเลือกคงที่ (enum)ผู้ให้บริการพยากรณ์อากาศภายนอกที่ใช้
external_location_idข้อความ (text, ว่างได้)รหัสอ้างอิงตำแหน่งของผู้ให้บริการนั้น (ถ้าจำเป็นต้องใช้)

weather_forecast Phase 1

พยากรณ์อากาศ — ข้อมูลพยากรณ์ล่วงหน้าที่ดึงมาจากผู้ให้บริการภายนอก แคชไว้ใช้งานในระบบ

ความสัมพันธ์: ผูกกับ weather_station_link และเป็นต้นทางให้สร้าง weather_alert เมื่อเข้าเงื่อนไขความเสี่ยง

ฟิลด์ชนิดข้อมูลเก็บอะไร
idเลขอ้างอิง/UUID (PK)รหัสประจำแถวนี้ ไม่ซ้ำกัน สร้างอัตโนมัติ
weather_station_link_idเลขอ้างอิง (FK)พยากรณ์นี้เป็นของพื้นที่ไหน
forecast_dateวันที่ (date)วันที่พยากรณ์นี้ใช้กับวันไหน
forecast_generated_atวันที่/เวลา (datetime)ตอนที่ดึงพยากรณ์นี้มาจาก external API
temperature_min / temperature_maxตัวเลข (decimal)อุณหภูมิต่ำสุด/สูงสุดที่คาดการณ์
rain_probability_pctตัวเลข (decimal)โอกาสที่ฝนจะตกเป็นเปอร์เซ็นต์
expected_rainfall_mmตัวเลข (decimal)ปริมาณฝนที่คาดว่าจะตก หน่วยมิลลิเมตร
conditionข้อความ/ตัวเลือกคงที่ (enum)สภาพอากาศโดยรวม เช่น sunny, cloudy, rain, storm

weather_actual_log Phase 1

บันทึกอากาศจริง — ข้อมูลอากาศที่เกิดขึ้นจริงต่อวันต่อพื้นที่ ใช้เก็บประวัติเทียบผลผลิต และกรอกเองได้ถ้าไม่มีเซนเซอร์

ความสัมพันธ์: ผูกกับ field/field_zone จากโมดูลผังแปลงและที่ดิน

ฟิลด์ชนิดข้อมูลเก็บอะไร
idเลขอ้างอิง/UUID (PK)รหัสประจำแถวนี้ ไม่ซ้ำกัน สร้างอัตโนมัติ
field_id / field_zone_idเลขอ้างอิง (FK)บันทึกอากาศของแปลงหรือโซนไหน
record_dateวันที่ (date)วันที่ของข้อมูลอากาศนี้
rainfall_mmตัวเลข (decimal)ปริมาณฝนที่ตกจริง หน่วยมิลลิเมตร
temperature_avgตัวเลข (decimal, ว่างได้)อุณหภูมิเฉลี่ยของวันนั้น
humidity_pctตัวเลข (decimal, ว่างได้)ความชื้นสัมพัทธ์เฉลี่ยของวันนั้น
sourceตัวเลือกคงที่ (enum)ที่มาของข้อมูล เลือกได้เฉพาะ: sensor, manual, external_api

weather_alert Phase 1

การแจ้งเตือนความเสี่ยงจากอากาศ — การแจ้งเตือนที่ระบบสร้างขึ้นเมื่อพยากรณ์หรือข้อมูลจริงเข้าเงื่อนไขความเสี่ยง เช่น ฝนตกหนัก ภัยแล้ง

ความสัมพันธ์: ผูกกับ field/field_zone และอ้างอิง weather_forecast หรือ weather_actual_log ที่ทำให้เกิดการเตือนนี้

ฟิลด์ชนิดข้อมูลเก็บอะไร
idเลขอ้างอิง/UUID (PK)รหัสประจำแถวนี้ ไม่ซ้ำกัน สร้างอัตโนมัติ
field_id / field_zone_idเลขอ้างอิง (FK)คำเตือนนี้เกี่ยวกับแปลงหรือโซนไหน
alert_typeตัวเลือกคงที่ (enum)ประเภทความเสี่ยง เลือกได้เฉพาะ: heavy_rain, drought, storm, frost
severityตัวเลือกคงที่ (enum)ระดับความรุนแรง เลือกได้เฉพาะ: info, warning, critical
triggered_dateวันที่ (date)วันที่เกิดการแจ้งเตือนนี้
messageข้อความ (text)ข้อความแจ้งเตือนที่แสดงให้ผู้ใช้เห็น

Business Rules & Formulas

6. สูตรคำนวณและกฎทางธุรกิจ (Business Rules & Formulas)

ตรรกะที่ dev ต้อง implement จริงเบื้องหลัง entity/endpoint ด้านบน

คำนวณตำแหน่งสอบถามพยากรณ์

Phase 1

ใช้เมื่อไม่ได้ระบุพิกัดเองตอนเชื่อมต่อพื้นที่

latitude/longitude ของ weather_station_link =
  centroid(field.gps_boundary)
  (ถ้าไม่ระบุพิกัดเอง ใช้จุดกึ่งกลางขอบเขตแปลง)

เกณฑ์แจ้งเตือนฝนตกหนัก (Heavy Rain Alert)

Phase 1

ตรวจทุกครั้งที่ sync พยากรณ์ใหม่จาก external API

ถ้า expected_rainfall_mm (วันใดในอีก 3 วันข้างหน้า)
   > heavy_rain_threshold_mm (ตั้งค่าได้ เช่น 50mm)

-> สร้าง weather_alert (alert_type = heavy_rain)

เกณฑ์แจ้งเตือนภัยแล้ง (Drought Alert)

Phase 2

ใช้ข้อมูลอากาศจริงสะสมย้อนหลัง ไม่ใช่แค่พยากรณ์

cumulative_rainfall(field, N วันล่าสุด) =
  SUM(weather_actual_log.rainfall_mm) ใน N วันล่าสุด

ถ้า cumulative_rainfall < drought_threshold_mm
   (ตั้งค่าตามช่วงเวลา/ฤดูกาลนั้น)

-> สร้าง weather_alert (alert_type = drought)

คำแนะนำเลื่อนการให้น้ำ (Irrigation Skip Recommendation)

Phase 1

ส่งให้โมดูล "การให้น้ำ ปุ๋ย และยา" ใช้ตัดสินใจ ไม่บังคับข้ามอัตโนมัติ

ถ้า rain_probability_pct (พรุ่งนี้) > skip_irrigation_threshold_pct
   (เช่น 70%)
AND expected_rainfall_mm > min_effective_rain_mm

-> แนะนำเลื่อน/ข้ามการให้น้ำตามแผน

ความสดของข้อมูลพยากรณ์ (Forecast Cache Freshness)

Phase 1

ป้องกันการแสดงพยากรณ์เก่าเกินไปจนไม่แม่นยำ

forecast ถือว่าล้าสมัยถ้า:
  today - forecast_generated_at > max_forecast_age_hours
  (เช่น 12 ชั่วโมง)
