โมดูลรายงานหน่วยงานรัฐ (Government Reporting)

สเปกสำหรับเริ่มพัฒนาได้ทันที ครอบคลุมขอบเขตและจุดเชื่อมต่อกับโมดูลอื่น ฟังก์ชันหลักแยก MVP กับที่เพิ่มทีหลังได้ โครงสร้างฐานข้อมูล API หลักที่ต้องมี สิทธิ์การเข้าถึงตามบทบาท และสูตรคำนวณ/กฎทางธุรกิจ

ส่วนหนึ่งของ คู่มือ ERP สำหรับธุรกิจฟาร์ม อัปเดต 18 ก.ค. 2569
1. ขอบเขตและจุดเชื่อมต่อ (Scope & Integration) 2. ฟังก์ชันหลัก (Core Functions) 3. ฐานข้อมูล (Database) 4. API 5. สิทธิ์การเข้าถึง (Roles) 6. สูตรคำนวณ (Formulas) 7. หน้าจอที่ต้องมี (Screens)
Scope & Integration

1. ขอบเขตและจุดเชื่อมต่อ (Scope & Integration Points)

โมดูลนี้เป็นชั้นสุดท้ายของกลุ่มตรวจสอบย้อนกลับและมาตรฐาน — รวบรวมข้อมูลจากโมดูลอื่นให้อยู่ในรูปแบบฟอร์มที่หน่วยงานรัฐกำหนด (กรมปศุสัตว์ กรมวิชาการเกษตร กรมการค้าต่างประเทศ) และติดตามสถานะการยื่น/ออกเอกสารส่งออก โดยไม่เป็นเจ้าของข้อมูลการผลิตหรือการรับรองมาตรฐานเอง

อยู่ในขอบเขต

  • กำหนดเทมเพลตรายงานตามฟอร์มของแต่ละหน่วยงาน
  • รวบรวมข้อมูลจากโมดูลอื่นตามช่วงเวลาที่กำหนดเป็นร่างรายงาน
  • ติดตามสถานะการยื่นรายงาน (draft → submitted → acknowledged/rejected)
  • ออกเอกสารประกอบการส่งออก เช่น ใบรับรองสุขภาพ/แหล่งกำเนิดสินค้า
  • แจ้งเตือนกำหนดยื่นรายงานตามรอบ

อยู่นอกขอบเขต (อ่านข้อมูลจากโมดูลอื่น ไม่คำนวณซ้ำ)

  • ไม่ได้เป็นเจ้าของข้อมูลการเคลื่อนย้าย/ขายเอง — ดึงจาก ทะเบียนสัตว์ (animal_movement), คัดแยกและส่งขาย (dispatch_record), ขายและลูกค้า (sales_order)
  • ไม่ตรวจ/ออกใบรับรองมาตรฐานเอง — ใช้สถานะใบรับรองจาก มาตรฐานฟาร์ม (certificate)
  • ไม่สร้าง trace code/ห่วงโซ่ย้อนกลับเอง — ใช้ผลจาก ตรวจสอบย้อนกลับ (trace_code) ประกอบเอกสารส่งออก
  • ไม่ได้เชื่อมต่อระบบยื่นออนไลน์ของหน่วยงานรัฐจริงใน MVP
โมดูลต้นทางข้อมูลที่ดึงมาใช้ทำอะไรใน Government ReportingPhase
ทะเบียนสัตว์animal_movement, animal_groupรายงานเคลื่อนย้ายสัตว์ต่อกรมปศุสัตว์Phase 1
คัดแยกและส่งขาย / การเก็บเกี่ยวdispatch_record, harvest_recordข้อมูลปริมาณผลผลิตสำหรับรายงานประจำงวดPhase 1
ขายและลูกค้าsales_order ที่เป็นการส่งออกระบุ shipment ที่ต้องออกเอกสารประกอบการส่งออกPhase 1
มาตรฐานฟาร์มcertificate.statusตรวจสิทธิ์ก่อนออกเอกสารส่งออก (ต้องมีใบรับรองยัง active)Phase 1
ตรวจสอบย้อนกลับtrace_code, ผล trace chain completenessแนบประกอบเอกสารรับรองแหล่งกำเนิดสินค้าPhase 1
Core Functions

2. ฟังก์ชันหลัก (Core Functions)

แยกชัดว่าอะไรต้องใช้งานได้ตั้งแต่วันแรก (MVP) และอะไรเพิ่มทีหลังได้โดยไม่กระทบการปฏิบัติตามข้อกำหนดพื้นฐาน

MVP — ต้องมีวันแรก Phase 1

  • กำหนดเทมเพลตรายงานต่อหน่วยงาน/ประเภทฟอร์ม
  • สร้างร่างรายงานโดยรวบรวมข้อมูลจากโมดูลอื่นตามช่วงเวลา
  • แก้ไขร่างรายงานก่อนยื่นจริง
  • บันทึกการยื่นรายงานพร้อมเลขอ้างอิง และติดตามสถานะ
  • ออกเอกสารประกอบการส่งออกต่อ shipment

เพิ่มทีหลังได้

  • ตั้งรอบรายงานอัตโนมัติพร้อมแจ้งเตือนล่วงหน้าตามกำหนดPhase 2
  • เติมข้อมูลในเทมเพลตใบรับรองส่งออกอัตโนมัติจาก Traceability/มาตรฐานฟาร์มPhase 2
  • เชื่อมต่อ API ยื่นรายงานตรงกับระบบออนไลน์ของหน่วยงานรัฐPhase 3
Database

3. ฐานข้อมูล (Database)

แต่ละเอนทิตีคือ 1 ตารางในฐานข้อมูล พร้อมคำอธิบายว่าแทนอะไรในโลกจริง และแต่ละฟิลด์เก็บอะไร ชนิดข้อมูลแบบไหน

report_template Phase 1

เทมเพลตรายงาน — นิยามของฟอร์มรายงานหนึ่งที่หน่วยงานรัฐกำหนด พร้อมความถี่ที่ต้องยื่น

ความสัมพันธ์: เป็นต้นทางของ report_submission หลายรายการ

ฟิลด์ชนิดข้อมูลเก็บอะไร
idเลขอ้างอิง/UUID (PK)รหัสประจำแถวนี้ ไม่ซ้ำกัน สร้างอัตโนมัติ
agency_nameตัวเลือกคงที่ (enum)หน่วยงานที่ต้องยื่น เลือกได้เฉพาะ: กรมปศุสัตว์, กรมวิชาการเกษตร, กรมการค้าต่างประเทศ, อื่นๆ
form_nameข้อความ (text)ชื่อฟอร์มรายงานตามที่หน่วยงานเรียก
form_codeข้อความ (text)รหัสฟอร์มอ้างอิงตามเอกสารราชการ
frequencyตัวเลือกคงที่ (enum)ความถี่ที่ต้องยื่น เลือกได้เฉพาะ: monthly, quarterly, annual, per_shipment
applicable_scopeตัวเลือกคงที่ (enum)ใช้กับพืชหรือปศุสัตว์ เลือกได้เฉพาะ: crop, livestock, both

report_submission Phase 1

การยื่นรายงาน — รายงานหนึ่งฉบับของงวดเวลาหนึ่ง ตั้งแต่ร่างจนถึงยื่นจริงและผลตอบรับจากหน่วยงาน

ความสัมพันธ์: ผูกกับ report_template และมี report_data_snapshot ประกอบ

ฟิลด์ชนิดข้อมูลเก็บอะไร
idเลขอ้างอิง/UUID (PK)รหัสประจำแถวนี้ ไม่ซ้ำกัน สร้างอัตโนมัติ
template_idเลขอ้างอิง (FK → report_template)รายงานนี้ยื่นตามฟอร์มไหน
period_startวันที่ (date)วันเริ่มต้นของงวดที่รายงาน
period_endวันที่ (date)วันสิ้นสุดของงวดที่รายงาน
generated_dateวันที่ (date)วันที่ระบบสร้างร่างรายงาน
submitted_dateวันที่ (date, ว่างได้)วันที่ยื่นจริงต่อหน่วยงาน
reference_numberข้อความ (text, ว่างได้)เลขที่รับเรื่องจากหน่วยงาน
statusตัวเลือกคงที่ (enum)เลือกได้เฉพาะ: draft, submitted, acknowledged, rejected
submitted_byเลขอ้างอิง (FK → user)ใครเป็นคนยื่นรายงานนี้

report_data_snapshot Phase 1

ข้อมูลอ้างอิงประกอบรายงาน — บันทึกว่ารายงานฉบับหนึ่งดึงข้อมูลมาจากรายการใดในโมดูลอื่นบ้าง ณ เวลาที่สร้างร่าง เพื่อรักษาความถูกต้องของหลักฐานย้อนหลัง

ความสัมพันธ์: ผูกกับ report_submission และอ้างอิงเอนทิตีต้นทางแบบยืดหยุ่น (source_module + source_entity + source_ref_id) เช่นเดียวกับ trace_link ในโมดูลตรวจสอบย้อนกลับ

ฟิลด์ชนิดข้อมูลเก็บอะไร
idเลขอ้างอิง/UUID (PK)รหัสประจำแถวนี้ ไม่ซ้ำกัน สร้างอัตโนมัติ
submission_idเลขอ้างอิง (FK → report_submission)เป็นส่วนหนึ่งของรายงานฉบับไหน
source_moduleตัวเลือกคงที่ (enum)ข้อมูลนี้มาจากโมดูลไหน เลือกได้เฉพาะ: crop, livestock, sales
source_entityข้อความ (text)ชื่อเอนทิตีต้นทาง เช่น "animal_movement", "dispatch_record"
source_ref_idข้อความ (text)เลขอ้างอิงของรายการต้นทางนั้น
value_summaryข้อความ (text/JSON)ค่าที่ดึงมา ณ เวลาสร้างร่าง (แช่แข็งไว้ ไม่เปลี่ยนตามข้อมูลต้นทางภายหลัง)

export_document Phase 1

เอกสารประกอบการส่งออก — เอกสารที่ต้องออกให้ลูกค้า/ด่านศุลกากรต่อ shipment เช่น ใบรับรองสุขภาพสัตว์ ใบรับรองสุขอนามัยพืช ใบรับรองแหล่งกำเนิดสินค้า

ความสัมพันธ์: อ้างอิง sales_order/shipment จากโมดูลขายและลูกค้า และอาจผูกกับ report_submission ที่เกี่ยวข้อง

ฟิลด์ชนิดข้อมูลเก็บอะไร
idเลขอ้างอิง/UUID (PK)รหัสประจำแถวนี้ ไม่ซ้ำกัน สร้างอัตโนมัติ
shipment_refข้อความ (อ้างอิง sales_order)เอกสารนี้ออกให้ shipment ไหน
document_typeตัวเลือกคงที่ (enum)เลือกได้เฉพาะ: health_certificate, phytosanitary_certificate, certificate_of_origin
issued_dateวันที่ (date)วันที่ออกเอกสาร
issued_byเลขอ้างอิง (FK → user)ใครเป็นคนออกเอกสารนี้
file_refข้อความ (text)ตำแหน่งที่เก็บไฟล์เอกสารที่สร้างขึ้น

Business Rules & Formulas

6. สูตรคำนวณและกฎทางธุรกิจ (Business Rules & Formulas)

ตรรกะที่ dev ต้อง implement จริงเบื้องหลัง entity/endpoint ด้านบน

รวบรวมข้อมูลอัตโนมัติเข้าร่างรายงาน (Data Auto-Compilation)

Phase 1

ทำงานเมื่อสร้าง report_submission ใหม่ ดึงข้อมูลตาม applicable_scope ของเทมเพลต

generate_draft(template, period_start, period_end):
  ดึงรายการจากโมดูลต้นทางตาม template.applicable_scope
    ที่เกิดขึ้นระหว่าง period_start .. period_end
  บันทึกแต่ละรายการเป็น report_data_snapshot
  รวมยอด/สรุปตามรูปแบบฟอร์มของ template

กำหนดวันยื่นรายงานครั้งถัดไป (Submission Deadline)

Phase 1

คำนวณจากความถี่ของเทมเพลตเพื่อใช้แจ้งเตือนล่วงหน้า

next_due_date = period_end + ระยะเวลาผ่อนผันตามกฎหมาย
  (เช่น monthly -> +15 วันหลังสิ้นเดือน)

ถ้า today >= next_due_date - 7 วัน AND status = draft
  -> แจ้งเตือนเจ้าหน้าที่มาตรฐานให้ยื่นก่อนเลยกำหนด

ตรวจสิทธิ์ก่อนออกเอกสารส่งออก (Export Document Eligibility)

Phase 1

ประตูความปลอดภัยเช่นเดียวกับ PHI/withdrawal period — เรียกใช้ผลตรวจของโมดูลต้นทางแทนคำนวณซ้ำ

can_issue_export_document(shipment_ref) =
  certificate.status = active (จากโมดูลมาตรฐานฟาร์ม ที่ครอบคลุมสินค้านี้)
  AND is_trace_complete(trace_code) = true (จากโมดูลตรวจสอบย้อนกลับ)

ถ้าเงื่อนไขใดไม่ผ่าน
  -> ปฏิเสธการออกเอกสาร พร้อมระบุสาเหตุที่ขาด

ยื่นใหม่หลังถูกปฏิเสธ (Rejection Resubmission)

Phase 1

รักษาประวัติการยื่นเดิมไว้แทนการแก้ทับ

ถ้า report_submission.status = rejected
  -> ต้องสร้าง report_submission แถวใหม่
     (เชื่อมอ้างอิงกลับไปฉบับที่ถูกปฏิเสธ)
     ห้ามแก้ไขฉบับเดิมที่ status = rejected แล้ว

ความไม่เปลี่ยนแปลงของข้อมูลอ้างอิง (Snapshot Immutability)

Phase 1

รักษาความถูกต้องของหลักฐานย้อนหลัง แม้ข้อมูลต้นทางจะถูกแก้ไขภายหลัง

เมื่อ report_submission.status เปลี่ยนเป็น submitted
  -> report_data_snapshot ทุกแถวของฉบับนี้ถูกล็อกแก้ไขไม่ได้
     value_summary คงค่าที่ดึงมา ณ วันที่สร้างร่างเท่านั้น
     แม้ข้อมูลต้นทางจะถูกแก้ไขในภายหลังก็ไม่กระทบ
Screens

7. หน้าจอที่ต้องมี (Screens/Pages)

รายชื่อหน้าจอที่ต้องมีจริงในโมดูลนี้ พร้อมส่วนประกอบหลักของแต่ละหน้า — ใช้เป็น checklist ออกแบบ UI ต่อได้ตรง ๆ ไม่ต้องนั่งไล่จากฟังก์ชัน/entity เอง

แดชบอร์ดรายงานหน่วยงานรัฐ (Government Reporting Dashboard) Phase 1

หน้าแรกที่เจ้าหน้าที่มาตรฐานเปิดดูภาพรวมสถานะรายงานและกำหนดยื่นที่ใกล้ถึง

  • การ์ดสรุปจำนวน report_submission ตามสถานะ: draft, submitted, acknowledged, rejected
  • รายการรายงานที่ใกล้ถึง next_due_date เรียงตามความเร่งด่วน
  • รายการ shipment ที่รอออกเอกสารประกอบการส่งออก
  • ตัวกรองตาม agency_name และ applicable_scope ที่ใช้ร่วมกับทุกวิดเจ็ต

เทมเพลตรายงาน (Report Templates) Phase 1

จัดการนิยามฟอร์มรายงานของแต่ละหน่วยงานและความถี่ที่ต้องยื่น

  • ตารางรายการ: agency_name, form_name, form_code, frequency, applicable_scope
  • ตัวกรองตาม agency_name และ applicable_scope
  • ปุ่ม "เพิ่มเทมเพลตใหม่" เปิดฟอร์มกรอก agency_name, form_name, form_code, frequency, applicable_scope

รายการร่างรายงาน (Report Submissions List) Phase 1

ดูรายงานทั้งหมดพร้อมสถานะ ตั้งแต่ร่างจนถึงผลตอบรับจากหน่วยงาน

  • ตารางรายการ: form_name (จาก template), period_start–period_end, generated_date, submitted_date, reference_number, status พร้อม badge สีตามสถานะ
  • ตัวกรองตามสถานะ (draft/submitted/acknowledged/rejected), agency_name, ช่วงงวด
  • ปุ่ม "สร้างร่างรายงานใหม่"

สร้างร่างรายงานใหม่ (Create Report Draft) Phase 1

รวบรวมข้อมูลจากโมดูลอื่นตามช่วงเวลาที่กำหนดเป็นร่างรายงานอัตโนมัติ

  • ฟอร์มเลือก template_id, period_start, period_end
  • ปุ่ม "สร้างร่าง" เรียก generate_draft ดึงข้อมูลตาม applicable_scope มาบันทึกเป็น report_data_snapshot ทีละแถว
  • แถบสถานะความคืบหน้าขณะรวบรวมข้อมูลจากโมดูลต้นทาง

รายละเอียดร่างรายงาน (Report Submission Detail) Phase 1

ดู แก้ไข ยื่น และติดตามผลตอบรับของรายงานฉบับหนึ่ง

  • หัวข้อสรุป: reference_number, status, period_start–period_end, generated_date
  • ตาราง report_data_snapshot ประกอบร่าง: source_module, source_entity, source_ref_id, value_summary
  • ปุ่ม "แก้ไขร่าง" (เฉพาะ status = draft) และปุ่ม "บันทึกว่ายื่นแล้ว" เปิดฟอร์มกรอก submitted_date + reference_number
  • ปุ่ม "บันทึกผลตอบรับ" อัปเดต status เป็น acknowledged/rejected
  • ถ้า status = rejected แสดงลิงก์ไปยังฉบับที่ยื่นใหม่ (resubmission chain) และล็อกฉบับเดิมห้ามแก้ไข

เอกสารประกอบการส่งออก (Export Documents List) Phase 1

ดูเอกสารทั้งหมดที่ออกไปแล้วต่อ shipment

  • ตารางรายการ: shipment_ref, document_type, issued_date, issued_by
  • ตัวกรองตาม document_type และช่วงวันที่ issued_date
  • คลิกแต่ละแถวเปิดไฟล์เอกสารจาก file_ref

ออกเอกสารประกอบการส่งออกใหม่ (Issue Export Document) Phase 1

ออกเอกสารต่อ shipment หลังผ่านการตรวจสิทธิ์อัตโนมัติ

  • ฟอร์มเลือก shipment_ref และ document_type (health_certificate/phytosanitary_certificate/certificate_of_origin)
  • ตรวจสิทธิ์อัตโนมัติ can_issue_export_document: certificate.status = active และ trace chain ครบ ถ้าไม่ผ่านแสดงสาเหตุที่ขาด
  • ปุ่ม "ออกเอกสาร" สร้างไฟล์และบันทึก file_ref, issued_date, issued_by

คำขอออกเอกสารส่งออก (Export Document Request) Phase 1

หน้าสำหรับพนักงานขายขอให้ออกเอกสารประกอบการส่งออกของ shipment ตนเอง

  • เลือก shipment_ref ของตนเองจาก sales_order ที่เป็นการส่งออก
  • ปุ่ม "ขอออกเอกสาร" ส่งต่อให้เจ้าหน้าที่มาตรฐานพิจารณา
  • ตารางสถานะคำขอของตน: shipment_ref, document_type, สถานะ (รออนุมัติ/ออกแล้ว)

กำหนดยื่นรายงานที่ใกล้ถึง (Upcoming Submission Deadlines) Phase 2

รวมรายงานที่ next_due_date ใกล้ถึงเพื่อเร่งยื่นก่อนเลยกำหนด

  • ตารางรายงาน status = draft ที่ next_due_date ภายใน 7 วัน เรียงตามวันที่ใกล้สุด
  • ตัวกรองตาม agency_name
  • คลิกแถวลิงก์ตรงไปหน้ารายละเอียดร่างรายงาน

ตั้งรอบแจ้งเตือนอัตโนมัติ (Auto Reminder Schedule Settings) Phase 2

กำหนดระยะผ่อนผันและวันล่วงหน้าก่อนแจ้งเตือนต่อความถี่ของเทมเพลต

  • ฟอร์มตั้งระยะผ่อนผันตามกฎหมายต่อ frequency (เช่น monthly → +15 วันหลังสิ้นเดือน)
  • ตั้งจำนวนวันล่วงหน้าก่อนแจ้งเตือน (ค่าเริ่มต้น 7 วัน) และรายชื่อผู้รับแจ้งเตือน

เทมเพลตเติมข้อมูลเอกสารส่งออกอัตโนมัติ (Export Document Auto-fill Mapping) Phase 2

กำหนดว่าเอกสารแต่ละประเภทดึงข้อมูลจากมาตรฐานฟาร์ม/ตรวจสอบย้อนกลับมาเติมอัตโนมัติจากฟิลด์ไหน

  • ฟอร์ม map document_type กับฟิลด์ต้นทางจาก certificate และ trace_code
  • พรีวิวเอกสารที่เติมข้อมูลอัตโนมัติก่อนออกจริง

ตั้งค่าการเชื่อมต่อระบบยื่นออนไลน์หน่วยงานรัฐ (Government API Integration Settings) Phase 3

เชื่อมต่อ API ยื่นรายงานตรงกับระบบออนไลน์ของหน่วยงานรัฐแทนการยื่นด้วยมือ

  • ฟอร์มตั้งค่า endpoint/credential ต่อ agency_name พร้อมปุ่ม "ทดสอบการเชื่อมต่อ"
  • log ประวัติการยื่นผ่าน API พร้อมผลลัพธ์และรหัสอ้างอิงที่ได้กลับมา
